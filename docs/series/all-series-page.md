# Feature: All Series Page

## 1. Purpose

Feature **All Series Page** дозволяє користувачу переглядати всі книжкові серії, які є в його бібліотеці BookNest.

Сторінка допомагає користувачу:

* бачити всі книжкові цикли в одному місці;
* створювати нову серію;
* відстежувати прогрес читання по кожній серії;
* швидко знаходити недочитані серії;
* бачити, яку книгу варто читати наступною;
* розуміти загальний стан своїх серій через коротку статистику;
* переходити на детальну сторінку конкретної серії.

All Series Page — це сторінка-огляд серій. Вона не відповідає за повну логіку створення, редагування, видалення або керування книгами всередині серії.

Повна логіка створення та редагування серії описується окремо:

```text
Feature: Create / Edit Series
```

---

## 2. Main idea

Сторінка **Серії** показує всі книжкові серії користувача.

Route:

```text
/series
```

Серія може з’явитися на сторінці двома способами:

* користувач створив серію вручну через Create Series flow;
* користувач додав книгу і вказав, що вона є частиною нової або вже існуючої серії.

У MVP підтримуються обидва сценарії:

```text
Scenario 1:
Користувач створює серію вручну зі сторінки /series.

Scenario 2:
Користувач додає книгу через Create Book flow і прив’язує її до серії.
```

Основна задача сторінки:

```text
Показати всі серії, їхній прогрес, наступну книгу та дати швидкий доступ до створення нової серії.
```

Important:

```text
All Series Page тільки запускає Create Series flow.
Поля, validation rules і submit behavior описуються в Feature: Create / Edit Series.
```

---

## 3. Entry points

Користувач може перейти на сторінку **Серії** з основної навігації застосунку.

Основний entry point:

| Entry point     | Behavior                     |
| --------------- | ---------------------------- |
| Sidebar → Серії | відкриває сторінку `/series` |

Додаткові entry points:

| Entry point       | Behavior                                                          |
| ----------------- | ----------------------------------------------------------------- |
| Dashboard         | перехід до всіх серій або недочитаних серій                       |
| Book Details Page | перехід до серії, до якої належить книга                          |
| My Library Page   | перехід до серії через series badge або meta info на картці книги |
| Create Book Form  | створення або вибір серії під час додавання книги                 |

### 4.1. Header

Header має бути візуально схожий на header сторінок **My Library** та **Favorites**.

Header містить:

* ілюстрацію або icon-block;
* title;
* count badge;
* subtitle;
* summary cards;
* primary action **Створити серію**.

Example:

```text
Серії 9 серій
Книжкові цикли твоєї колекції — стеж за прогресом і не пропусти жодного тому.

[9] Усього серій
[3] Прочитано
[5] Недочитані

```

---

### 4.2. Header summary cards

Header summary cards показують коротку статистику по серіях користувача.

У MVP потрібно показати 4 cards:

| Card          | Description                                               |
| ------------- | --------------------------------------------------------- |
| Усього серій  | загальна кількість серій користувача                      |
| Прочитано     | кількість серій, які користувач повністю прочитав         |
| Недочитані    | кількість серій, які користувач почав, але ще не завершив |
| Книг у серіях | кількість книг у бібліотеці, які належать до серій        |

---

#### Card: Усього серій

Показує всі серії користувача.

Example:

```text
9
серій
```

У цей показник входять:

* серії з книгами;
* вручну створені серії без книг;
* завершені серії;
* серії, що ще виходять;
* серії з невідомим статусом.

---

#### Card: Прочитано

Показує кількість серій, які користувач повністю прочитав.

Example:

```text
3
прочитано
```

Important:

Label має бути саме **Прочитано**, а не **Завершено**, щоб не плутати з `seriesStatus = completed`.

```text
Прочитано = прогрес користувача.
Завершена = статус книжкового циклу.
```

---

#### Card: Недочитані

Показує кількість серій, які користувач почав, але ще не дочитав.

Example:

```text
5
недочитані
```

Серія вважається недочитаною, якщо:

* користувач прочитав або читає хоча б одну книгу серії;
* не всі книги серії прочитані;
* серія має більше ніж одну книгу або `totalBooksCount > 1`.

---

#### Card: Книг у серіях

Показує, скільки книг з бібліотеки користувача належать до серій.

Example:

```text
48
книг у серіях
```

Цей показник не рахує порожні серії без книг.

---

### 4.3. Header primary action

У header має бути primary button:

```text
+ Створити серію
```

Behavior:

* відкриває Create Series flow;
* після успішного створення серія з’являється на сторінці `/series`;
* якщо серія створена без книг, вона показується як empty series card;
* користувач може пізніше додати книги до серії через Create Book / Edit Book flow.

Important:

```text
All Series Page не описує поля, validation rules і submit behavior створення серії.
Це описується в Feature: Create / Edit Series.
```

---

### 4.4. Main content layout

Основна частина сторінки має містити:

* tabs;
* toolbar;
* series grid або list;
* empty states.

Recommended desktop layout:

```text
[Main content: 70–75% width] [Right sidebar: 25–30% width]
```

На mobile right sidebar має переходити під основний список.

---

### 4.5. Tabs

У MVP сторінка має дві основні вкладки:

```text
Усі серії
Недочитані
```

#### Tab: Усі серії

Показує всі серії користувача.

Сюди входять:

* серії з книгами;
* вручну створені серії без книг;
* початі серії;
* не початі серії;
* повністю прочитані серії;
* недочитані серії;
* серії, що ще виходять;
* серії з невідомим статусом.

#### Tab: Недочитані

Показує серії, які користувач уже почав, але ще не завершив.

Серія потрапляє у вкладку **Недочитані**, якщо:

* у серії є більше ніж одна книга або вказано `totalBooksCount > 1`;
* хоча б одна книга в серії має статус `finished` або `reading`;
* не всі книги серії мають статус `finished`.

Порожні серії не показуються у вкладці **Недочитані**.

---

### 4.6. Toolbar

Toolbar розміщується під tabs.

Toolbar містить:

* search input;
* filter by series status;
* filter by reading state;
* sorting;
* grid/list view switch.

Recommended order:

```text
[Search] [Series status filter] [Reading state filter] [Sorting] [Grid/List switch]
```

---

### 4.7. Right sidebar

Right sidebar потрібен для швидких дій, фокусу на продовженні серій і компактної статистики.

У MVP right sidebar має містити:

```text
1. Quick actions
2. Continue series
3. Closest to completion
4. Series status stats
```

Right sidebar не має дублювати весь список серій. Він має допомагати користувачу швидко зрозуміти, що робити далі.

### 5.13. Progress Bar

Progress bar показує, яку частину серії користувач уже прочитав.

У прогрес входять тільки книги зі статусом:

```text
finished
```

Base formula:

```text
read books count / total books count * 100
```

Якщо `totalBooksCount` вказаний:

```text
Прочитано 2 з 5
40%
```

Якщо `totalBooksCount` не вказаний:

```text
Прочитано 2 з 4 доданих
50%
```

Якщо серія створена, але книг ще немає:

```text
0 книг
Прогрес ще недоступний
```

Якщо всі книги прочитані:

```text
Усі книги прочитані
100%
```

---

### 5.14. Next Book Block

Next Book показує, яку книгу користувачу логічно читати далі.

Наступна книга — це перша книга в серії, яка:

* ще не має `readingStatus = finished`;
* має найменший part number серед непрочитаних книг;
* іде після вже прочитаних або поточних книг.

Example:

```text
Наступна книга:
Двір мороку і гніву
Книга 2
```

Якщо всі книги прочитані:

```text
Усі книги прочитані
```

Якщо серія порожня:

```text
Додайте першу книгу в серію
```

Якщо наступна книга ще не додана в бібліотеку:

```text
Наступна книга ще не додана
```

## 6. Actions

### 6.1. Create series

Користувач може створити нову серію через кнопку:

```text
+ Створити серію
```

Entry points:

* header button;
* right sidebar quick action;
* empty state button.

Behavior:

1. Користувач натискає **Створити серію**.
2. Відкривається Create Series flow.
3. Користувач створює серію.
4. Після успішного створення серія з’являється на сторінці `/series`.
5. Якщо книг у серії ще немає, серія показується як empty series card.

Important:

```text
Поля форми, validation rules, duplicate check і submit behavior описуються в Feature: Create / Edit Series.
```

---

### 6.2. Search series

Користувач може шукати серії через search input.

Behavior:

* після введення тексту список серій фільтрується;
* пошук працює без перезавантаження сторінки;
* якщо результатів немає, показується empty search state;
* очищення search input повертає повний список відповідно до активної вкладки.

---

### 6.3. Filter series

Користувач може фільтрувати серії за:

* статусом серії;
* станом читання.

Фільтри застосовуються до активної вкладки.

---

### 6.4. Sort series

* list view показує серії компактніше.

Якщо list view не входить у MVP, сторінка використовує тільки grid view.

Expected behavior:

```text
Користувач переходить на /series/:seriesId
```

Series Details Page описується в окремій feature documentation.

### 6.7. Add book to empty series

Якщо серія створена вручну і ще не має книг, користувач може натиснути:


* прогрес серії перераховується.

## 8. What is not included

У MVP для **All Series Page** не входить:

* повна логіка створення серії;
* редагування серії;
* видалення серії;
* об’єднання дублікатів серій;
* повне керування книгами всередині серії;
* drag-and-drop порядку книг у серії;
* автоматичне визначення серії з інтернету;
* імпорт повного списку книг серії;
* додавання відсутньої наступної книги в wishlist;
* улюблені серії;
* середній рейтинг серії;
* складні рекомендації;
* reading challenge по серіях;
* analytics по жанрах серій;
* окрема сторінка “Незавершені серії” в sidebar.

Important:

```text
Створення нової серії входить у MVP як flow, який запускається з All Series Page.
Деталі створення та редагування серії описуються в Feature: Create / Edit Series.
```

## 9. Acceptance Criteria

### Page access

* Користувач може відкрити сторінку `/series` через sidebar.
* Сторінка доступна тільки авторизованому користувачу.
* Користувач бачить тільки свої серії.

### Header

* Користувач бачить title **Серії**.
* Користувач бачить badge з кількістю серій.
* Користувач бачить subtitle сторінки.
* Користувач бачить summary cards у header.
* Header показує кількість усіх серій.
* Header показує кількість повністю прочитаних серій.
* Header показує кількість недочитаних серій.
* Header показує кількість книг у серіях.
* Користувач бачить кнопку **Створити серію** у header.

### Create series entry point

* Користувач може натиснути **Створити серію**.
* Після натискання відкривається Create Series flow.
* Після успішного створення серія з’являється на сторінці `/series`.
* Якщо серія створена без книг, вона показується як empty series card.
* Деталі полів, валідації та submit behavior не описуються в All Series Page.

### Tabs

* Користувач бачить вкладку **Усі серії**.
* Користувач бачить вкладку **Недочитані**.
* Користувач може перемикатися між вкладками.
* Вкладка **Усі серії** показує всі серії користувача.
* Вкладка **Недочитані** показує тільки серії, які користувач почав, але не завершив.
* Порожні серії не показуються у вкладці **Недочитані**.

### Search and filters

* Користувач може шукати серії за назвою.
* Користувач може шукати серії за автором.
* Користувач може шукати серії за назвою книги в серії.
* Користувач може фільтрувати серії за статусом серії.
* Користувач може фільтрувати серії за станом читання.
* Користувач може фільтрувати серії без книг.
* Користувач може сортувати серії.

### Series card

* Користувач бачить картки серій.
* Кожна картка показує cover або placeholder.
* Кожна картка показує назву серії.
* Кожна картка показує автора, якщо він доступний.
* Кожна картка показує статус серії.
* Кожна картка показує кількість книг.
* Кожна картка показує кількість прочитаних книг.
* Кожна картка показує progress bar, якщо прогрес доступний.
* Кожна картка показує наступну книгу, якщо її можна визначити.
* Якщо всі книги серії прочитані, картка показує відповідний стан.
* Якщо серія не має книг, картка показує empty series state.
* Користувач може перейти на детальну сторінку серії.

### Progress

* Прогрес серії рахується по книгах зі статусом `finished`.
* Якщо `totalBooksCount` вказаний, прогрес рахується від нього.
* Якщо `totalBooksCount` не вказаний, прогрес рахується від кількості книг серії, доданих у бібліотеку.
* Progress bar не ламається, якщо в серії немає прочитаних книг.
* Для порожньої серії progress bar може не показуватися.
* Progress bar показує 100%, якщо всі книги серії прочитані.

### Right sidebar

* Користувач бачить right sidebar на desktop.
* Right sidebar містить блок **Швидкі дії**.
* Right sidebar містить блок **Продовжити серію**.
* Right sidebar містить блок **Найближчі до завершення**.
* Right sidebar містить блок **Статус циклів**.
* Right sidebar не дублює основний список серій.
* На mobile right sidebar переходить під основний контент.

### Empty and error states

* Якщо серій немає, користувач бачить empty state.
* Empty state дозволяє створити серію.
* Empty state дозволяє додати книгу.
* Якщо у вкладці **Недочитані** немає серій, користувач бачить окремий empty state.
* Якщо search не має результатів, користувач бачить empty search state.
* Якщо серії не завантажилися, користувач бачить error state.

### Scope

* All Series Page показує всі серії користувача.
* All Series Page дозволяє запустити Create Series flow.
* All Series Page не описує повну логіку створення серії.
* All Series Page не включає редагування серії.
* All Series Page не включає видалення серії.
* All Series Page не включає повне керування книгами всередині серії.
* Перехід на Series Details Page працює, але сама Series Details Page описується окремою документацією.
