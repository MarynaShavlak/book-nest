# Create / Edit Book Form Documentation

## 1. Мета форми

Форма створення / редагування книги потрібна, щоб користувач міг додати книгу до своєї бібліотеки BookNest або оновити вже створений запис.

Форма має підтримувати два режими:

* **Create mode** — створення нової книги;
* **Edit mode** — редагування вже існуючої книги.

Основна задача форми — зібрати базові дані про книгу, класифікацію, статуси та інші додаткові параметри без перевантаження користувача.

---

## 2. Структура форми

| Order | Блок               | Required | Purpose                                              |
| ----: | ------------------ | -------: | ---------------------------------------------------- |
|     1 | Основна інформація | Частково | Формує основну ідентичність книги                    |
|     2 | Класифікація       |       Ні | Допомагає фільтрувати, групувати й аналізувати книги |

---

## 3. Загальна поведінка форми

### Create mode

У режимі створення книги:

* форма відкривається з порожніми або default значеннями;
* required поля мають бути заповнені перед submit;
* optional поля можна залишити порожніми;
* custom author, custom publisher і custom tags створюються тільки після submit всієї форми;
* якщо користувач закрив форму без збереження, custom значення не створюються;
* preview оновлюється під час заповнення ключових полів.

### Edit mode

У режимі редагування книги:

* форма відкривається з поточними значеннями книги;
* користувач може змінити required і optional поля;
* користувач може очистити optional поля;
* якщо користувач змінює автора, оновлюється зв’язок книги з новим автором;
* якщо користувач очищає видавництво, книга зберігається без видавництва;
* якщо користувач прибирає жанри або теги, книга зберігається без них;
* видалення тегу з книги не означає автоматичне видалення тегу із загального списку тегів користувача.

### Submit flow

1. Користувач натискає submit.
2. Система перевіряє validation rules.
3. Якщо є помилки, користувач бачить validation errors.
4. Якщо дані валідні, система нормалізує значення.
5. Система перевіряє дублікати для custom значень.
6. Якщо custom author / publisher / tags не існують, вони створюються.
7. Книга зберігається з усіма вибраними та створеними значеннями.
8. Користувач бачить success state або переходить на сторінку книги / бібліотеки.

## 4. Shared rules

Ці правила застосовуються до всієї форми, тому не дублюються в описі кожного поля.

### 4.1. Text normalization

Перед submit усі текстові значення потрібно нормалізувати:

```ts
title = title.trim();
authorName = authorName.trim();
publisherName = publisherName?.trim() || null;
description = description?.trim() || null;
tagName = tagName.trim();
```

Якщо optional поле після `trim` стало порожнім, його потрібно зберігати як `null` або не відправляти взагалі — залежно від домовленості з backend.

### 4.2. HTML validation

HTML-теги заборонені в усіх текстових полях.

Це стосується:

* назви книги;
* custom author;
* custom publisher;
* опису книги;
* custom tags.

### 4.3. Empty spaces only

Текстове поле не може складатися тільки з пробілів.

Для required полів це вважається незаповненим значенням.

Для optional полів значення після `trim` має ставати `null`.

### 4.4. Duplicate check

Для custom значень перевірка дублікатів виконується по правилу:

```text
normalized value + user scope
```

Duplicate check має бути:

* case-insensitive;
* після `trim`;
* з урахуванням зайвих пробілів;
* бажано з нормалізацією апострофів, крапок і схожих символів.

Приклад однакових значень:

```text
Сара Дж. Маас
сара дж. маас
Сара Дж.  Маас
```

```text
slow burn
Slow Burn
slow   burn
```

Такі значення мають вважатися потенційними дублікатами.

### 4.5. Custom value creation

Custom значення не створюються одразу під час введення.

Для MVP рекомендовано створювати custom значення тільки після submit всієї форми.

Це стосується:

* custom author;
* custom publisher;
* custom tags.

Причина: не потрібно створювати зайві записи, якщо користувач ввів значення, але потім скасував створення книги.

### 4.6. Autocomplete with custom value pattern

Цей pattern використовується для:

* автора;
* видавництва;
* тегів.

#### Behavior

* користувач вводить search value;
* система показує збіги зі списку;
* користувач може вибрати існуюче значення;
* якщо потрібного значення немає, користувач може створити custom value;
* custom value тимчасово додається у форму;
* реальне створення custom value відбувається тільки після submit;
* перед створенням виконується duplicate check.

#### UI action

Якщо значення не знайдено, потрібно показати дію:

```text
+ Додати “{searchValue}”
```

Для автора можна показувати:

```text
+ Додати автора “{searchValue}”
```

Для видавництва:

```text
+ Додати видавництво “{searchValue}”
```

Для тегів:

```text
+ Додати тег “{searchValue}”
```

## 5. Preview behavior

Права панель preview має оновлюватися під час заповнення форми.

Preview не має дублювати всю інформацію з форми. Його задача — швидко показати, як виглядатиме книга в бібліотеці.

| Поле             | Як впливає на preview                 |
| ---------------- | ------------------------------------- |
| Назва книги      | Оновлює title                         |
| Автор            | Оновлює author                        |
| Жанри            | Можуть показуватися як chips / badges |
| Теги             | Можуть показуватися як chips / badges |
| Вікова категорія | Може показуватися як badge            |
| Видавництво      | Можна не показувати в compact preview |
| Опис             | Можна не показувати в compact preview |
| Мова книги       | Можна не показувати в compact preview |

Якщо назва книги не введена, у preview показується placeholder:

```text
Приклад назви книги
```

Якщо автор не вибраний, у preview показується placeholder:

```text
Автор не вказаний
```

# 6. Блок: Основна інформація

## 6.1. Purpose

Блок **“Основна інформація”** містить базові дані про книгу.

Цей блок має бути першим у формі, тому що саме він формує основну ідентичність книги:

* назва книги;
* автор;
* видавництво;
* короткий опис без спойлерів.

---

## 6.4. Block-specific behavior

### Create mode

У create mode:

* назва книги порожня;
* автор не вибраний;
* видавництво не вибране;
* опис порожній;
* preview показує placeholders для назви й автора;
* submit недоступний або показує errors, якщо required поля не заповнені.

### Edit mode

У edit mode:

* поля заповнюються поточними значеннями книги;
* користувач може змінити назву;
* користувач може змінити автора;
* користувач може змінити або очистити видавництво;
* користувач може змінити або очистити опис.

---

## 6.5. Acceptance Criteria

* Користувач бачить блок **Основна інформація** у формі створення / редагування книги.
* Користувач може ввести назву книги.
* Користувач може вибрати існуючого автора або створити custom author.
* Користувач може опційно вибрати існуюче видавництво або створити custom publisher.
* Користувач може опційно додати короткий опис без спойлерів.
* Якщо required поля не заповнені, книга не зберігається.
* Якщо введені невалідні дані, користувач бачить validation errors.
* Preview оновлюється після зміни назви й автора.
* Після submit значення блоку нормалізуються.

# 7. Блок: Класифікація

## 7.1. Purpose

Блок **“Класифікація”** потрібен, щоб користувач міг описати, до яких категорій належить книга.

Цей блок допомагає:

* фільтрувати книги в бібліотеці;
* будувати статистику по жанрах;
* швидко знаходити книги за тегами;
* групувати книги за мовою;
* показувати вікову категорію книги;
* покращити майбутні рекомендації всередині застосунку.

Блок не є обов’язковим для створення книги, але бажано показувати його одразу після блоку **“Основна інформація”**.

---

## 7.2. Fields overview

| Поле             | Type                        | Required | Source                         | Validation                  | Preview        |
| ---------------- | --------------------------- | -------: | ------------------------------ | --------------------------- | -------------- |
| Жанри            | Multi-select / Autocomplete |       Ні | Predefined config              | max 5, тільки існуючі жанри | Chips / badges |
| Теги             | Multi-select / Tag input    |       Ні | User saved tags + custom input | 2–30 символів, max 12       | Chips / badges |
| Вікова категорія | Select                      |       Ні | Predefined config              | тільки allowed values       | Badge          |
| Мова книги       | Select / Autocomplete       |       Ні | Predefined config              | тільки allowed values       | Optional       |

---

## 7.3. Field details

## Жанри

| Параметр         | Значення                    |
| ---------------- | --------------------------- |
| Label            | Жанри                       |
| Placeholder      | Оберіть жанри               |
| Type             | Multi-select / Autocomplete |
| Required         | Ні                          |
| Max selected     | 5                           |
| Duplicate values | Заборонено                  |
| Unknown genre    | Заборонено                  |
| Empty value      | Заборонено                  |

### Data source

Для MVP жанри беруться з predefined config:

```text
foundation/config/book-genres.json
```

Користувач не створює custom genres у формі книги.

Якщо в майбутньому буде дозволено custom genres, краще винести це в окремий розділ:

```text
Налаштування → Довідники
```

### Logic

* користувач може вибрати один або кілька жанрів;
* вибрані жанри показуються як chips;
* жанр можна видалити через `x` у chip;
* порядок вибраних жанрів не є критичним;
* жанри використовуються у фільтрах бібліотеки;
* жанри використовуються у статистиці;
* жанри показуються на детальній сторінці книги;
* жанри можуть показуватися в preview картки книги.

### Empty state

Якщо жанри не вибрані, у правій панелі можна показати:

```text
Жанри ще не обрані
```

### Error messages

```text
Можна обрати не більше 5 жанрів
Обраний жанр не знайдено
Цей жанр уже додано
```

## Теги

| Параметр        | Значення                                |
| --------------- | --------------------------------------- |
| Label           | Теги                                    |
| Placeholder     | Введіть тег або оберіть зі збережених   |
| Type            | Multi-select / Tag input                |
| Required        | Ні                                      |
| Min length      | 2 символи                               |
| Max length      | 30 символів                             |
| Max selected    | 12                                      |
| Duplicate check | Так                                     |
| HTML tags       | Заборонено                              |
| Allowed symbols | Літери, цифри, пробіли, дефіс, апостроф |

### Purpose

Теги — це персональні позначки, які користувач сам додає до книг.

Теги можуть описувати:

* настрій книги;
* троп;
* тему;
* особисту категорію;
* джерело асоціації;
* читацьке враження.

Приклади тегів:

```text
dark academia
slow burn
enemies to lovers
затишна книга
сильна героїня
прочитати восени
книжка з TikTok
плакала
```

### Data source

У BookNest немає global predefined списку тегів.

Список тегів формується індивідуально для кожного користувача.

Autocomplete показує тільки ті теги, які користувач уже створював раніше і які були збережені в його профілі / бібліотеці.

### First book behavior

Якщо користувач створює першу книгу і ще ніколи не додавав теги:

* список збережених тегів порожній;
* autocomplete не показує готових варіантів;
* користувач може ввести новий тег вручну;
* після додавання тег показується як chip;
* після submit книги новий тег зберігається для цього користувача;
* при створенні наступних книг цей тег уже буде доступний в autocomplete.

Приклад:

```text
Перша книга:
користувач додає тег “dark academia”

Наступна книга:
“dark academia” уже з’являється в autocomplete
```

### Add tag logic

* користувач вводить текст тегу;
* якщо такий тег уже існує серед збережених тегів користувача, він може вибрати його зі списку;
* якщо такого тегу ще немає, користувач може створити новий;
* тег додається після натискання `Enter` або вибору зі списку;
* вибрані теги показуються як chips;
* тег можна прибрати з книги через `x` у chip;
* видалення chip прибирає тег тільки з цієї книги.

### Custom tag creation

Custom tags створюються тільки після submit всієї форми книги.

#### Flow

1. Користувач вводить новий тег.
2. Тег тимчасово додається у форму як chip.
3. Користувач зберігає книгу.
4. Після submit новий тег зберігається для поточного користувача.
5. Тег стає доступним в autocomplete для наступних книг.

### Empty states

Якщо користувач ще не створював теги, у dropdown / autocomplete можна показати:

```text
У вас ще немає збережених тегів. Введіть новий тег і натисніть Enter.
```

Якщо теги не вибрані в поточній формі, у правій панелі можна показати:

```text
Теги ще не додані
```

### Error messages

```text
Тег має містити щонайменше 2 символи
Тег не може бути довшим за 30 символів
Такий тег уже додано
Можна додати не більше 12 тегів
```

* користувач може змінити вікову категорію;
* користувач може змінити мову книги;

## 7.6. Acceptance Criteria

* Користувач бачить блок **Класифікація** у формі створення / редагування книги.
* Користувач може опційно вибрати один або кілька жанрів.
* Користувач може опційно вибрати існуючий тег або створити custom tag.
* Якщо користувач створює першу книгу і тегів ще немає, він може додати новий тег вручну.
* Нові теги зберігаються для користувача тільки після submit книги.
* Користувач може опційно вибрати вікову категорію.
* Якщо вікова категорія не вибрана, використовується `not_specified`.
* Користувач може опційно вибрати мову книги.
* Якщо мова не вибрана, використовується `ukrainian`.
* Блок **Класифікація** не блокує створення книги, якщо всі його поля порожні.
* Якщо введені невалідні значення, користувач бачить validation errors.
* Жанри й теги можуть оновлювати preview.

# 8. Блок: Статус

## 8.1. Purpose

Блок **“Статус”** потрібен, щоб користувач міг визначити поточний стан книги у своїй бібліотеці.

Цей блок відповідає за:

* статус читання книги;
* додаткові дані, пов’язані з читанням;
* статус володіння книгою;
* додаткові дані, пов’язані з купівлею, доставкою або позикою;
* формат книги;
* появу книги у спеціальних розділах застосунку:

    * **Читаю зараз**;
    * **Книги до покупки**;
    * **Книги в дорозі**;
    * **Позичені книги**;
    * **Статистика**;
    * **Цілі читання**;
    * **Календар читання**.

Блок є важливим для створення книги, бо саме статуси визначають, де книга буде відображатися після збереження.

---

---

## 8.2. UI behavior

Статуси у формі мають відображатися не як dropdown, а як **chip-перемикачі**.

### Статус читання

* відображається як група chips;
* працює як single-select / radio group;
* користувач може вибрати тільки один статус читання;
* при виборі нового статусу попередній статус автоматично знімається;
* якщо обраний статус читання потребує додаткових даних, під групою відкривається conditional block.

### Статус володіння

* відображається як група chips;
* працює як single-select / radio group;
* користувач може вибрати тільки один статус володіння;
* якщо обраний статус володіння потребує додаткових даних, під групою відкривається conditional block.

### Формат книги

* відображається як група chips;
* працює як multi-select;
* користувач може вибрати один або кілька форматів;
* формат не є статусом володіння.

---

## 8.3. Recommended UI order

У формі блок **“Статус”** має йти в такому порядку:

1. **Статус читання**
2. **Conditional block для статусу читання**, якщо він потрібен
3. **Статус володіння**
4. **Conditional block для статусу володіння**, якщо він потрібен
5. **Формат книги**

Це важливо для зручності: користувач обирає статус — і одразу під ним бачить поля, які стосуються саме цього статусу.

# 8.5. Статус читання

| Параметр      | Значення                  |
| ------------- | ------------------------- |
| Label         | Статус читання            |
| Type          | Chip single-select group  |
| Required      | Так                       |
| Default value | `not_started`             |
| Unknown value | Заборонено                |
| Empty value   | Замінити на `not_started` |

## Purpose

Статус читання показує, на якому етапі читання знаходиться книга.

Це основний статус для читацького прогресу, Dashboard, статистики, цілей читання та календаря.

## Options

| Value          | Label          | Tone    | Icon             | Де використовується                     |
| -------------- | -------------- | ------- | ---------------- | --------------------------------------- |
| `not_started`  | Не почато      | neutral | `i-circle-slash` | дефолт нової книги, фільтри             |
| `want_to_read` | Хочу прочитати | accent  | `i-bookmark`     | бібліотека, фільтри                     |
| `reading`      | Читаю          | info    | `i-book`         | Dashboard “Читаю зараз”, картка, деталі |
| `paused`       | На паузі       | warning | `i-clock`        | бібліотека, фільтри, деталі             |
| `finished`     | Прочитано      | success | `i-check-circle` | статистика, цілі читання, календар      |
| `dnf`          | Покинуто       | neutral | `i-x-circle`     | бібліотека, фільтри                     |
| `rereading`    | Перечитую      | info    | `i-refresh`      | Dashboard, деталі                       |

## Logic

* поле обов’язкове;
* за замовчуванням нова книга має статус `not_started`;
* користувач може вибрати тільки один статус читання;
* якщо користувач вибирає `reading`, книга має з’явитися у Dashboard-блоці **“Читаю зараз”**;
* якщо користувач вибирає `finished`, книга враховується у статистиці, цілях читання та календарі;
* якщо користувач вибирає `paused`, книга може показуватися у фільтрі **“На паузі”**;
* якщо користувач вибирає `dnf`, книга не рахується як прочитана;
* якщо користувач вибирає `rereading`, книга може вважатися активним читанням.

## Important note about `want_to_read`

`want_to_read` означає, що користувач хоче прочитати книгу.

Це не те саме, що **Черга читання**.

Книга зі статусом `want_to_read` не має автоматично додаватися в reading queue.
Додавання в чергу має бути окремою дією або окремим checkbox.

## MVP note

Для MVP можна показувати всі статуси, крім `rereading`, якщо логіка повторного читання ще не готова.

`rereading` можна залишити в config, але тимчасово не показувати в UI.

## Error message

```text
Оберіть статус читання
```

# 8.6. Conditional blocks для статусу читання

Conditional blocks для статусу читання потрібні, щоб зібрати додаткові дані для прогресу, статистики, цілей читання та календаря.

Ці блоки не мають сильно блокувати створення книги. Більшість полів у них optional.

---

## Якщо reading status = `not_started`

Додатковий блок не показується.

### Logic

* книга зберігається як ще не почата;
* прогрес читання не потрібен;
* дата початку читання не потрібна;
* книга не враховується як активне читання.

---

## Якщо reading status = `want_to_read`

Додатковий блок не показується.

### Logic

* книга позначається як та, яку користувач хоче прочитати;
* книга не додається автоматично в чергу читання;
* якщо потрібно додати книгу в чергу, це має бути окремою дією.

---

## Якщо reading status = `reading`

Показати блок:

```text
Прогрес читання
```

### Поля

| Поле                 | Type         | Required | Опис                                 |
| -------------------- | ------------ | -------: | ------------------------------------ |
| Поточна сторінка     | Number input |       Ні | Сторінка, на якій зараз користувач   |
| Дата початку читання | Date picker  |       Ні | Коли користувач почав читати книгу   |
| Нотатка до прогресу  | Textarea     |       Ні | Коротка нотатка про поточний прогрес |

### Logic

* блок показується тільки для `reading`;
* якщо є `pagesCount`, поточна сторінка не може бути більшою за кількість сторінок;
* якщо поточна сторінка дорівнює кількості сторінок, можна запропонувати змінити статус на `finished`;
* якщо дата початку не вибрана, можна залишити поле порожнім або автоматично підставити поточну дату;

# 8.7. Статус володіння

| Параметр      | Значення                 |
| ------------- | ------------------------ |
| Label         | Статус володіння         |
| Type          | Chip single-select group |
| Required      | Так                      |
| Default value | `none`                   |
| Unknown value | Заборонено               |
| Empty value   | Замінити на `none`       |

## Purpose

Статус володіння показує, чи є книга у користувача, чи він хоче її купити, чи книга в дорозі, чи вона позичена.

Цей статус впливає на те, у яких розділах буде показана книга.

## Options

| Value                   | Label             | Tone    | Icon                  | Де використовується         |
| ----------------------- | ----------------- | ------- | --------------------- | --------------------------- |
| `none`                  | Немає             | neutral | `i-circle-slash`      | дефолт, фільтри             |
| `want_to_buy`           | Хочу купити       | accent  | `i-cart`              | сторінка “Книги до покупки” |
| `in_transit`            | В дорозі          | info    | `i-truck`             | сторінка “Книги в дорозі”   |
| `owned`                 | Маю               | success | `i-check-circle`      | бібліотека, деталі          |
| `borrowed_from_someone` | Позичена у когось | info    | `i-arrow-down-circle` | сторінка “Позичені книги”   |
| `lent_to_someone`       | Видана комусь     | warning | `i-arrow-up-right`    | сторінка “Позичені книги”   |

## Important naming

Для статусу **“В дорозі”** в основному статусі володіння потрібно використовувати:

```text
in_transit
```

Не використовувати `ordered` як ownership status.

`ordered` має залишатися тільки всередині delivery status і означати **“Замовлено”**.

## Logic

* поле обов’язкове;
* за замовчуванням нова книга має статус `none`;
* користувач може вибрати тільки один статус володіння;
* якщо вибрано `want_to_buy`, книга з’являється у розділі **“Книги до покупки”**;
* якщо вибрано `in_transit`, книга з’являється у розділі **“Книги в дорозі”**;
* якщо вибрано `owned`, книга показується як книга, що є у користувача;
* якщо вибрано `borrowed_from_someone`, книга з’являється у розділі **“Позичені книги”** як книга, яку користувач позичив у когось;
* якщо вибрано `lent_to_someone`, книга з’являється у розділі **“Позичені книги”** як книга, яку користувач дав комусь.

# 8.10. Conditional data behavior

## Create mode

Якщо користувач заповнив conditional block, а потім змінив статус на інший, попередній conditional block приховується.

У create mode дані прихованого conditional block не потрібно відправляти при submit, якщо вони більше не відповідають активному статусу.

### Приклад

1. Користувач вибрав `finished`.
2. Заповнив дату прочитання й оцінку.
3. Потім змінив статус читання на `reading`.
4. Блок **“Завершення”** приховується.
5. При submit дані з блоку **“Завершення”** не відправляються.

---

## Edit mode

В edit mode потрібно бути обережнішим, бо conditional data може вже бути збережена.

Якщо користувач змінює статус так, що поточний conditional block більше неактуальний, потрібно показати confirmation modal.

### Confirmation modal

```text
Title: Змінити статус?

Description:
Поточні дані, пов’язані з попереднім статусом, можуть бути очищені або більше не відображатися після зміни статусу.

Actions:
- Скасувати
- Змінити статус
```

### Recommended behavior

* не очищати conditional data автоматично без підтвердження;
* якщо користувач підтвердив зміну, новий статус застосовується;
* попередній conditional block приховується;
* для MVP можна очищати неактуальні conditional data після підтвердження.

# 8.14. Block-specific behavior

## Create mode

У create mode:

* `readingStatus` має default `not_started`;
* reading conditional blocks не показуються, поки користувач не вибере статус, який потребує додаткових полів;
* `ownershipStatus` має default `none`;
* ownership conditional blocks не показуються, поки користувач не вибере відповідний ownership status;
* `formats` відкривається порожнім;
* якщо користувач змінив статус, попередній conditional block приховується;
* у submit потрапляють тільки дані активних conditional blocks.

## Edit mode

У edit mode:

* усі статуси відкриваються з поточними значеннями книги;
* користувач може змінити reading status;
* користувач може змінити ownership status;
* користувач може змінити формати;
* якщо зміна статусу приховує conditional block, потрібно показати confirmation modal;
* не очищати conditional data автоматично без підтвердження;
* якщо користувач переводить книгу з `in_transit` у `owned`, книга має зникнути з розділу **“Книги в дорозі”**;
* якщо користувач переводить позику в `returned`, книга має перестати бути активною у списку позичених.

# 8.16. Acceptance Criteria

* Користувач бачить блок **Статус** у формі створення / редагування книги.
* Статус читання показується як chip single-select group.
* Користувач може вибрати тільки один статус читання.
* Якщо статус читання не вибраний, використовується `not_started`.
* Якщо вибрано `reading`, показується блок **Прогрес читання**.
* Якщо вибрано `finished`, показується блок **Завершення**.
* Якщо вибрано `paused`, показується блок **Пауза в читанні**.
* Якщо вибрано `dnf`, показується блок **Покинуто**.
* Якщо вибрано `not_started` або `want_to_read`, reading conditional block не показується.
* Статус володіння показується як chip single-select group.
* Користувач може вибрати тільки один статус володіння.
* Якщо статус володіння не вибраний, використовується `none`.
* Формат книги показується як chip multi-select group.
* Користувач може вибрати один або кілька форматів книги.
* Якщо формат не вибраний, книга зберігається без формату.
* Якщо вибрано `want_to_buy`, показується блок **Інформація про купівлю**.
* Якщо вибрано `in_transit`, показується блок **Інформація про доставку**.
* Якщо вибрано `borrowed_from_someone`, показується блок **Позичена у когось**.
* Якщо вибрано `lent_to_someone`, показується блок **Видана комусь**.
* Якщо статус змінено в create mode, неактивний conditional block приховується і не відправляється при submit.
* Якщо статус змінено в edit mode і є збережені conditional data, показується confirmation modal.
* Якщо вибрано `reading`, книга з’являється у Dashboard-блоці **Читаю зараз**.
* Якщо вибрано `finished`, книга враховується у статистиці та reading goals.
* Якщо вибрано `want_to_buy`, книга з’являється на сторінці **Книги до покупки**.
* Якщо вибрано `in_transit`, книга з’являється на сторінці **Книги в дорозі**.
* Якщо вибрано `borrowed_from_someone` або `lent_to_someone`, книга з’являється на сторінці **Позичені книги**.
* `want_to_read` не додає книгу автоматично в чергу читання.
* Delivery due statuses не показуються як ручний select.
* Loan due statuses не показуються як ручний select.
* `received` не показується як delivery status, а працює як action.
* `isFavorite` не належить до статусів і керується окремим favorite toggle.
* Status badges у preview оновлюються після зміни значень.
* У create mode блок відкривається з default значеннями.
* У edit mode блок відкривається з поточними значеннями книги.
* Якщо введені невалідні значення, користувач бачить validation errors.

# 9. Блок: Тип книги 

## 9.1. Purpose

Блок **“Тип книги”** потрібен, щоб користувач міг вказати, чи є книга самостійною книгою, чи частиною книжкової серії.

Цей блок відповідає за:

* прив’язку книги до серії;
* номер частини у серії;
* статус серії;
* загальну кількість книг у серії;
* появу книги на сторінці деталей серії;
* правильний порядок книг усередині серії;
* перерахунок прогресу серії.

---

## 9.2. UI behavior

У формі створення / редагування книги блок **“Тип книги”** має починатися з перемикача:

```text
[ Соло книга ] [ Частина серії ]
```

Це має бути **single-select segmented control**.

Користувач може вибрати тільки один варіант:

| Варіант       | Логіка                     |
| ------------- | -------------------------- |
| `solo`        | Книга не належить до серії |
| `series_part` | Книга є частиною серії     |

---

## 9.3. Fields overview

| Поле                    | Type                            | Required | Коли показувати            | Опис                                     |
| ----------------------- | ------------------------------- | -------: | -------------------------- | ---------------------------------------- |
| Тип книги               | Segmented control               |      Так | Завжди                     | Соло книга або частина серії             |
| Назва серії             | Autocomplete / Creatable select |      Так | Якщо вибрано `series_part` | Вибір існуючої або створення нової серії |
| Номер частини           | Number input                    |      Так | Якщо вибрано `series_part` | Порядковий номер книги в серії           |

> **Властивості рівня серії** — статус серії, загальна кількість книг, опис і обкладинка — задаються в modal **“Створити серію”** (або згодом на сторінці серії), а не як інлайн-поля в кожній книзі (див. §9.6).

---

# 9.4. Тип книги

| Type          | Segmented control |
| Required      | Так               |

## Options

| Value         | Label         | Опис                       |
| ------------- | ------------- | -------------------------- |
| `solo`        | Соло книга    | Книга не належить до серії |
| `series_part` | Частина серії | Книга є частиною серії     |

## Logic

* за замовчуванням обрано **Соло книга**;
* якщо обрано **Соло книга**, поля серії приховані;
* якщо обрано **Частина серії**, відкриваються поля серії;
* якщо користувач перемикається з **Частина серії** назад на **Соло книга**, поля серії приховуються;
* у create mode дані прихованого блоку серії не відправляються при submit;
* у edit mode, якщо книга вже була прив’язана до серії, при зміні на **Соло книга** потрібно показати confirmation modal.

# 9.5. Назва серії

| Параметр    | Значення                         |
| ----------- | -------------------------------- |
| Label       | Назва серії                      |
| Placeholder | Оберіть або створіть серію       |
| Type        | Autocomplete / Creatable select  |
| Required    | Так, якщо книга є частиною серії |

## Data source

Поле має шукати серії з таких джерел:

* уже створені серії поточного користувача;
* нова серія, яку користувач може створити через modal.

## Logic

* користувач вводить назву серії;
* autocomplete показує існуючі серії користувача;
* користувач може вибрати існуючу серію;
* якщо серії немає, показати дію:

```text
+ Створити серію “{searchValue}”
```

* після натискання відкривається modal **“Створити серію”**;
* після заповнення modal нова серія тимчасово підставляється у форму книги;
* реальна серія створюється тільки після submit всієї форми книги.

---

# 9.6. Modal “Створити серію”

Modal **“Створити серію”** потрібна для швидкого створення нової серії прямо під час створення книги.

Modal не має одразу створювати серію в базі.
Вона має створити тільки тимчасовий draft series у формі.

---

## Поля modal

| Поле                    | Type                     | Required | Опис                                |
| ----------------------- | ------------------------ | -------: | ----------------------------------- |
| Назва серії             | Text input               |      Так | Назва нової серії                   |
| Статус серії            | Chip single-select group |       Ні | Завершена, ще виходить або невідомо |
| Загальна кількість книг | Number input             |       Ні | Скільки книг у серії                |
| Опис серії              | Textarea                 |       Ні | Короткий опис серії                 |
| Обкладинка серії        | Image upload             |       Ні | Зображення серії                    |

---

## Кнопки modal

```text
Скасувати
Створити серію
```

---

## Logic

* користувач натискає **Створити серію** в autocomplete;
* відкривається modal;
* користувач заповнює дані серії;
* після натискання **Створити серію** modal закривається;
* нова серія підставляється в поле **Назва серії**;
* фокус бажано перевести на поле **Номер частини**;
* серія ще не створюється в базі;
* серія буде створена тільки після submit всієї форми книги.

---

# 9.7. Варіант створення серії

Для MVP використовується варіант:

```text
Серія створюється тільки після submit книги.
```

## Чому так

Це потрібно, щоб не створювати порожні серії, якщо користувач:

* відкрив modal;
* ввів назву серії;
* натиснув “Створити серію”;
* але потім скасував створення книги.

У такому випадку в базі не має залишитися зайва серія без книг.

---

## Submit flow для нової серії

Якщо користувач створив нову серію через modal і потім натиснув **Зберегти книгу**, submit має працювати так:

1. Validate form.
2. Validate series block.
3. Якщо серія нова — створити серію.
4. Отримати ID створеної серії.
5. Створити книгу.
6. Прив’язати книгу до створеної серії.
7. Присвоїти книзі номер частини.
8. Додати книгу на сторінку деталей серії.
9. Перерахувати прогрес серії.
10. Показати success toast.
11. Перейти на детальну сторінку книги.

---

## Submit flow для існуючої серії

Якщо користувач вибрав уже існуючу серію:

1. Validate form.
2. Validate series block.
3. Створити або оновити книгу.
4. Прив’язати книгу до вибраної серії.
5. Присвоїти книзі номер частини.
6. Додати книгу на сторінку деталей серії.
7. Перерахувати прогрес серії.
8. Показати success toast.

# 9.17. Acceptance Criteria

* Користувач бачить блок **Серія** у формі створення / редагування книги.
* За замовчуванням книга створюється як **Соло книга**.
* Користувач може перемкнути тип книги на **Частина серії**.
* Якщо вибрано **Частина серії**, відкриваються поля серії.
* Користувач може вибрати існуючу серію.
* Якщо потрібної серії немає, користувач може відкрити modal **“Створити серію”**.
* Modal **“Створити серію”** містить назву серії, статус серії, загальну кількість книг, опис і обкладинку.
* Modal **“Створити серію”** не створює серію в базі одразу.
* Нова серія з modal тимчасово підставляється у форму книги.
* Реальна серія створюється тільки після submit книги.
* Якщо користувач скасував створення книги, draft series не зберігається.
* Користувач має вказати номер частини, якщо книга є частиною серії.
* Книга після збереження з’являється на сторінці деталей серії.
* Книга сортується в серії за номером частини.
* Прогрес серії перераховується після додавання книги.
* Якщо користувач перемикає книгу на **Соло книга** в edit mode, показується confirmation modal.

# 111111. Final Acceptance Criteria

* Користувач може створити книгу через форму Create Book.
* Користувач може редагувати книгу через форму Edit Book.
* У create mode форма відкривається з порожніми або default значеннями.
* У edit mode форма відкривається з поточними значеннями книги.
* Required поля мають бути заповнені перед submit.
* Optional поля можна залишити порожніми.
* Custom author, publisher і tags створюються тільки після submit.
* Для custom значень виконується duplicate check.
* Текстові значення нормалізуються перед збереженням.
* Невалідні значення не зберігаються.
* Користувач бачить зрозумілі validation errors.
* Preview оновлюється під час заповнення ключових полів.
* Книга не створюється і не оновлюється, якщо є validation errors.
