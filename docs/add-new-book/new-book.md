# Create / Edit Book Form Documentation

## 1. Мета форми

Форма створення / редагування книги потрібна, щоб користувач міг додати книгу до своєї бібліотеки BookNest або оновити вже створений запис.

Форма має підтримувати два режими:

* **Create mode** — створення нової книги;
* **Edit mode** — редагування вже існуючої книги.

Основна задача форми — зібрати базові дані про книгу, класифікацію, статуси та інші додаткові параметри без перевантаження користувача.

---

## 2. Структура форми

Форма складається із семи змістових блоків (розділи 6–12 цього документа):

| Розділ | Блок                     | Required | Призначення                                          |
| -----: | ------------------------ | -------: | ---------------------------------------------------- |
|      6 | Основна інформація       | Частково | Формує основну ідентичність книги                    |
|      7 | Класифікація             |       Ні | Допомагає фільтрувати, групувати й аналізувати книги |
|      8 | Статус                   |      Так | Статуси читання, володіння та формат книги           |
|      9 | Тип книги / Серія        | Частково | Зв’язок книги із серією та номер частини             |
|     10 | Деталі видання           |       Ні | Технічні дані конкретного видання                    |
|     11 | Організація в бібліотеці |       Ні | Улюблені, черга читання та власні списки             |
|     12 | Обкладинка книги         |       Ні | Зображення обкладинки книги                          |

## 3. Загальна поведінка форми

### Create mode

У режимі створення книги:

* форма відкривається з порожніми або default значеннями;
* required поля мають бути заповнені перед submit;
* optional поля можна залишити порожніми;
* custom author, custom publisher і custom tags створюються тільки після submit всієї форми;
* якщо користувач закрив форму без збереження, custom значення не створюються;
* preview оновлюється під час заповнення ключових полів.

### Edit mode

У режимі редагування книги:

* форма відкривається з поточними значеннями книги;
* користувач може змінити required і optional поля;
* користувач може очистити optional поля;
* якщо користувач змінює автора, оновлюється зв’язок книги з новим автором;
* якщо користувач очищає видавництво, книга зберігається без видавництва;
* якщо користувач прибирає жанри або теги, книга зберігається без них;
* видалення тегу з книги не означає автоматичне видалення тегу із загального списку тегів користувача.

### Submit flow

1. Користувач натискає submit.
2. Система перевіряє validation rules.
3. Якщо є помилки, користувач бачить validation errors.
4. Якщо дані валідні, система нормалізує значення.
5. Система перевіряє дублікати для custom значень.
6. Якщо custom author / publisher / tags не існують, вони створюються.
7. Книга зберігається з усіма вибраними та створеними значеннями.
8. Користувач бачить success state або переходить на сторінку книги / бібліотеки.

## 4. Shared rules

Ці правила застосовуються до всієї форми, тому не дублюються в описі кожного поля.

### 4.1. Text normalization

Перед submit усі текстові значення потрібно нормалізувати:

```ts
title = title.trim();
authorName = authorName.trim();
publisherName = publisherName?.trim() || null;
description = description?.trim() || null;
tagName = tagName.trim();
```

Якщо optional поле після `trim` стало порожнім, його потрібно зберігати як `null` або не відправляти взагалі — залежно від домовленості з backend.

### 4.2. HTML validation

HTML-теги заборонені в усіх текстових полях.

Це стосується:

* назви книги;
* custom author;
* custom publisher;
* опису книги;
* custom tags.

### 4.3. Empty spaces only

Текстове поле не може складатися тільки з пробілів.

Для required полів це вважається незаповненим значенням.

Для optional полів значення після `trim` має ставати `null`.

### 4.4. Duplicate check

Для custom значень перевірка дублікатів виконується по правилу:

```text
normalized value + user scope
```

Duplicate check має бути:

* case-insensitive;
* після `trim`;
* з урахуванням зайвих пробілів;
* бажано з нормалізацією апострофів, крапок і схожих символів.

Приклад однакових значень:

```text
Сара Дж. Маас
сара дж. маас
Сара Дж.  Маас
```

```text
slow burn
Slow Burn
slow   burn
```

Такі значення мають вважатися потенційними дублікатами.

### 4.5. Custom value creation

Custom значення не створюються одразу під час введення.

Для MVP рекомендовано створювати custom значення тільки після submit всієї форми.

Це стосується:

* custom author;
* custom publisher;
* custom tags.

Причина: не потрібно створювати зайві записи, якщо користувач ввів значення, але потім скасував створення книги.

### 4.6. Autocomplete with custom value pattern

Цей pattern використовується для:

* автора;
* видавництва;
* тегів.

#### Behavior

* користувач вводить search value;
* система показує збіги зі списку;
* користувач може вибрати існуюче значення;
* якщо потрібного значення немає, користувач може створити custom value;
* custom value тимчасово додається у форму;
* реальне створення custom value відбувається тільки після submit;
* перед створенням виконується duplicate check.

#### UI action

Якщо значення не знайдено, потрібно показати дію:

```text
+ Додати “{searchValue}”
```

Для автора можна показувати:

```text
+ Додати автора “{searchValue}”
```

Для видавництва:

```text
+ Додати видавництво “{searchValue}”
```

Для тегів:

```text
+ Додати тег “{searchValue}”
```

## 5. Preview behavior

Права панель preview має оновлюватися під час заповнення форми.

Preview не має дублювати всю інформацію з форми. Його задача — швидко показати, як виглядатиме книга в бібліотеці.

| Поле             | Як впливає на preview                 |
| ---------------- | ------------------------------------- |
| Назва книги      | Оновлює title                         |
| Автор            | Оновлює author                        |
| Жанри            | Можуть показуватися як chips / badges |
| Теги             | Можуть показуватися як chips / badges |
| Вікова категорія | Може показуватися як badge            |
| Видавництво      | Можна не показувати в compact preview |
| Опис             | Можна не показувати в compact preview |
| Мова книги       | Можна не показувати в compact preview |

Якщо назва книги не введена, у preview показується placeholder:

```text
Приклад назви книги
```

Якщо автор не вибраний, у preview показується placeholder:

```text
Автор не вказаний
```

## 6. Блок: Основна інформація

### 6.1. Purpose

Блок **“Основна інформація”** містить базові дані про книгу.

Цей блок має бути першим у формі, тому що саме він формує основну ідентичність книги:

* назва книги;
* автор;
* видавництво;
* короткий опис без спойлерів.

---

### 6.2. Fields overview

| Поле                            | Type                  | Required | Source              | Validation                                      | Preview        |
| ------------------------------- | --------------------- | -------: | ------------------- | ----------------------------------------------- | -------------- |
| Назва книги                     | Text input            |      Так | Manual input        | 1–150 символів                                  | Оновлює title  |
| Автор                           | Autocomplete / Select |      Так | Predefined + custom | existing або custom author 2–100 символів       | Оновлює author |
| Видавництво                     | Autocomplete / Select |       Ні | Predefined + custom | custom publisher 2–100 символів, якщо заповнене | Optional       |
| Коротко про книгу без спойлерів | Textarea              |       Ні | Manual input        | max 500 символів                                | Optional       |

---

### 6.3. Field details

#### Назва книги

| Параметр            | Значення              |
| ------------------- | --------------------- |
| Label               | Назва книги *         |
| Placeholder         | Введіть назву книги   |
| Type                | Text input            |
| Required            | Так                   |
| Min length          | 1 символ після `trim` |
| Max length          | 150 символів          |
| Empty spaces only   | Заборонено            |
| HTML tags           | Заборонено            |
| Preview placeholder | Приклад назви книги   |

##### Logic

* користувач вводить назву книги вручну;
* значення оновлює title у preview;
* якщо поле порожнє, у preview показується placeholder;
* без назви книга не може бути створена.

##### Error messages

```text
Введіть назву книги
Назва книги не може бути довшою за 150 символів
```

#### Автор

| Параметр                 | Значення                          |

* custom authors поточного користувача.

Для MVP можна використовувати local config. У майбутньому це можна замінити на API.

* користувач починає вводити ім’я автора;
* система показує збіги зі списку авторів;
* користувач може вибрати існуючого автора;
* якщо автора немає, користувач може додати custom author;
* після вибору або створення автора поле вважається заповненим;
* у preview оновлюється ім’я автора;
* якщо автор не вибраний, submit має бути заблокований або має показувати validation error.

##### Custom author creation

Custom author створюється тільки після submit всієї форми.

Перед створенням потрібно виконати duplicate check по правилу:


### 6.4. Block-specific behavior

#### Create mode

У create mode:

* назва книги порожня;
* автор не вибраний;
* видавництво не вибране;
* опис порожній;
* preview показує placeholders для назви й автора;
* submit недоступний або показує errors, якщо required поля не заповнені.

#### Edit mode

У edit mode:

* поля заповнюються поточними значеннями книги;
* користувач може змінити назву;
* користувач може змінити автора;
* користувач може змінити або очистити видавництво;
* користувач може змінити або очистити опис.

---

### 6.5. Acceptance Criteria

* Користувач бачить блок **Основна інформація** у формі створення / редагування книги.
* Користувач може ввести назву книги.
* Користувач може вибрати існуючого автора або створити custom author.
* Користувач може опційно вибрати існуюче видавництво або створити custom publisher.
* Користувач може опційно додати короткий опис без спойлерів.
* Якщо required поля не заповнені, книга не зберігається.
* Якщо введені невалідні дані, користувач бачить validation errors.
* Preview оновлюється після зміни назви й автора.
* Після submit значення блоку нормалізуються.

## 7. Блок: Класифікація

### 7.1. Purpose

Блок **“Класифікація”** потрібен, щоб користувач міг описати, до яких категорій належить книга.

Цей блок допомагає:

* фільтрувати книги в бібліотеці;
* будувати статистику по жанрах;
* швидко знаходити книги за тегами;
* групувати книги за мовою;
* показувати вікову категорію книги;
* покращити майбутні рекомендації всередині застосунку.

Блок не є обов’язковим для створення книги, але бажано показувати його одразу після блоку **“Основна інформація”**.

---

### 7.2. Fields overview

| Поле             | Type                        | Required | Source                         | Validation                  | Preview        |
| ---------------- | --------------------------- | -------: | ------------------------------ | --------------------------- | -------------- |
| Жанри            | Multi-select / Autocomplete |       Ні | Predefined config              | max 5, тільки існуючі жанри | Chips / badges |
| Теги             | Multi-select / Tag input    |       Ні | User saved tags + custom input | 2–30 символів, max 12       | Chips / badges |
| Вікова категорія | Select                      |       Ні | Predefined config              | тільки allowed values       | Badge          |
| Мова книги       | Select / Autocomplete       |       Ні | Predefined config              | тільки allowed values       | Optional       |

---

### 7.3. Field details

#### Жанри

| Параметр         | Значення                    |
| ---------------- | --------------------------- |
| Label            | Жанри                       |
| Placeholder      | Оберіть жанри               |
| Type             | Multi-select / Autocomplete |
| Required         | Ні                          |
| Max selected     | 5                           |
| Duplicate values | Заборонено                  |
| Unknown genre    | Заборонено                  |
| Empty value      | Заборонено                  |

##### Data source

Для MVP жанри беруться з predefined config:

```text
foundation/config/book-genres.json
```

Користувач не створює custom genres у формі книги.

Якщо в майбутньому буде дозволено custom genres, краще винести це в окремий розділ:

```text
Налаштування → Довідники
```

##### Logic

* користувач може вибрати один або кілька жанрів;
* вибрані жанри показуються як chips;
* жанр можна видалити через `x` у chip;
* порядок вибраних жанрів не є критичним;
* жанри використовуються у фільтрах бібліотеки;
* жанри використовуються у статистиці;
* жанри показуються на детальній сторінці книги;
* жанри можуть показуватися в preview картки книги.

##### Empty state

Якщо жанри не вибрані, у правій панелі можна показати:

```text
Жанри ще не обрані
```

##### Error messages

```text
Можна обрати не більше 5 жанрів
Обраний жанр не знайдено
Цей жанр уже додано
```

#### Теги

| Параметр        | Значення                                |
| --------------- | --------------------------------------- |
| Label           | Теги                                    |
| Placeholder     | Введіть тег або оберіть зі збережених   |
| Type            | Multi-select / Tag input                |
| Required        | Ні                                      |
| Min length      | 2 символи                               |
| Max length      | 30 символів                             |
| Max selected    | 12                                      |
| Duplicate check | Так                                     |
| HTML tags       | Заборонено                              |
| Allowed symbols | Літери, цифри, пробіли, дефіс, апостроф |

##### Purpose

Теги — це персональні позначки, які користувач сам додає до книг.

Теги можуть описувати:

* настрій книги;
* троп;
* тему;
* особисту категорію;
* джерело асоціації;
* читацьке враження.

Приклади тегів:

```text
dark academia
slow burn
enemies to lovers
затишна книга
сильна героїня
прочитати восени
книжка з TikTok
плакала
```

##### Data source

У BookNest немає global predefined списку тегів.

Список тегів формується індивідуально для кожного користувача.

Autocomplete показує тільки ті теги, які користувач уже створював раніше і які були збережені в його профілі / бібліотеці.

##### First book behavior

Якщо користувач створює першу книгу і ще ніколи не додавав теги:

* список збережених тегів порожній;
* autocomplete не показує готових варіантів;
* користувач може ввести новий тег вручну;
* після додавання тег показується як chip;
* після submit книги новий тег зберігається для цього користувача;
* при створенні наступних книг цей тег уже буде доступний в autocomplete.

Приклад:

```text
Перша книга:
користувач додає тег “dark academia”

Наступна книга:
“dark academia” уже з’являється в autocomplete
```

##### Add tag logic

* користувач вводить текст тегу;
* якщо такий тег уже існує серед збережених тегів користувача, він може вибрати його зі списку;
* якщо такого тегу ще немає, користувач може створити новий;
* тег додається після натискання `Enter` або вибору зі списку;
* вибрані теги показуються як chips;
* тег можна прибрати з книги через `x` у chip;
* видалення chip прибирає тег тільки з цієї книги.

##### Custom tag creation

Custom tags створюються тільки після submit всієї форми книги.

##### Flow

1. Користувач вводить новий тег.
2. Тег тимчасово додається у форму як chip.
3. Користувач зберігає книгу.
4. Після submit новий тег зберігається для поточного користувача.
5. Тег стає доступним в autocomplete для наступних книг.

##### Empty states

Якщо користувач ще не створював теги, у dropdown / autocomplete можна показати:

```text
У вас ще немає збережених тегів. Введіть новий тег і натисніть Enter.
```

Якщо теги не вибрані в поточній формі, у правій панелі можна показати:

```text
Теги ще не додані
```

##### Error messages

```text
Тег має містити щонайменше 2 символи
Тег не може бути довшим за 30 символів
Такий тег уже додано
Можна додати не більше 12 тегів
```

* користувач може додати або прибрати теги;
* користувач може змінити вікову категорію;
* користувач може змінити мову книги;

### 7.6. Acceptance Criteria

* Користувач бачить блок **Класифікація** у формі створення / редагування книги.
* Користувач може опційно вибрати один або кілька жанрів.
* Користувач може опційно вибрати існуючий тег або створити custom tag.
* Якщо користувач створює першу книгу і тегів ще немає, він може додати новий тег вручну.
* Нові теги зберігаються для користувача тільки після submit книги.
* Користувач може опційно вибрати вікову категорію.
* Якщо вікова категорія не вибрана, використовується `not_specified`.
* Користувач може опційно вибрати мову книги.
* Якщо мова не вибрана, використовується `ukrainian`.
* Блок **Класифікація** не блокує створення книги, якщо всі його поля порожні.
* Якщо введені невалідні значення, користувач бачить validation errors.
* Жанри й теги можуть оновлювати preview.

## 8. Блок: Статус

### 8.1. Purpose

Блок **“Статус”** потрібен, щоб користувач міг визначити поточний стан книги у своїй бібліотеці.

Цей блок відповідає за:

* статус читання книги;
* додаткові дані, пов’язані з читанням;
* статус володіння книгою;
* додаткові дані, пов’язані з купівлею, доставкою або позикою;
* формат книги;
* появу книги у спеціальних розділах застосунку:

    * **Читаю зараз**;
    * **Книги до покупки**;
    * **Книги в дорозі**;
    * **Позичені книги**;
    * **Статистика**;
    * **Цілі читання**;
    * **Календар читання**.

Блок є важливим для створення книги, бо саме статуси визначають, де книга буде відображатися після збереження.

---

---

### 8.2. UI behavior

Статуси у формі мають відображатися не як dropdown, а як **chip-перемикачі**.

#### Статус читання

* відображається як група chips;
* працює як single-select / radio group;
* користувач може вибрати тільки один статус читання;
* при виборі нового статусу попередній статус автоматично знімається;
* якщо обраний статус читання потребує додаткових даних, під групою відкривається conditional block.

#### Статус володіння

* відображається як група chips;
* працює як single-select / radio group;
* користувач може вибрати тільки один статус володіння;
* якщо обраний статус володіння потребує додаткових даних, під групою відкривається conditional block.

#### Формат книги

* відображається як група chips;
* працює як multi-select;
* користувач може вибрати один або кілька форматів;
* формат не є статусом володіння.

---

### 8.3. Recommended UI order

У формі блок **“Статус”** має йти в такому порядку:

1. **Статус читання**
2. **Conditional block для статусу читання**, якщо він потрібен
3. **Статус володіння**
4. **Conditional block для статусу володіння**, якщо він потрібен
5. **Формат книги**

Це важливо для зручності: користувач обирає статус — і одразу під ним бачить поля, які стосуються саме цього статусу.

### 8.5. Статус читання

| Параметр      | Значення                  |
| ------------- | ------------------------- |
| Label         | Статус читання            |
| Type          | Chip single-select group  |
| Required      | Так                       |
| Default value | `not_started`             |
| Unknown value | Заборонено                |
| Empty value   | Замінити на `not_started` |

#### Purpose

Статус читання показує, на якому етапі читання знаходиться книга.

Це основний статус для читацького прогресу, Dashboard, статистики, цілей читання та календаря.

#### Options

| Value          | Label          | Де використовується                     |
| -------------- | -------------- | --------------------------------------- |
| `not_started`  | Не почато      | дефолт нової книги, фільтри             |
| `want_to_read` | Хочу прочитати | бібліотека, фільтри                     |
| `reading`      | Читаю          | Dashboard “Читаю зараз”, картка, деталі |
| `paused`       | На паузі       | бібліотека, фільтри, деталі             |
| `finished`     | Прочитано      | статистика, цілі читання, календар      |
| `dnf`          | Покинуто       | бібліотека, фільтри                     |
| `rereading`    | Перечитую      | Dashboard, деталі                       |

> Канонічні значення, `tone` та іконки — у `foundation/config/statuses.json` (єдине джерело правди); тут не дублюються.

#### Logic

* поле обов’язкове;
* за замовчуванням нова книга має статус `not_started`;
* користувач може вибрати тільки один статус читання;
* якщо користувач вибирає `reading`, книга має з’явитися у Dashboard-блоці **“Читаю зараз”**;
* якщо користувач вибирає `finished`, книга враховується у статистиці, цілях читання та календарі;
* якщо користувач вибирає `paused`, книга може показуватися у фільтрі **“На паузі”**;
* якщо користувач вибирає `dnf`, книга не рахується як прочитана;
* якщо користувач вибирає `rereading`, книга може вважатися активним читанням.

#### Important note about `want_to_read`

`want_to_read` означає, що користувач хоче прочитати книгу.

Це не те саме, що **Черга читання**.

Книга зі статусом `want_to_read` не має автоматично додаватися в reading queue.
Додавання в чергу має бути окремою дією або окремим checkbox.

#### MVP note

Для MVP можна показувати всі статуси, крім `rereading`, якщо логіка повторного читання ще не готова.

`rereading` можна залишити в config, але тимчасово не показувати в UI.

#### Error message

```text
Оберіть статус читання
```

### 8.6. Conditional blocks для статусу читання

Conditional blocks для статусу читання потрібні, щоб зібрати додаткові дані для прогресу, статистики, цілей читання та календаря.

Ці блоки не мають сильно блокувати створення книги. Більшість полів у них optional.

> Валідацію всіх умовних полів зібрано в зведеній таблиці блоку (підрозділ **Validation** нижче).

---

#### Якщо reading status = `not_started`

Додатковий блок не показується.

##### Logic

* книга зберігається як ще не почата;
* прогрес читання не потрібен;
* дата початку читання не потрібна;
* книга не враховується як активне читання.

---

#### Якщо reading status = `want_to_read`

Додатковий блок не показується.

##### Logic

* книга позначається як та, яку користувач хоче прочитати;
* книга не додається автоматично в чергу читання;
* якщо потрібно додати книгу в чергу, це має бути окремою дією.

---

#### Якщо reading status = `reading`

Показати блок:

```text
Прогрес читання
```

##### Поля

| Поле                 | Type         | Required | Опис                                 |
| -------------------- | ------------ | -------: | ------------------------------------ |
| Поточна сторінка     | Number input |       Ні | Сторінка, на якій зараз користувач   |
| Дата початку читання | Date picker  |       Ні | Коли користувач почав читати книгу   |
| Нотатка до прогресу  | Textarea     |       Ні | Коротка нотатка про поточний прогрес |

##### Logic

* блок показується тільки для `reading`;
* якщо є `pagesCount`, поточна сторінка не може бути більшою за кількість сторінок;
* якщо поточна сторінка дорівнює кількості сторінок, можна запропонувати змінити статус на `finished`;
* якщо дата початку не вибрана, можна залишити поле порожнім або автоматично підставити поточну дату;
* книга з’являється у Dashboard-блоці **“Читаю зараз”**.

##### Logic

* блок показується тільки для `finished`;
* дата прочитання може автоматично ставати поточною датою;
* користувач може змінити дату вручну;
* оцінка не є обов’язковою;
* якщо є `pagesCount`, прогрес можна вважати 100%;

| Empty value   | Замінити на `none`       |

#### Purpose

Статус володіння показує, чи є книга у користувача, чи він хоче її купити, чи книга в дорозі, чи вона позичена.

Цей статус впливає на те, у яких розділах буде показана книга.

#### Options

| Value                   | Label             | Де використовується         |
| ----------------------- | ----------------- | --------------------------- |
| `none`                  | Немає             | дефолт, фільтри             |
| `want_to_buy`           | Хочу купити       | сторінка “Книги до покупки” |
| `in_transit`            | В дорозі          | сторінка “Книги в дорозі”   |
| `owned`                 | Маю               | бібліотека, деталі          |
| `borrowed_from_someone` | Позичена у когось | сторінка “Позичені книги”   |
| `lent_to_someone`       | Видана комусь     | сторінка “Позичені книги”   |

> Канонічні значення, `tone` та іконки — у `foundation/config/statuses.json` (єдине джерело правди); тут не дублюються.

#### Important naming

Для статусу **“В дорозі”** в основному статусі володіння потрібно використовувати:

```text
in_transit
```

Не використовувати `ordered` як ownership status.

`ordered` має залишатися тільки всередині delivery status і означати **“Замовлено”**.

#### Logic

* поле обов’язкове;
* за замовчуванням нова книга має статус `none`;
* користувач може вибрати тільки один статус володіння;
* якщо вибрано `want_to_buy`, книга з’являється у розділі **“Книги до покупки”**;
* якщо вибрано `in_transit`, книга з’являється у розділі **“Книги в дорозі”**;
* якщо вибрано `owned`, книга показується як книга, що є у користувача;
* якщо вибрано `borrowed_from_someone`, книга з’являється у розділі **“Позичені книги”** як книга, яку користувач позичив у когось;
* якщо вибрано `lent_to_someone`, книга з’являється у розділі **“Позичені книги”** як книга, яку користувач дав комусь.

### 8.10. Conditional data behavior

#### Create mode

Якщо користувач заповнив conditional block, а потім змінив статус на інший, попередній conditional block приховується.

У create mode дані прихованого conditional block не потрібно відправляти при submit, якщо вони більше не відповідають активному статусу.

#### Приклад

1. Користувач вибрав `finished`.
2. Заповнив дату прочитання й оцінку.
3. Потім змінив статус читання на `reading`.
4. Блок **“Завершення”** приховується.
5. При submit дані з блоку **“Завершення”** не відправляються.

---

#### Edit mode

В edit mode потрібно бути обережнішим, бо conditional data може вже бути збережена.

Якщо користувач змінює статус так, що поточний conditional block більше неактуальний, потрібно показати confirmation modal.

#### Confirmation modal

```text
Title: Змінити статус?

Description:
Поточні дані, пов’язані з попереднім статусом, можуть бути очищені або більше не відображатися після зміни статусу.

Actions:
- Скасувати
- Змінити статус
```

#### Recommended behavior

* не очищати conditional data автоматично без підтвердження;
* якщо користувач підтвердив зміну, новий статус застосовується;
* попередній conditional block приховується;
* для MVP можна очищати неактуальні conditional data після підтвердження.

### 8.13. Block-specific behavior

#### Create mode

У create mode:

* `readingStatus` має default `not_started`;
* reading conditional blocks не показуються, поки користувач не вибере статус, який потребує додаткових полів;
* `ownershipStatus` має default `none`;
* ownership conditional blocks не показуються, поки користувач не вибере відповідний ownership status;
* `formats` відкривається порожнім;
* якщо користувач змінив статус, попередній conditional block приховується;
* у submit потрапляють тільки дані активних conditional blocks.

#### Edit mode

У edit mode:

* усі статуси відкриваються з поточними значеннями книги;
* користувач може змінити reading status;
* користувач може змінити ownership status;
* користувач може змінити формати;
* якщо зміна статусу приховує conditional block, потрібно показати confirmation modal;
* не очищати conditional data автоматично без підтвердження;
* якщо користувач переводить книгу з `in_transit` у `owned`, книга має зникнути з розділу **“Книги в дорозі”**;
* якщо користувач переводить позику в `returned`, книга має перестати бути активною у списку позичених.

### 8.15. Acceptance Criteria

* Користувач бачить блок **Статус** у формі створення / редагування книги.
* Статус читання показується як chip single-select group.
* Користувач може вибрати тільки один статус читання.
* Якщо статус читання не вибраний, використовується `not_started`.
* Якщо вибрано `reading`, показується блок **Прогрес читання**.
* Якщо вибрано `finished`, показується блок **Завершення**.
* Якщо вибрано `paused`, показується блок **Пауза в читанні**.
* Якщо вибрано `dnf`, показується блок **Покинуто**.
* Якщо вибрано `not_started` або `want_to_read`, reading conditional block не показується.
* Статус володіння показується як chip single-select group.
* Користувач може вибрати тільки один статус володіння.
* Якщо статус володіння не вибраний, використовується `none`.
* Формат книги показується як chip multi-select group.
* Користувач може вибрати один або кілька форматів книги.
* Якщо формат не вибраний, книга зберігається без формату.
* Якщо вибрано `want_to_buy`, показується блок **Інформація про купівлю**.
* Якщо вибрано `in_transit`, показується блок **Інформація про доставку**.
* Якщо вибрано `borrowed_from_someone`, показується блок **Позичена у когось**.
* Якщо вибрано `lent_to_someone`, показується блок **Видана комусь**.
* Якщо статус змінено в create mode, неактивний conditional block приховується і не відправляється при submit.
* Якщо статус змінено в edit mode і є збережені conditional data, показується confirmation modal.
* Якщо вибрано `reading`, книга з’являється у Dashboard-блоці **Читаю зараз**.
* Якщо вибрано `finished`, книга враховується у статистиці та reading goals.
* Якщо вибрано `want_to_buy`, книга з’являється на сторінці **Книги до покупки**.
* Якщо вибрано `in_transit`, книга з’являється на сторінці **Книги в дорозі**.
* Якщо вибрано `borrowed_from_someone` або `lent_to_someone`, книга з’являється на сторінці **Позичені книги**.
* `want_to_read` не додає книгу автоматично в чергу читання.
* Delivery due statuses не показуються як ручний select.
* Loan due statuses не показуються як ручний select.
* `received` не показується як delivery status, а працює як action.
* `isFavorite` не належить до статусів і керується окремим favorite toggle.
* Status badges у preview оновлюються після зміни значень.
* У create mode блок відкривається з default значеннями.
* У edit mode блок відкривається з поточними значеннями книги.
* Якщо введені невалідні значення, користувач бачить validation errors.

## 9. Блок: Тип книги

### 9.1. Purpose

Блок **“Тип книги”** потрібен, щоб користувач міг вказати, чи є книга самостійною книгою, чи частиною книжкової серії.

Цей блок відповідає за:

* прив’язку книги до серії;
* номер частини у серії;
* статус серії;
* загальну кількість книг у серії;
* появу книги на сторінці деталей серії;
* правильний порядок книг усередині серії;
* перерахунок прогресу серії.

---

### 9.2. UI behavior

### 9.4. Тип книги

#### Options

| Value         | Label         | Опис                       |
| ------------- | ------------- | -------------------------- |
| `solo`        | Соло книга    | Книга не належить до серії |
| `series_part` | Частина серії | Книга є частиною серії     |

#### Logic

* за замовчуванням обрано **Соло книга**;
* якщо обрано **Соло книга**, поля серії приховані;
* якщо обрано **Частина серії**, відкриваються поля серії;
* якщо користувач перемикається з **Частина серії** назад на **Соло книга**, поля серії приховуються;
* у create mode дані прихованого блоку серії не відправляються при submit;
* у edit mode, якщо книга вже була прив’язана до серії, при зміні на **Соло книга** потрібно показати confirmation modal.

### 9.5. Назва серії

#### Data source

Поле має шукати серії з таких джерел:

* реальна серія створюється тільки після submit всієї форми книги.

### 9.6. Modal “Створити серію”

Вона має створити тільки тимчасовий draft series у формі.

* користувач заповнює дані серії;
* після натискання **Створити серію** modal закривається;
* нова серія підставляється в поле **Назва серії**;
* фокус бажано перевести на поле **Номер частини**;
* серія ще не створюється в базі;
* серія буде створена тільки після submit всієї форми книги.

---

### 9.7. Варіант створення серії

Для MVP використовується варіант:

```text
Серія створюється тільки після submit книги.
```

#### Чому так

Це потрібно, щоб не створювати порожні серії, якщо користувач:

* відкрив modal;
* ввів назву серії;
* натиснув “Створити серію”;
* але потім скасував створення книги.

У такому випадку в базі не має залишитися зайва серія без книг.

---

#### Submit flow для нової серії

Якщо користувач створив нову серію через modal і потім натиснув **Зберегти книгу**, submit має працювати так:

1. Validate form.
2. Validate series block.
3. Якщо серія нова — створити серію.
4. Отримати ID створеної серії.
5. Створити книгу.
6. Прив’язати книгу до створеної серії.
7. Присвоїти книзі номер частини.
8. Додати книгу на сторінку деталей серії.
9. Перерахувати прогрес серії.
10. Показати success toast.
11. Перейти на детальну сторінку книги.

---

#### Submit flow для існуючої серії

Якщо користувач вибрав уже існуючу серію:

1. Validate form.
2. Validate series block.
3. Створити або оновити книгу.
4. Прив’язати книгу до вибраної серії.
5. Присвоїти книзі номер частини.
6. Додати книгу на сторінку деталей серії.
7. Перерахувати прогрес серії.
8. Показати success toast.

---

### 9.8. Номер частини

| Параметр    | Значення                         |
| ----------- | -------------------------------- |
| Label       | Номер частини                    |
| Placeholder | Наприклад: 1                     |
| Type        | Number input                     |
| Required    | Так, якщо книга є частиною серії |

#### Logic

* поле показується тільки якщо вибрано **Частина серії**;
* визначає порядок книги в серії;
* після збереження книга має відображатися на сторінці серії відповідно до номера частини;
* якщо дві книги мають однаковий номер частини, потрібно показати warning або validation error.

#### Error messages

```text
Вкажіть номер частини
Номер частини має бути цілим числом
Номер частини має бути від 1 до 999
Книга з таким номером частини вже є в цій серії
```

### 9.9. Block-specific behavior

#### Create mode

У create mode:

* за замовчуванням вибрано **Соло книга**;
* якщо вибрано **Соло книга**, поля серії приховані;
* якщо вибрано **Частина серії**, поля серії відкриваються;
* користувач може вибрати існуючу серію;
* користувач може створити нову серію через modal;
* нова серія з modal тимчасово підставляється у форму;
* реальна серія створюється тільки після submit книги;
* якщо користувач скасував створення книги, draft series не зберігається.

#### Edit mode

У edit mode:

* якщо книга вже є частиною серії, блок відкривається з поточними значеннями;
* користувач може змінити серію;
* користувач може змінити номер частини;
* користувач може прибрати книгу з серії, переключивши на **Соло книга**;
* якщо користувач прибирає книгу з серії, потрібно показати confirmation modal;
* після зміни серії прогрес старої та нової серії має бути перерахований.

---

### 9.10. Conditional data behavior

#### Якщо користувач перемикається з “Частина серії” на “Соло книга”

У create mode:

* поля серії приховуються;
* дані серії не відправляються при submit;
* якщо була створена draft series через modal, вона не зберігається.

У edit mode:

* потрібно показати confirmation modal.

##### Confirmation modal

```text
Title: Прибрати книгу з серії?

Description:
Книга більше не буде відображатися на сторінці цієї серії. Номер частини та зв’язок із серією буде очищено.

Actions:
- Скасувати
- Прибрати з серії
```

### 9.12. Acceptance Criteria

* Користувач бачить блок **Серія** у формі створення / редагування книги.
* За замовчуванням книга створюється як **Соло книга**.
* Користувач може перемкнути тип книги на **Частина серії**.
* Якщо вибрано **Частина серії**, відкриваються поля серії.
* Користувач може вибрати існуючу серію.
* Якщо потрібної серії немає, користувач може відкрити modal **“Створити серію”**.
* Modal **“Створити серію”** містить назву серії, статус серії, загальну кількість книг, опис і обкладинку.
* Modal **“Створити серію”** не створює серію в базі одразу.
* Нова серія з modal тимчасово підставляється у форму книги.
* Реальна серія створюється тільки після submit книги.
* Якщо користувач скасував створення книги, draft series не зберігається.
* Користувач має вказати номер частини, якщо книга є частиною серії.
* Книга після збереження з’являється на сторінці деталей серії.
* Книга сортується в серії за номером частини.
* Прогрес серії перераховується після додавання книги.
* Якщо користувач перемикає книгу на **Соло книга** в edit mode, показується confirmation modal.
* Якщо введені невалідні значення, користувач бачить validation errors.

## 10. Блок: Деталі видання

### 10.1. Purpose

Блок **“Деталі видання”** потрібен, щоб користувач міг додати технічну інформацію саме про конкретне видання книги.

Цей блок не описує читацький статус, прогрес, серію або нотатки.
Він зберігає інформацію про саме видання:

* оригінальну назву;
* присвяту
* кількість сторінок;
* рік видання;
* ISBN;
* перекладача;
* ілюстратора.

Ці дані допомагають:

* точніше описати книгу;
* відрізняти різні видання однієї книги;
* правильно рахувати прогрес читання;
* показувати повнішу інформацію на сторінці деталей книги;
* покращити фільтрацію та пошук у бібліотеці.

---

### 10.2. Fields overview

| Поле               | Type                      | Required | Validation                         | Де використовується         |
| ------------------ | ------------------------- | -------: | ---------------------------------- | --------------------------- |
| Присвята           | Textarea                  | Ні       | max 300 символів                   | деталі книги                |
| Кількість сторінок | Number input              |       Ні | integer, min 1, max 10000          | прогрес читання, статистика |
| Рік видання        | Number input              |       Ні | 4 digits, не більше поточного року | деталі книги, фільтри       |
| ISBN               | Text input                |       Ні | ISBN-10 або ISBN-13                | пошук, дублікати, деталі    |
| Оригінальна назва  | Text input                |       Ні | max 200 символів                   | деталі книги                |
| Перекладач         | Text input / Autocomplete |       Ні | max 100 символів                   | деталі книги                |
| Ілюстратор         | Text input / Autocomplete |       Ні | max 100 символів                   | деталі книги                |

### 10.3. Кількість сторінок

| Параметр    | Значення           |
| ----------- | ------------------ |
| Label       | Кількість сторінок |
| Placeholder | Наприклад: 528     |
| Type        | Number input       |
| Required    | Ні                 |

#### Purpose

Поле показує, скільки сторінок має конкретне видання книги.

Це важливо для:

* розрахунку прогресу читання;
* перевірки поля **Поточна сторінка**;
* статистики прочитаних сторінок;
* reading goals;
* reading calendar.

#### Logic

* поле необов’язкове;
* якщо кількість сторінок вказана, вона використовується для validation прогресу;
* якщо кількість сторінок не вказана, прогрес можна вести без обмеження по максимальній сторінці;
* якщо книга має статус `finished`, прогрес може вважатися 100%;
* якщо користувач вводить поточну сторінку в блоці **Статус**, вона не може бути більшою за кількість сторінок.

```text
Кількість сторінок не може бути більшою за 10000
```

### 10.14. Acceptance Criteria

* Користувач бачить блок **Деталі видання** у формі створення / редагування книги.
* Блок **Деталі видання** не є обов’язковим.
* Користувач може вказати кількість сторінок.
* Користувач може залишити кількість сторінок порожньою.
* Якщо кількість сторінок вказана, вона має бути цілим числом більше 0.
* Користувач може вказати рік видання.
* Якщо рік видання вказаний, він має бути валідним роком.
* Користувач може вказати ISBN.
* Якщо ISBN вказаний, він має бути валідним ISBN-10 або ISBN-13.
* Користувач може вказати оригінальну назву.
* Користувач може вказати перекладача.
* Користувач може вказати ілюстратора.
* Користувач може створити книгу, не заповнюючи цей блок.
* У create mode поля відкриваються порожніми.
* У edit mode поля відкриваються з поточними значеннями книги.
* Якщо введені невалідні значення, користувач бачить validation errors.
* Якщо кількість сторінок змінена так, що поточний прогрес стає невалідним, користувач бачить warning або validation error.
* Поля блоку **Деталі видання** показуються на сторінці деталей книги, якщо вони заповнені.

## 11. Блок: Організація в бібліотеці

### 11.1. Purpose

Блок **“Організація в бібліотеці”** потрібен, щоб користувач міг одразу визначити, як книга має бути розміщена всередині його особистої бібліотеки.

Цей блок не описує саму книгу і не змінює її статус читання або володіння.
Він відповідає за організаційні дії:

* додати книгу в улюблені;
* додати книгу в чергу читання;
* вибрати пріоритет у черзі;
* додати книгу до одного або кількох власних списків;
* створити новий список прямо під час створення книги.

---

### 11.2. UI behavior

Блок має бути необов’язковим.

Користувач може створити книгу, не заповнюючи жодного поля цього блоку.

Рекомендований порядок елементів:

```text id="k1les6"
Організація в бібліотеці

[ ] Додати в улюблені

[ ] Додати в чергу читання
    → Пріоритет у черзі

Додати до списків
[ multi-select списків ]

+ Створити новий список
```

---

| ---------------------- | --------------------------------- | -------: | ------------------------------- | ------------------------------------------------ |

| Додати до списків      | Multi-select                      |       Ні | Завжди                          | Додає книгу до власних списків                   |

### 11.4. Додати в улюблені

| Параметр      | Значення          |
| ------------- | ----------------- |
| Label         | Додати в улюблені |
| Type          | Checkbox / Switch |
| Required      | Ні                |
| Default value | `false`           |

#### Purpose

Поле **“Додати в улюблені”** дозволяє користувачу одразу позначити книгу як улюблену під час створення або редагування.

Це окрема дія, яка не належить до статусів книги.

#### Logic

* за замовчуванням вимкнено;
* якщо користувач увімкнув це поле, книга після збереження з’являється у розділі **“Улюблені книги”**;
* якщо поле вимкнено, книга не потрапляє в улюблені;
* це поле не змінює `readingStatus`;
* це поле не змінює `ownershipStatus`;
* це поле не залежить від статусу читання.

#### Data

```ts id="n4uq6a"
isFavorite: boolean
```

#### Acceptance Criteria

* Користувач може позначити книгу як улюблену під час створення.
* Користувач може не позначати книгу як улюблену.
* Якщо книга позначена як улюблена, вона з’являється у розділі **Улюблені книги**.
* Якщо користувач вимикає це поле в edit mode, книга зникає з розділу **Улюблені книги**.

---

### 11.5. Додати в чергу читання

| Параметр      | Значення               |
| ------------- | ---------------------- |
| Label         | Додати в чергу читання |
| Type          | Checkbox / Switch      |
| Required      | Ні                     |
| Default value | `false`                |

#### Purpose

Поле **“Додати в чергу читання”** дозволяє користувачу одразу додати книгу до reading queue.

Це окрема дія і вона не повинна автоматично вмикатися через статус `want_to_read`.

#### Important note

`want_to_read` і **Черга читання** — це різні речі.

```text id="7eulqf"
want_to_read = користувач хоче прочитати книгу
reading queue = користувач поставив книгу в конкретну чергу читання
```

Тому якщо користувач вибрав статус **“Хочу прочитати”**, книга не має автоматично додаватися в чергу.

#### Logic

* за замовчуванням вимкнено;
* якщо користувач увімкнув поле, після submit книга додається в **Чергу читання**;
* якщо користувач вимкнув поле, книга не додається в чергу;
* якщо книга вже є в черзі, повторно її додавати не потрібно;
* книга в черзі має отримати позицію;
* за замовчуванням нова книга додається в кінець черги;
* порядок у черзі можна змінити пізніше на сторінці **Черга читання**.

#### Data

```ts id="j5dqds"
addToReadingQueue: boolean
```

#### Recommended behavior

Якщо користувач додає книгу в чергу, але книга має статус `finished` або `dnf`, можна показати легкий warning, але не обов’язково блокувати дію.

Приклад:

```text id="2s8nfw"
Ця книга вже має статус “Прочитано”. Ви все одно можете додати її в чергу для перечитування.
```

### 11.6. Пріоритет у черзі

| Параметр        | Значення                                       |
| --------------- | ---------------------------------------------- |
| Label           | Пріоритет у черзі                              |
| Type            | Chip single-select group / Select              |
| Required        | Ні                                             |
| Default value   | `normal`                                       |
| Коли показувати | Тільки якщо увімкнено “Додати в чергу читання” |

#### Purpose

Поле **“Пріоритет у черзі”** дозволяє користувачу визначити, наскільки важливо прочитати цю книгу найближчим часом.

#### Options

| Value    | Label     | Опис                                      |
| -------- | --------- | ----------------------------------------- |
| `low`    | Низький   | Книга не термінова                        |
| `normal` | Звичайний | Стандартний пріоритет                     |
| `high`   | Високий   | Книгу хочеться прочитати найближчим часом |

> Канонічні значення та `tone` — у `foundation/config/statuses.json` (єдине джерело правди); тут не дублюються.

#### Logic

* поле показується тільки якщо `addToReadingQueue = true`;
* якщо користувач не вибрав пріоритет, використовується `normal`;
* якщо користувач вимикає **“Додати в чергу читання”**, пріоритет не відправляється при submit;
* пріоритет не змінює порядок автоматично, якщо в застосунку використовується ручний drag-and-drop порядок;
* пріоритет можна показувати як badge на сторінці **Черга читання**.

#### Data

```ts id="qgkwu3"
queuePriority: 'low' | 'normal' | 'high'
```

### 11.7. Додати до списків

#### Purpose

Поле **“Додати до списків”** дозволяє користувачу одразу додати книгу до одного або кількох власних списків.

Приклади списків:

* “Книги для осені”;
* “Фентезі, яке хочу прочитати”;
* “Подарунки”;
* “Улюблені світи”;
* “Книги від блогерів”.

#### Data source

Поле має показувати тільки списки поточного користувача.

Джерела:

* уже створені власні списки користувача;

* поле необов’язкове;
* користувач може вибрати один або кілька списків;

* після submit книга додається до вибраних списків;
* якщо користувач скасував створення книги, нові draft lists не зберігаються.

### 11.8. Modal “Створити новий список”

Modal **“Створити новий список”** потрібна, щоб користувач міг створити власний список прямо під час створення книги.

Modal не має одразу створювати список у базі.
Вона має створити тільки тимчасовий draft list у формі.

Реальний список створюється тільки після submit книги.

---

#### Поля modal

| Поле         | Type       | Required | Опис                 |
| ------------ | ---------- | -------: | -------------------- |
| Назва списку | Text input |      Так | Назва нового списку  |
| Опис списку  | Textarea   |       Ні | Короткий опис списку |

---

#### Кнопки modal

```text id="864ubi"
Скасувати
Створити список
```

---

#### Logic

* користувач натискає **Створити новий список**;
* відкривається modal;
* користувач вводить назву списку;
* після натискання **Створити список** modal закривається;
* новий список тимчасово додається у multi-select;
* новий список одразу вибирається для цієї книги;
* реальний список створюється тільки після submit книги;
* якщо користувач скасував створення книги, draft list не зберігається.

---

### 11.9. Варіант створення нових списків

Для MVP використовується варіант:

```text id="vju5su"
Нові списки створюються тільки після submit книги.
```

#### Чому так

Це потрібно, щоб не створювати порожні списки, якщо користувач:

* відкрив modal;
* ввів назву списку;
* натиснув **Створити список**;
* але потім скасував створення книги.

У такому випадку в базі не має залишитися зайвий список без книг.

---

#### Submit flow для нового списку

Якщо користувач створив новий список через modal і потім натиснув **Зберегти книгу**, submit має працювати так:

1. Validate form.
2. Validate organization block.
3. Створити книгу.
4. Якщо є нові draft lists — створити ці списки.
5. Отримати ID створених списків.
6. Додати книгу до вибраних існуючих списків.
7. Додати книгу до нових створених списків.
8. Показати success toast.
9. Перейти на детальну сторінку книги.

---

#### Submit flow для існуючих списків

Якщо користувач вибрав тільки існуючі списки:

1. Validate form.
2. Validate organization block.
3. Створити або оновити книгу.
4. Додати книгу до вибраних списків.
5. Показати success toast.

---

### 11.10. Conditional data behavior

#### Якщо користувач вимикає “Додати в чергу читання”

У create mode:

* поле **Пріоритет у черзі** приховується;
* `queuePriority` не відправляється при submit;
* книга не додається в чергу.

У edit mode:

* якщо книга вже була в черзі, потрібно показати confirmation modal.

##### Confirmation modal

```text id="0kchyu"
Title: Прибрати книгу з черги?

Description:
Книга більше не буде відображатися у вашій черзі читання. Її можна буде додати знову пізніше.

Actions:
- Скасувати
- Прибрати з черги
```

---

#### Якщо користувач прибирає список з multi-select

У create mode:

* книга просто не буде додана до цього списку після submit.

У edit mode:

* якщо книга вже була в цьому списку, можна прибрати її без modal;
* для MVP confirmation modal не обов’язкова;
* після збереження книга має зникнути з цього списку.

---

### 11.11. Normalization before submit

Перед submit потрібно нормалізувати значення блоку:

```ts id="vr5o78"
isFavorite = Boolean(isFavorite);

addToReadingQueue = Boolean(addToReadingQueue);

queuePriority = addToReadingQueue
  ? queuePriority || 'normal'
  : null;

selectedListIds = unique(selectedListIds);

draftLists = draftLists.map((list) => ({
  title: list.title.trim(),
  description: list.description?.trim() || null,
```

### 11.12. Block-specific behavior

#### Create mode

У create mode:

* `isFavorite` має default `false`;
* `addToReadingQueue` має default `false`;
* `queuePriority` прихований, поки не ввімкнено **“Додати в чергу читання”**;
* список власних списків завантажується для поточного користувача;
* користувач може вибрати існуючі списки;
* користувач може створити новий draft list через modal;
* новий draft list не створюється в базі до submit книги;
* якщо користувач скасував створення книги, draft list не зберігається.

#### Edit mode

У edit mode:

* `isFavorite` відкривається з поточним значенням книги;
* якщо книга вже є в черзі, checkbox **“Додати в чергу читання”** має бути увімкнений;
* якщо книга вже має пріоритет у черзі, він має бути вибраний;
* якщо книга вже належить до списків, ці списки мають бути вибрані в multi-select;
* користувач може прибрати книгу з улюблених;
* користувач може прибрати книгу з черги;
* користувач може додати або прибрати книгу зі списків;
* після зміни списків сторінки відповідних списків мають оновитися.

* badge **“У черзі”**, якщо книга додана в reading queue.

### 11.15. Acceptance Criteria

* Користувач бачить блок **Організація в бібліотеці** у формі створення / редагування книги.
* Блок є необов’язковим.
* Користувач може створити книгу, не заповнюючи цей блок.
* Користувач може позначити книгу як улюблену.
* Якщо книга позначена як улюблена, вона з’являється у розділі **Улюблені книги**.
* Користувач може додати книгу в чергу читання.
* Якщо книга додана в чергу, вона з’являється на сторінці **Черга читання**.
* `want_to_read` не додає книгу в чергу автоматично.
* Якщо увімкнено **Додати в чергу читання**, користувач може вибрати пріоритет.
* Якщо пріоритет не вибраний, використовується `normal`.
* Якщо **Додати в чергу читання** вимкнено, `queuePriority` не відправляється при submit.
* Користувач може додати книгу до одного або кількох власних списків.
* Користувач не може додати книгу в один список двічі.
* Користувач може створити новий список через modal.
* Новий список з modal не створюється в базі одразу.
* Новий список створюється тільки після submit книги.
* Якщо користувач скасував створення книги, draft list не зберігається.
* У create mode поля відкриваються з default значеннями.
* У edit mode поля відкриваються з поточними значеннями книги.
* Якщо книга вже є в черзі, checkbox **Додати в чергу читання** відкривається увімкненим.
* Якщо книга вже належить до списків, ці списки вибрані в multi-select.
* Якщо користувач прибирає книгу з черги в edit mode, показується confirmation modal.
* Якщо введені невалідні значення, користувач бачить validation errors.

## 12. Блок: Обкладинка книги

### 12.1. Purpose

Блок **“Обкладинка книги”** потрібен, щоб користувач міг додати зображення обкладинки під час створення або редагування книги.

Обкладинка допомагає:

* візуально впізнавати книгу в бібліотеці;
* зробити картки книг більш живими;
* покращити сторінку деталей книги;
* використовувати красивий preview у формі створення книги.

Обкладинка не є обов’язковим полем.
Користувач може створити книгу без обкладинки.

---

### 12.2. Recommended cover format

Обкладинка книги має бути вертикальною.

Рекомендований формат:

```text id="sppeh5"
Aspect ratio: 2:3
```

Приклади рекомендованих розмірів:

| Розмір           | Коментар                            |
| ---------------- | ----------------------------------- |
| `600 × 900 px`   | Мінімальний хороший варіант         |
| `800 × 1200 px`  | Рекомендований варіант              |
| `1000 × 1500 px` | Якісний варіант для великих екранів |

Приклад, як на реальній книжковій обкладинці:

```text id="3lrt32"
Вертикальне зображення
Ширина менша за висоту
Формат приблизно 2:3
```

---

### 12.3. UI behavior

Блок може бути розміщений:

* у правій preview-панелі форми;
* або як окремий upload-блок наприкінці форми.

Рекомендований варіант для твоєї форми:

```text id="knkc5s"
Праворуч:
- preview обкладинки
- upload area
```

Якщо обкладинка вже вибрана, показати дію:

```text id="zyakzs"

```

#### Create mode

У create mode:

* обкладинка просто прибирається з форми;
* файл не завантажується;
* книга створюється без обкладинки.

#### Edit mode

У edit mode:

* якщо книга вже мала обкладинку, після натискання **Видалити обкладинку** потрібно показати confirmation modal або позначити обкладинку як “буде видалена після збереження”.

```text id="b5r9zr"
- Скасувати
- Видалити
```

### 12.12. Upload flow

#### Create mode

У create mode обкладинка не має завантажуватися в storage одразу після вибору.

Рекомендована логіка:

1. Користувач вибирає файл.
2. Файл показується у preview.
3. Файл тимчасово зберігається у стані форми.
4. Користувач натискає **Створити книгу**.
5. Форма проходить validation.
6. Створюється книга.
7. Обкладинка завантажується в storage.
8. URL обкладинки зберігається у книзі.
9. Користувач переходить на сторінку деталей книги.

#### Чому не завантажувати одразу

Це потрібно, щоб не створювати зайві файли, якщо користувач:

* вибрав обкладинку;
* заповнив форму;
* але потім скасував створення книги.

---

#### Edit mode

У edit mode:

1. Користувач бачить поточну обкладинку.
2. Користувач може замінити або видалити її.
3. Нова обкладинка показується у preview.
4. Реальна заміна відбувається тільки після submit.
5. Якщо submit скасовано або є помилки, стара обкладинка залишається без змін.

### 12.19. Acceptance Criteria

* Користувач бачить можливість завантажити обкладинку книги.
* Обкладинка книги не є обов’язковою.
* Користувач може створити книгу без обкладинки.
* Користувач може завантажити JPG, JPEG, PNG або WEBP файл.
* Користувач не може завантажити файл більш ніж 5 MB.
* Користувач бачить preview обкладинки перед submit.
* Якщо зображення не вертикальне, користувач бачить warning.
* Якщо файл має неправильний формат, користувач бачить validation error.
* Якщо файл пошкоджений, користувач бачить validation error.
* У create mode файл не завантажується в storage до submit книги.
* Якщо користувач скасував створення книги, файл не зберігається.
* У edit mode стара обкладинка не замінюється до submit.
* Користувач може замінити обкладинку.
* Користувач може видалити обкладинку.
* Якщо обкладинка видалена, показується fallback placeholder.
* Якщо обкладинка не додана, у бібліотеці показується fallback placeholder.
* Alt text для обкладинки генерується автоматично.

## 13. Final Acceptance Criteria

* Користувач може створити книгу через форму Create Book.
* Користувач може редагувати книгу через форму Edit Book.
* У create mode форма відкривається з порожніми або default значеннями.
* У edit mode форма відкривається з поточними значеннями книги.
* Required поля мають бути заповнені перед submit.
* Optional поля можна залишити порожніми.
* Custom author, publisher і tags створюються тільки після submit.
* Для custom значень виконується duplicate check.
* Текстові значення нормалізуються перед збереженням.
* Невалідні значення не зберігаються.
* Користувач бачить зрозумілі validation errors.
* Preview оновлюється під час заповнення ключових полів.
* Книга не створюється і не оновлюється, якщо є validation errors.
