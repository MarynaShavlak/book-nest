# Feature: Моя бібліотека

## 1. Purpose

Сторінка **“Моя бібліотека”** — це головний центр керування всіма книгами користувача в BookNest.

На цій сторінці користувач має бачити всю свою книжкову колекцію в одному місці, швидко знаходити потрібну книгу, фільтрувати бібліотеку, змінювати вигляд списку та переходити до детальної сторінки книги.

Це одна з основних сторінок застосунку, бо саме з неї користувач найчастіше буде взаємодіяти зі своєю бібліотекою.

---

### 1.1. What this feature allows users to do

Користувач може:

* переглядати всі книги, які він додав у BookNest;
* бачити книги незалежно від їхнього статусу читання або володіння;
* швидко знаходити книгу через пошук;
* фільтрувати книги за статусами, жанрами, тегами, авторами, форматами та іншими параметрами;
* сортувати бібліотеку;
* перемикати вигляд між grid view та list view;
* бачити ключову інформацію про книгу прямо на картці або в рядку списку;
* переходити до детальної сторінки книги;
* додавати нову книгу;
* виконувати швидкі дії з книгою, якщо вони доступні.

---

### 1.2. Why this feature is important

**Моя бібліотека** є базовою сторінкою для всієї роботи з BookNest.

Вона потрібна, щоб користувач міг:

* не губитися у великій кількості книг;
* швидко розуміти, що він читає зараз;
* бачити, які книги вже прочитані;
* знаходити книги, які хоче прочитати або купити;
* керувати книгами в дорозі, позиченими або виданими комусь;
* повертатися до деталей конкретної книги;
* підтримувати свою бібліотеку в актуальному стані.

---

### 1.3. What books are included

На сторінці **“Моя бібліотека”** мають відображатися всі активні книги поточного користувача.

Книга потрапляє в бібліотеку після:

* створення вручну;
* імпорту;
* додавання через інший сценарій застосунку, якщо в майбутньому такий буде.

Книга має відображатися в бібліотеці незалежно від:

* статусу читання;
* статусу володіння;
* формату;
* наявності обкладинки;
* наявності серії;
* наявності жанрів або тегів;
* наявності рейтингу;
* наявності прогресу читання.

---

## 2. Page entry point

Сторінка **“Моя бібліотека”** має бути доступна з основної навігації застосунку.

Це одна з головних сторінок BookNest, тому користувач має легко знаходити її одразу після входу в застосунок.

---

### 2.1. Sidebar navigation

У sidebar має бути пункт меню:

```text
Моя бібліотека
```

Рекомендована позиція в sidebar:

```text
Головна
Моя бібліотека
Серії
Черга читання
Списки
Книги до покупки
Улюблені
Нотатки
Цитати
Статистика
Налаштування
```

Пункт **“Моя бібліотека”** має бути одним із верхніх пунктів меню, бо це основний робочий розділ застосунку.

---

### 2.2. Route

Рекомендований route:

```text
/library
```

Альтернативні варіанти:

```text
/books
/my-library
```

Рекомендований варіант для BookNest:

```text
/library
```

Причина: цей route короткий, зрозумілий і добре підходить для сторінки всієї бібліотеки користувача.

---

### 2.3. Page access rules

Сторінка доступна тільки авторизованому користувачу.

Якщо користувач не авторизований:

* він не має бачити сторінку бібліотеки;
* його потрібно перенаправити на login page;
* після успішного login можна повернути його назад на `/library`.

---

### 2.4. User scope

Користувач має бачити тільки свої книги.

На сторінці не мають відображатися:

* книги інших користувачів;
* видалені книги;
* чужі списки;
* чужі серії;
* чужі теги;
* чужі авторські custom-дані.

Усі запити для цієї сторінки мають бути обмежені поточним користувачем.

---


### 2.5. Header action entry point

На сторінці **“Моя бібліотека”** у header має бути основна дія:

```text
+ Додати книгу
```

Після натискання користувач переходить на сторінку створення книги:

```text
/books/create
```

або відкриває форму створення книги, якщо в застосунку використовується modal / drawer flow.

Рекомендований варіант для повної версії:

```text
/books/create
```

Причина: форма створення книги велика, має багато блоків і краще працює як окрема сторінка, а не як маленька modal.

---


### 2.6. URL behavior

Сторінка має підтримувати query params для фільтрів, пошуку, сортування та pagination.


Це потрібно, щоб:

* користувач міг оновити сторінку і не втратити фільтри;
* можна було повертатися назад через browser history;
* посилання на відфільтровану бібліотеку було стабільним;
* frontend і backend мали передбачувану логіку запитів.

---

### 2.7. Acceptance Criteria

* У sidebar є пункт **Моя бібліотека**.
* Пункт **Моя бібліотека** веде на сторінку `/library`.
* Сторінка доступна тільки авторизованому користувачу.
* Неавторизований користувач не може відкрити сторінку бібліотеки.
* Користувач бачить тільки свої книги.
* Книги інших користувачів не відображаються.
* Видалені книги не відображаються за замовчуванням.
* На сторінці є header action **+ Додати книгу**.
* Натискання **+ Додати книгу** веде до створення книги.
* Сторінка підтримує URL query params для пошуку, фільтрів, сортування та pagination.
* Після оновлення сторінки активні query params не мають втрачатися.


```text

```

* У header є кнопка **+ Додати книгу**.
* Кнопка веде на сторінку створення книги.
* Під header показуються summary cards.
* Summary cards показують: усього книг, читаю, прочитано, улюблених.
* Summary cards є інформаційними.
* Summary cards не є клікабельними.
* Summary cards рахують тільки книги поточного користувача.
* Видалені книги не враховуються в summary cards.


## 4. Library toolbar

Toolbar сторінки **“Моя бібліотека”** — це верхня панель керування списком книг.

Вона розташована під page header і над списком книг.

---

### 4.1. Purpose

Toolbar потрібен, щоб користувач міг швидко:

* знайти книгу;
* відкрити фільтри;
* змінити сортування;
* перемкнути вигляд бібліотеки;
* бачити кількість знайдених результатів;
* очистити активний пошук або фільтри.

---

### 4.2. Toolbar elements

| Element       | Type          | Description                   |
| ------------- | ------------- | ----------------------------- |
| Search        | Input         | Пошук книги                   |
| Filters       | Button        | Відкриває панель фільтрів     |
| Sort          | Dropdown      | Змінює порядок книг           |
| View mode     | Toggle        | Перемикає `grid` / `list`     |
| Results count | Text          | Показує кількість результатів |
| Clear all     | Button / Link | Очищає пошук і фільтри        |

---

### 4.3. Recommended layout

```text
[ Search input ] [ Фільтри ] [ Сортувати ] [ Grid/List ]  128 книг
```

Якщо активні пошук або фільтри:

```text
[ Search input ] [ Фільтри • 3 ] [ Сортувати ] [ Grid/List ]  Знайдено 24 з 128  [ Очистити все ]
```

---

### 4.4. Basic behavior

* search input шукає книги за назвою, автором або серією;
* кнопка **Фільтри** відкриває розширені фільтри;
* якщо є активні фільтри, біля кнопки показується count;
* sort dropdown змінює порядок книг;
* view mode перемикає вигляд між grid і list;
* results count оновлюється після пошуку або фільтрації;
* **Очистити все** показується тільки якщо є активний пошук або фільтри.

---

### 4.5. Acceptance Criteria

* Toolbar показується під page header.
* Toolbar містить search input.
* Toolbar містить кнопку **Фільтри**.
* Toolbar містить sort dropdown.
* Toolbar містить перемикач grid / list.
* Toolbar показує кількість книг або знайдених результатів.
* Якщо активні фільтри, кнопка **Фільтри** показує count.
* Якщо активний пошук або фільтри, користувач бачить дію **Очистити все**.
* Після очищення пошуку і фільтрів показується повний список книг.


## 5. Search

Search у **“Моїй бібліотеці”** потрібен, щоб користувач міг швидко знайти книгу за ключовою інформацією.

Search input знаходиться в **Library toolbar**.

---

### 5.1. Search input

Placeholder:

```text
Пошук за назвою, автором або серією
```

Search має працювати по активних книгах поточного користувача.

Видалені книги не мають потрапляти в результати пошуку.

---

### 5.2. Search fields

Пошук має працювати за такими полями:

| Поле              | Приклад                | Пріоритет |
| ----------------- | ---------------------- | --------: |
| Назва книги       | `Четверте крило`       |      High |
| Оригінальна назва | `Fourth Wing`          |      High |
| Автор             | `Ребекка Яррос`        |      High |
| Назва серії       | `Емпіреї`              |      High |
| Видавництво       | `КСД`                  |    Medium |
| Жанри             | `Fantasy`              |    Medium |
| Теги              | `дракони`, `романтика` |    Medium |
| ISBN              | `9786175481234`        |    Medium |
| Перекладач        | `Олена Оксенич`        |       Low |
| Ілюстратор        | `Ім’я ілюстратора`     |       Low |

---

### 5.3. What search should not include

Search у **“Моїй бібліотеці”** не має шукати по:

| Поле / дані   | Причина                                       |
| ------------- | --------------------------------------------- |
| Нотатки       | Це окрема фіча Notes                          |
| Цитати        | Це окрема фіча Quotes                         |
| Персонажі     | Це окрема фіча Characters                     |
| Присвята      | Це деталь видання, не основне поле для пошуку |
| Опис серії    | Це належить до Series details                 |
| Службові поля | `id`, `createdAt`, `updatedAt`, `userId`      |

---

### 5.4. Search behavior

* пошук не чутливий до регістру;
* зайві пробіли на початку і в кінці ігноруються;
* кілька пробілів всередині запиту мають сприйматися як один;
* пошук має працювати по частковому збігу;
* пошук має працювати українською та англійською мовами;
* для ISBN потрібно ігнорувати дефіси та пробіли;
* search query має комбінуватися з активними фільтрами.

Приклад:

```text
Запит: "wing"
Може знайти: "Fourth Wing"
```

```text
Запит: "яррос"
Може знайти: книги авторки Ребекки Яррос
```

```text
Запит: "978 617"
Може знайти книгу з ISBN "978-617-..."
```

---

### 5.5. Search + filters logic

Search і filters мають працювати разом.

Логіка:

```text
search query + active filters = filtered search results
```

Приклад:

```text
search = "крило"
genre = fantasy
readingStatus = finished
```

Результат:

```text
Показати тільки книги, які:
- містять "крило" в searchable fields;
- мають жанр fantasy;
- мають статус readingStatus = finished.
```

---

### 5.6. URL query behavior

Search query має зберігатися в URL.

Приклад:

```text
/library?search=wing
```

Якщо користувач оновлює сторінку, search input має відновити значення з URL.

---

### 5.7. Empty search behavior

Якщо search input порожній:

```text
Показати всі книги з урахуванням активних фільтрів
```

Якщо користувач очищає search input:

* search query видаляється з URL;
* список книг оновлюється;
* активні фільтри залишаються.

---

### 5.8. No results state

Якщо за пошуком нічого не знайдено, показати no results state.

```text
Нічого не знайдено

Спробуйте змінити запит або очистити фільтри.
```

Action:

```text
Очистити пошук
```

Якщо також активні фільтри:

```text
Очистити все
```

---

### 5.9. Technical behavior

* search має мати debounce;
* рекомендований debounce: `300ms`;
* мінімальна довжина запиту: `2` символи;
* для ISBN можна дозволити пошук з `1` символу, але це не обов’язково;
* після зміни search query потрібно скидати pagination на першу сторінку.

---

### 5.10. Acceptance Criteria

* Користувач бачить search input у Library toolbar.
* Користувач може шукати книги за назвою.
* Користувач може шукати книги за оригінальною назвою.
* Користувач може шукати книги за автором.
* Користувач може шукати книги за назвою серії.
* Користувач може шукати книги за видавництвом.
* Користувач може шукати книги за жанрами.
* Користувач може шукати книги за тегами.
* Користувач може шукати книги за ISBN.
* Search не чутливий до регістру.
* Search працює разом з активними фільтрами.
* Search query зберігається в URL.
* Після очищення search input список книг оновлюється.
* Якщо результатів немає, користувач бачить no results state.
* Видалені книги не потрапляють у результати пошуку.



## 6. Quick filters

Quick filters — це короткі chips під toolbar, які дозволяють користувачу швидко відфільтрувати бібліотеку за найчастішими сценаріями.

Вони не замінюють розширені фільтри, а дають швидкий доступ до популярних категорій.

---

### 6.1. Recommended quick filters

| Chip           | Query logic                                                 |
| -------------- |-------------------------------------------------------------|
| Усі            | без quick filter                                            |
| Читаю          | `readingStatus=reading` + `readingStatus=rereading`         |
| Хочу прочитати | `readingStatus=want_to_read`                                |
| Прочитано      | `readingStatus=finished`                                    |
| Улюблені       | `isFavorite=true`                                           |
| До покупки     | `ownershipStatus=want_to_buy`                               |
| В дорозі       | `ownershipStatus=in_transit`                                |
| Позичені       | `ownershipStatus=borrowed_from_someone` + `lent_to_someone` |
| Серії          | `seriesState=series_part`                                   |
| Соло           | `seriesState=solo`                                          |

---

### 6.2. UI behavior

* quick filters показуються як horizontal chips;
* за замовчуванням активний chip **Усі**;
* одночасно може бути активний тільки один quick filter;
* активний chip має бути візуально виділений;
* на mobile chips можуть скролитися горизонтально;
* якщо quick filters не поміщаються в один рядок, вони не мають ламати layout.

---

### 6.3. Filter behavior

* при кліку на chip список книг одразу оновлюється;
* quick filter комбінується з активним пошуком;
* quick filter може комбінуватися з advanced filters;
* якщо користувач обирає інший quick filter, попередній quick filter замінюється;
* chip **Усі** прибирає тільки quick filter;
* дія **Очистити все** очищає quick filter, search і advanced filters.

---

### 6.4. URL query behavior

Quick filter має зберігатися в URL.

Приклади:

```text
/library?quickFilter=reading
/library?quickFilter=favorites
/library?quickFilter=in_transit
/library?quickFilter=series
```

Після reload сторінки активний quick filter має відновлюватися з URL.

---

### 6.5. What not to include as quick filters

Не варто додавати в quick filters жанри або аудиторні категорії типу:

```text
Fantasy
Young Adult
Romance
```

Їх краще показувати в **Advanced filters** або в окремому блоці популярних жанрів.

---

### 6.6. Acceptance Criteria

* Quick filters показуються під Library toolbar.
* Користувач бачить chip **Усі**.
* Користувач може швидко відфільтрувати книги за основними сценаріями.
* Одночасно активний тільки один quick filter.
* Активний quick filter візуально виділений.
* Quick filter працює разом із search.
* Quick filter працює разом із advanced filters.
* Chip **Усі** прибирає активний quick filter.
* Quick filter зберігається в URL.
* Після reload сторінки активний quick filter відновлюється.


## 7. Advanced filters

Advanced filters — це розширена панель фільтрів на сторінці **“Моя бібліотека”**.

Вона відкривається після натискання кнопки **Фільтри** в Library toolbar і дозволяє користувачу точніше відфільтрувати книги за основними властивостями книги.

---

### 7.1. Purpose

Advanced filters потрібні, щоб користувач міг швидко знайти книги за:

* статусом читання;
* статусом володіння;
* форматом;
* жанрами;
* тегами;
* віковою категорією;
* мовою;
* автором;
* видавництвом;
* типом книги;
* рейтингом;
* деталями видання.

Advanced filters не мають дублювати окремі сторінки застосунку.

---

### 7.2. Recommended filters

| Filter               | Type                        | Logic                            |
| -------------------- | --------------------------- | -------------------------------- |
| Статус читання       | Multi-select                | Фільтр за `readingStatus`        |
| Статус володіння     | Multi-select                | Фільтр за `ownershipStatus`      |
| Формат книги         | Multi-select                | Фільтр за `formats`              |
| Жанри                | Multi-select / Autocomplete | Фільтр за `genreIds`             |
| Теги                 | Multi-select / Autocomplete | Фільтр за `tagIds`               |
| Вікова категорія     | Select / Multi-select       | Фільтр за `ageCategory`          |
| Мова книги           | Select / Multi-select       | Фільтр за `language`             |
| Автор                | Autocomplete                | Фільтр за `authorId`             |
| Видавництво          | Autocomplete                | Фільтр за `publisherId`          |
| Тип книги            | Select                      | Усі / Соло книги / Частина серії |
| Рейтинг              | Range / Select              | Фільтр за `rating`               |
| Рік видання          | Range                       | Фільтр за `publicationYear`      |
| Кількість сторінок   | Range                       | Фільтр за `pagesCount`           |
| Наявність обкладинки | Select                      | Є обкладинка / Немає обкладинки  |

---

### 7.3. Reading status filter

Фільтр за статусом читання.

Options:

| Value          | Label          |
| -------------- | -------------- |
| `not_started`  | Не почато      |
| `want_to_read` | Хочу прочитати |
| `reading`      | Читаю          |
| `paused`       | На паузі       |
| `finished`     | Прочитано      |
| `dnf`          | Покинуто       |
| `rereading`    | Перечитую      |

Logic:

* користувач може вибрати один або кілька статусів;
* кілька вибраних статусів працюють як `OR`;
* порожнє значення означає “усі статуси”.

---

### 7.4. Ownership status filter

Фільтр за статусом володіння.

Options:

| Value                   | Label             |
| ----------------------- | ----------------- |
| `none`                  | Немає             |
| `want_to_buy`           | Хочу купити       |
| `in_transit`            | В дорозі          |
| `owned`                 | Маю               |
| `borrowed_from_someone` | Позичена у когось |
| `lent_to_someone`       | Видана комусь     |

Important:

* `ebook` і `audiobook` не мають бути в ownership status;
* електронна й аудіокнига — це формат книги;
* детальні фільтри позики не треба додавати тут, бо для цього є окрема сторінка **Позичені книги**.

---

### 7.5. Format filter

Фільтр за форматом книги.

Options:

| Value       | Label      |
| ----------- | ---------- |
| `paper`     | Паперова   |
| `ebook`     | Електронна |
| `audiobook` | Аудіокнига |

Logic:

* книга може мати один або кілька форматів;
* кілька вибраних форматів працюють як `OR`;
* книги без формату показуються тільки тоді, коли format filter не активний.

---

### 7.6. Classification filters

Фільтри з блоку **Класифікація**.

| Filter           | Type                        | Logic                                        |
| ---------------- | --------------------------- | -------------------------------------------- |
| Жанри            | Multi-select / Autocomplete | Показати книги з вибраними жанрами           |
| Теги             | Multi-select / Autocomplete | Показати книги з вибраними тегами            |
| Вікова категорія | Select / Multi-select       | Показати книги з вибраною віковою категорією |
| Мова книги       | Select / Multi-select       | Показати книги вибраною мовою                |

Age category options:

| Value             | Label        |
| ----------------- | ------------ |
| `not_specified`   | Не вказано   |
| `no_restrictions` | Без обмежень |
| `6_plus`          | 6+           |
| `12_plus`         | 12+          |
| `14_plus`         | 14+          |
| `16_plus`         | 16+          |
| `18_plus`         | 18+          |

Important:

* `Young Adult`, `New Adult`, `Adult` не мають бути віковими категоріями;
* такі значення краще використовувати як теги або окрему audience-фічу.

---

### 7.7. Author and publisher filters

| Filter      | Type         | Logic                                |
| ----------- | ------------ | ------------------------------------ |
| Автор       | Autocomplete | Показати книги вибраного автора      |
| Видавництво | Autocomplete | Показати книги вибраного видавництва |

Logic:

* фільтри мають працювати по ID, якщо сутність уже існує;
* custom author і custom publisher також мають бути доступні у фільтрах;
* автор і видавництво мають бути обмежені поточним користувачем та predefined даними.

---

### 7.8. Book type filter

Фільтр за типом книги.

Options:

| Value         | Label         | Logic                |
| ------------- | ------------- | -------------------- |
| `all`         | Усі           | Показати всі книги   |
| `solo`        | Соло книги    | Книги без `seriesId` |
| `series_part` | Частина серії | Книги з `seriesId`   |

Important:

* конкретну серію не потрібно додавати як основний advanced filter;
* для цього є окрема сторінка **Серії** та сторінка деталей серії;
* у бібліотеці достатньо фільтра **Соло / Частина серії**.

---

### 7.9. Rating and edition filters

Фільтри за читацькою оцінкою та деталями видання.

| Filter               | Type           | Logic                                       |
| -------------------- | -------------- | ------------------------------------------- |
| Рейтинг              | Range / Select | `ratingFrom` / `ratingTo`                   |
| Рік видання          | Range          | `publicationYearFrom` / `publicationYearTo` |
| Кількість сторінок   | Range          | `pagesCountFrom` / `pagesCountTo`           |
| Наявність обкладинки | Select         | Усі / Є обкладинка / Немає обкладинки       |

Recommended options for cover filter:

| Value           | Label            |
| --------------- | ---------------- |
| `all`           | Усі              |
| `with_cover`    | Є обкладинка     |
| `without_cover` | Немає обкладинки |

Important:

* ISBN краще шукати через search input;
* перекладача й ілюстратора краще залишити для search або future advanced mode;
* присвяту не потрібно додавати як filter.

---

### 7.10. Filters that should not be included here

Ці фільтри не потрібно додавати в Advanced filters сторінки **“Моя бібліотека”**, бо для них є окремі сторінки або окремі фічі.

| Filter             | Чому не додавати                                |
| ------------------ | ----------------------------------------------- |
| Улюблені           | Є окрема сторінка **Улюблені книги**            |
| У черзі читання    | Є окрема сторінка **Черга читання**             |
| Власні списки      | Є окрема сторінка **Власні списки**             |
| Конкретна серія    | Є сторінка **Серії** та details page серії      |
| Статус серії       | Це фільтр для сторінки серій                    |
| Прострочені позики | Це логіка сторінки **Позичені книги**           |
| Повернути скоро    | Це логіка сторінки **Позичені книги**           |
| Статус доставки    | Це краще винести на сторінку **Книги в дорозі** |
| Нотатки            | Окрема Notes feature                            |
| Цитати             | Окрема Quotes feature                           |
| Персонажі          | Окрема Characters feature                       |

---

### 7.11. Filter behavior

* фільтри працюють разом із search;
* фільтри з різних груп комбінуються через `AND`;
* кілька значень всередині одного фільтра комбінуються через `OR`;
* після зміни фільтрів список книг оновлюється;
* після зміни фільтрів pagination скидається на першу сторінку;
* активні фільтри показуються в Active filters bar.

Example:

```text
search = "крило"
readingStatus = finished
genre = fantasy
format = paper
```

Result:

```text
Показати книги, які:
- містять "крило" у searchable fields;
- мають статус "Прочитано";
- мають жанр Fantasy;
- мають формат "Паперова".
```

---

### 7.12. Clear behavior

У панелі фільтрів має бути дія:

```text
Очистити фільтри
```

Logic:

* очищає тільки advanced filters;
* не очищає search input;
* не змінює quick filter;
* не змінює sort;
* не змінює view mode.

Дія **Очистити все** має бути глобальною і може очищати:

* search;
* quick filter;
* advanced filters;
* active filter chips.

---

### 7.13. URL query behavior

Advanced filters мають зберігатися в URL query params.

Examples:

```text
/library?readingStatus=reading
/library?ownershipStatus=in_transit
/library?format=ebook
/library?genreIds=fantasy,romance
/library?tagIds=slow-burn,dark-academia
/library?authorId=author_123
/library?publisherId=publisher_456
/library?bookType=series_part
/library?ratingFrom=4
/library?publicationYearFrom=2020&publicationYearTo=2026
/library?pagesCountFrom=300&pagesCountTo=700
/library?cover=without_cover
```

Після reload сторінки вибрані фільтри мають відновлюватися з URL.

---

### 7.14. Acceptance Criteria

* Користувач може відкрити Advanced filters через кнопку **Фільтри**.
* Користувач може фільтрувати книги за статусом читання.
* Користувач може фільтрувати книги за статусом володіння.
* Користувач може фільтрувати книги за форматом.
* Користувач може фільтрувати книги за жанрами.
* Користувач може фільтрувати книги за тегами.
* Користувач може фільтрувати книги за віковою категорією.
* Користувач може фільтрувати книги за мовою.
* Користувач може фільтрувати книги за автором.
* Користувач може фільтрувати книги за видавництвом.
* Користувач може фільтрувати соло-книги та книги з серій.
* Користувач може фільтрувати книги за рейтингом.
* Користувач може фільтрувати книги за роком видання.
* Користувач може фільтрувати книги за кількістю сторінок.
* Користувач може фільтрувати книги за наявністю обкладинки.
* Advanced filters не дублюють сторінки **Улюблені**, **Черга читання**, **Власні списки**, **Серії**, **Позичені книги**.
* Advanced filters працюють разом із search.
* Активні фільтри відображаються в Active filters bar.
* Advanced filters зберігаються в URL query params.
* Після reload сторінки активні фільтри відновлюються.
* Користувач може очистити advanced filters.


## 8. Active filters bar

Active filters bar — це рядок із активними фільтрами, який показується під Library toolbar, коли користувач застосував search, quick filter або advanced filters.

Він потрібен, щоб користувач одразу бачив, чому список книг відфільтрований.

---

### 8.1. When to show

Active filters bar показується, якщо активний хоча б один параметр:

* search query;
* quick filter;
* advanced filter.

Якщо немає активних фільтрів або пошуку, цей блок не показується.

---

### 8.2. What to show

Active filters bar має показувати активні параметри як chips.

Приклад:

```text
Пошук: крило ×
Прочитано ×
Fantasy ×
Паперова ×
Автор: Сара Дж. Маас ×
Очистити все
```

---

### 8.3. Chip behavior

Кожен chip має показувати конкретний активний параметр.

| Chip type        | Example                |
| ---------------- | ---------------------- |
| Search           | `Пошук: крило`         |
| Quick filter     | `Читаю`                |
| Reading status   | `Прочитано`            |
| Ownership status | `В дорозі`             |
| Format           | `Паперова`             |
| Genre            | `Fantasy`              |
| Tag              | `slow burn`            |
| Age category     | `16+`                  |
| Language         | `Українська`           |
| Author           | `Автор: Сара Дж. Маас` |
| Publisher        | `Видавництво: КСД`     |
| Book type        | `Частина серії`        |
| Rating           | `Рейтинг від 4`        |
| Publication year | `2020–2026`            |
| Pages count      | `300–700 стор.`        |
| Cover            | `Без обкладинки`       |

---

### 8.4. Remove one filter

Користувач може прибрати окремий filter chip через `×`.

Logic:

* при видаленні chip прибирається тільки відповідний параметр;
* інші активні фільтри залишаються;
* список книг оновлюється;
* URL query params оновлюються.

Приклад:

```text
Було:
[Прочитано ×] [Fantasy ×] [Паперова ×]

Користувач прибрав Fantasy

Стало:
[Прочитано ×] [Паперова ×]
```

---

### 8.5. Clear all

У кінці Active filters bar має бути дія:

```text
Очистити все
```

Logic:

* очищає search query;
* очищає quick filter;
* очищає advanced filters;
* не змінює sort;
* не змінює view mode;
* скидає pagination на першу сторінку;
* оновлює URL query params.

---

### 8.6. URL behavior

Active filters bar має відображати стан з URL query params.

Приклад:

```text
/library?search=крило&readingStatus=finished&format=paper
```

На сторінці мають показатися chips:

```text
Пошук: крило ×
Прочитано ×
Паперова ×
Очистити все
```

---

### 8.7. Empty state

Якщо всі active filters видалені:

* Active filters bar приховується;
* список книг повертається до default state;
* URL очищається від filter/search params.

---

### 8.8. Acceptance Criteria

* Active filters bar показується тільки коли є активний search, quick filter або advanced filter.
* Кожен активний параметр показується як окремий chip.
* Користувач може прибрати окремий filter chip.
* При видаленні chip список книг оновлюється.
* Інші активні фільтри не очищаються.
* Користувач може натиснути **Очистити все**.
* **Очистити все** прибирає search, quick filter і advanced filters.
* Sort і view mode не скидаються після **Очистити все**.
* Active filters bar синхронізується з URL query params.
* Якщо активних параметрів немає, Active filters bar не показується.


## 9. Sorting

Sorting — це керування порядком відображення книг у **“Моїй бібліотеці”**.

Sorting не змінює набір книг у списку, а тільки визначає, у якому порядку вони показуються після застосування search і filters.

---

### 9.1. Purpose

Sorting потрібен, щоб користувач міг швидко впорядкувати бібліотеку за найважливішими параметрами:

* датою додавання;
* назвою книги;
* автором;
* рейтингом;
* роком видання;
* кількістю сторінок;
* останнім оновленням.

---

### 9.2. Default sorting

Default sorting:

```text id="ag4zoq"
Нещодавно додані
```

Logic:

```text id="n6clu2"
createdAt DESC
```

Новіші книги мають показуватися першими.

---

### 9.3. Recommended sorting options

| Option             | Logic                  |
| ------------------ | ---------------------- |
| Нещодавно додані   | `createdAt DESC`       |
| Давно додані       | `createdAt ASC`        |
| Нещодавно оновлені | `updatedAt DESC`       |
| Назва А–Я          | `title ASC`            |
| Назва Я–А          | `title DESC`           |
| Автор А–Я          | `authorName ASC`       |
| Автор Я–А          | `authorName DESC`      |
| Найвищий рейтинг   | `rating DESC`          |
| Найнижчий рейтинг  | `rating ASC`           |
| Новіші видання     | `publicationYear DESC` |
| Старіші видання    | `publicationYear ASC`  |
| Більше сторінок    | `pagesCount DESC`      |
| Менше сторінок     | `pagesCount ASC`       |

---

### 9.4. Sorting behavior

* sorting застосовується до результатів після search і filters;
* sorting не очищає search;
* sorting не очищає quick filter;
* sorting не очищає advanced filters;
* sorting не змінює view mode;
* після зміни sorting pagination має скидатися на першу сторінку;
* вибране sorting значення має зберігатися в URL query params;
* після reload сторінки sorting має відновлюватися з URL.

---

### 9.5. Empty values behavior

Якщо в книги немає значення для поля сортування, вона має показуватися після книг, у яких це значення є.

Examples:

| Sorting            | Books without value                                                |
| ------------------ | ------------------------------------------------------------------ |
| Рейтинг            | книги без rating показуються після оцінених                        |
| Рік видання        | книги без publication year показуються після книг із роком         |
| Кількість сторінок | книги без pages count показуються після книг із кількістю сторінок |

---

### 9.6. URL query behavior

Sorting має зберігатися в URL.

Examples:

```text id="t8hlbg"
/library?sort=createdAt_desc
/library?sort=title_asc
/library?sort=rating_desc
/library?sort=publicationYear_desc
/library?sort=pagesCount_asc
```

Якщо sort query param відсутній, використовується default sorting:

```text id="962hmg"
createdAt_desc
```

---

### 9.7. Interaction with filters

Sorting застосовується після фільтрації.

Example:

```text id="2jfn1p"
search = "крило"
genre = fantasy
readingStatus = finished
sort = rating_desc
```

Result:

```text id="2jt1k2"
1. Спочатку знайти книги, які відповідають search і filters.
2. Потім відсортувати знайдені книги за рейтингом від найвищого до найнижчого.
```

---

### 9.8. Acceptance Criteria

* Користувач бачить sorting control у Library toolbar.
* За замовчуванням книги сортуються як **Нещодавно додані**.
* Користувач може змінити sorting option.
* Sorting змінює тільки порядок книг, але не змінює набір результатів.
* Sorting працює разом із search.
* Sorting працює разом із quick filters.
* Sorting працює разом із advanced filters.
* Після зміни sorting pagination скидається на першу сторінку.
* Sorting зберігається в URL query params.
* Після reload сторінки вибране sorting значення відновлюється.
* Книги без значення для вибраного sorting field показуються після книг із заповненим значенням.


## 10. View modes

View modes — це перемикач вигляду списку книг у **“Моїй бібліотеці”**.

View mode не змінює набір книг, search, filters або sorting. Він змінює тільки те, як книги візуально відображаються на сторінці.

---

### 10.1. Available view modes

| View mode | Description                            |
| --------- | -------------------------------------- |
| `grid`    | Книги показуються як картки            |
| `list`    | Книги показуються як компактний список |

---

### 10.2. Default view mode

Default view mode:

```text
grid
```

Grid view краще підходить як основний вигляд, бо бібліотека візуально сприймається як книжкова полиця.

---

### 10.3. Grid view

Grid view показує книги у вигляді карток.

Картка книги може містити:

* обкладинку;
* назву книги;
* автора;
* статус читання;
* статус володіння;
* формат;
* рейтинг;
* короткі chips жанрів або тегів;
* quick actions.

Grid view краще підходить для візуального перегляду бібліотеки.

---

### 10.4. List view

List view показує книги у вигляді компактних рядків.

Рядок книги може містити:

* маленьку обкладинку;
* назву книги;
* автора;
* статус читання;
* формат;
* рейтинг;
* рік видання;
* кількість сторінок;
* quick actions.

List view краще підходить для швидкого перегляду великої кількості книг.

---

### 10.5. View mode behavior

* користувач може перемикатися між `grid` і `list`;
* перемикач знаходиться в Library toolbar;
* зміна view mode не очищає search;
* зміна view mode не очищає quick filter;
* зміна view mode не очищає advanced filters;
* зміна view mode не змінює sorting;
* зміна view mode не скидає pagination;
* вибраний view mode має зберігатися як user preference.

---

### 10.6. URL query behavior

View mode може зберігатися в URL query params.

Examples:

```text
/library?view=grid
/library?view=list
```

Якщо `view` відсутній в URL, система має використовувати збережений user preference.

Якщо user preference ще немає, використовується default:

```text
grid
```

---

### 10.7. Responsive behavior

На desktop доступні обидва режими:

```text
grid / list
```

На mobile:

* grid view може показувати 1–2 картки в ряд;
* list view має залишатися компактним;
* перемикач view mode не має ламати toolbar;
* останній вибраний view mode має зберігатися між відкриттями сторінки.

---

### 10.8. Acceptance Criteria

* Користувач бачить перемикач `grid / list` у Library toolbar.
* За замовчуванням використовується `grid` view.
* Користувач може перемкнути бібліотеку в `list` view.
* Користувач може повернутися назад у `grid` view.
* View mode змінює тільки вигляд списку книг.
* View mode не очищає search.
* View mode не очищає filters.
* View mode не змінює sorting.
* View mode зберігається як user preference.
* Після reload сторінки останній вибраний view mode відновлюється.
* Grid і list view коректно працюють на desktop і mobile.


## 11. Book card actions

Book card actions — це дії, які користувач може виконати з книгою прямо з картки в `grid` view або з рядка в `list` view.

Щоб не перевантажувати інтерфейс, на картці мають бути тільки основні дії, а додаткові дії мають бути винесені в menu.

---

### 11.1. Purpose

Book card actions потрібні, щоб користувач міг швидко:

* відкрити деталі книги;
* додати або прибрати книгу з улюблених;
* відредагувати книгу;
* оновити прогрес читання;
* додати книгу в чергу або список;
* додати нотатку чи цитату;
* змінити статус книги;
* видалити книгу.

---

### 11.2. Visible actions

На картці книги мають бути видимі тільки базові дії.

| Action            | UI                                  | Logic                                |
| ----------------- | ----------------------------------- | ------------------------------------ |
| Open book details | клік по картці / назві / обкладинці | відкриває сторінку деталей книги     |
| Toggle favorite   | heart icon                          | додає або прибирає книгу з улюблених |
| More actions      | `...` button                        | відкриває меню з додатковими діями   |

---

### 11.3. More actions menu

Усі додаткові дії мають бути в меню `...`.

| Action                   | Logic                                                      |
| ------------------------ | ---------------------------------------------------------- |
| Редагувати               | відкриває сторінку редагування книги                       |
| Оновити прогрес          | відкриває modal оновлення прогресу                         |
| Почати читати            | змінює статус на `reading` або відкриває progress modal    |
| Позначити як прочитану   | змінює статус на `finished` або відкриває completion modal |
| Додати в чергу читання   | додає книгу в reading queue                                |
| Додати до списку         | відкриває modal додавання книги до власного списку         |
| Додати нотатку           | відкриває modal створення нотатки                          |
| Додати цитату            | відкриває modal створення цитати                           |
| Змінити статус володіння | відкриває modal або форму зміни ownership status           |
| Видалити                 | відкриває confirm delete modal                             |

---

### 11.4. Conditional actions

Деякі дії мають показуватися тільки для відповідних статусів книги.

| Action                   | Коли показувати                                                      |
| ------------------------ | -------------------------------------------------------------------- |
| Оновити прогрес          | якщо `readingStatus = reading`, `rereading` або `paused`             |
| Почати читати            | якщо книга не має active reading status                              |
| Позначити як прочитану   | якщо `readingStatus !== finished`                                    |
| Позначити як отриману    | якщо `ownershipStatus = in_transit`                                  |
| Позначити як повернуту   | якщо `ownershipStatus = borrowed_from_someone` або `lent_to_someone` |
| Додати в чергу читання   | якщо книги ще немає в reading queue                                  |
| Прибрати з черги читання | якщо книга вже є в reading queue                                     |

---

### 11.5. Delete behavior

Дія **Видалити** не має одразу видаляти книгу.

При натисканні потрібно показати confirmation modal.

```text id="jssuz6"
Видалити книгу?

Цю дію не можна буде скасувати.
```

Actions:

```text id="y3bcc1"
Скасувати
Видалити
```

Recommended logic:

* delete action має бути внизу menu;
* delete action має бути візуально відділена від інших дій;
* після підтвердження книга прибирається з бібліотеки;
* якщо використовується soft delete, книга отримує `deletedAt`.

---

### 11.6. Behavior after action

Після виконання action:

* список книг має оновитися;
* summary cards мають оновитися, якщо дія впливає на статистику;
* active filters мають залишитися без змін;
* sorting має залишитися без змін;
* view mode має залишитися без змін;
* користувач має бачити success або error state.

---

### 11.7. What not to do

Не потрібно показувати всі дії окремими кнопками на картці.

Поганий варіант:

```text id="wwdkvy"
Редагувати / Видалити / Нотатка / Цитата / В чергу / В список / Прогрес
```

Рекомендований варіант:

```text id="7908re"
[ Heart ] [ ... ]
```

---

### 11.8. Acceptance Criteria

* Користувач може відкрити деталі книги з картки.
* Користувач може додати або прибрати книгу з улюблених.
* Користувач бачить кнопку `...` для додаткових дій.
* Користувач може відредагувати книгу через actions menu.
* Користувач може оновити прогрес читання, якщо дія доступна для поточного статусу.
* Користувач може додати книгу в reading queue.
* Користувач може додати книгу до власного списку.
* Користувач може додати нотатку до книги.
* Користувач може додати цитату до книги.
* Користувач може змінити ownership status.
* Дія **Видалити** відкриває confirmation modal.
* Conditional actions показуються тільки тоді, коли вони релевантні для поточного статусу книги.
* Після виконання action список книг оновлюється.
* Search, filters, sorting і view mode не скидаються після виконання action.

## 12. Bulk actions

Bulk actions — це масові дії над кількома книгами в **“Моїй бібліотеці”**.

Користувач може вибрати кілька книг через checkboxes і застосувати одну дію одразу до всіх вибраних книг.

---

### 12.1. Purpose

Bulk actions потрібні, щоб користувач міг швидко організувати бібліотеку без редагування кожної книги окремо.

Користувач може масово:

* додати книги до власного списку;
* додати книги в чергу читання;
* змінити статус читання;
* змінити статус володіння;
* додати теги;
* додати книги в улюблені;
* прибрати книги з улюблених;
* видалити книги.

---

### 12.2. Selection behavior

Користувач може вибирати книги через checkbox на картці або в рядку списку.

Logic:

* checkbox показується для кожної книги;
* після вибору першої книги з’являється Bulk actions bar;
* користувач може вибрати кілька книг;
* користувач може зняти вибір з окремої книги;
* користувач може очистити весь selection;
* selected books мають бути візуально виділені.

---

### 12.3. Bulk actions bar

Bulk actions bar показується тільки тоді, коли вибрана хоча б одна книга.

Recommended content:

```text
Обрано: 3 книги    [Додати до списку] [Додати в чергу] [Змінити статус] [Ще...]
```

Bar має містити:

| Element         | Description              |
| --------------- | ------------------------ |
| Selected count  | Кількість вибраних книг  |
| Primary actions | Найчастіші bulk actions  |
| More actions    | Меню з додатковими діями |
| Clear selection | Скидання вибору          |

---

### 12.4. Recommended minimal bulk actions

| Action                   | Logic                                                |
| ------------------------ | ---------------------------------------------------- |
| Додати до списку         | додає вибрані книги до custom list                   |
| Додати в чергу читання   | додає вибрані книги в reading queue                  |
| Змінити статус читання   | оновлює `readingStatus` для вибраних книг            |
| Змінити статус володіння | оновлює `ownershipStatus` для вибраних книг          |
| Додати теги              | додає один або кілька тегів до вибраних книг         |
| Додати в улюблені        | встановлює `isFavorite = true`                       |
| Прибрати з улюблених     | встановлює `isFavorite = false`                      |
| Видалити книги           | відкриває confirmation modal і видаляє вибрані книги |

---

### 12.5. Add to custom list

Action:

```text
Додати до списку
```

Logic:

* відкриває modal вибору custom list;
* користувач вибирає один список;
* вибрані книги додаються до цього списку;
* якщо книга вже є в списку, вона не дублюється;
* після успішної дії selection можна очистити.

---

### 12.6. Add to reading queue

Action:

```text
Додати в чергу читання
```

Logic:

* вибрані книги додаються в reading queue;
* якщо книга вже є в черзі, вона не дублюється;
* нові книги додаються в кінець черги;
* порядок вибраних книг можна брати з поточного порядку в бібліотеці.

---

### 12.7. Change reading status

Action:

```text
Змінити статус читання
```

Користувач вибирає новий reading status:

| Value          | Label          |
| -------------- | -------------- |
| `not_started`  | Не почато      |
| `want_to_read` | Хочу прочитати |
| `reading`      | Читаю          |
| `paused`       | На паузі       |
| `finished`     | Прочитано      |
| `dnf`          | Покинуто       |
| `rereading`    | Перечитую      |

Logic:

* статус змінюється для всіх вибраних книг;
* bulk action оновлює тільки `readingStatus`;
* індивідуальні поля типу rating, progress, date finished або note не заповнюються масово;
* якщо потрібні детальні дані, користувач редагує книгу окремо.

---

### 12.8. Change ownership status

Action:

```text
Змінити статус володіння
```

Користувач вибирає новий ownership status:

| Value                   | Label             |
| ----------------------- | ----------------- |
| `none`                  | Немає             |
| `want_to_buy`           | Хочу купити       |
| `in_transit`            | В дорозі          |
| `owned`                 | Маю               |
| `borrowed_from_someone` | Позичена у когось |
| `lent_to_someone`       | Видана комусь     |

Logic:

* статус змінюється для всіх вибраних книг;
* bulk action оновлює тільки `ownershipStatus`;
* індивідуальні дані доставки або позики не заповнюються масово;
* якщо для статусу потрібні деталі, їх можна додати пізніше через edit book.

---

### 12.9. Add tags

Action:

```text
Додати теги
```

Logic:

* відкриває modal вибору або створення тегів;
* користувач може вибрати один або кілька тегів;
* теги додаються до всіх вибраних книг;
* вже існуючі теги не дублюються;
* нові custom tags створюються для поточного користувача.

---

### 12.10. Favorite actions

Actions:

```text
Додати в улюблені
Прибрати з улюблених
```

Logic:

* **Додати в улюблені** встановлює `isFavorite = true`;
* **Прибрати з улюблених** встановлює `isFavorite = false`;
* дія застосовується до всіх вибраних книг;
* summary card **Улюблених** має оновитися після виконання дії.

---

### 12.11. Delete books

Action:

```text
Видалити книги
```

Це destructive action, тому перед видаленням потрібно показати confirmation modal.

Modal text:

```text
Видалити вибрані книги?

Цю дію не можна буде скасувати.
```

Actions:

```text
Скасувати
Видалити
```

Logic:

* книги не видаляються без підтвердження;
* після підтвердження вибрані книги видаляються або отримують `deletedAt`;
* після видалення книги зникають зі списку;
* selection очищається;
* summary cards оновлюються.

---

### 12.12. What not to include in bulk actions

Не потрібно додавати bulk actions для даних, які потребують індивідуального заповнення.

Не додавати:

* додати нотатку;
* додати цитату;
* змінити прогрес читання;
* змінити рейтинг;
* змінити дату прочитання;
* змінити дані позики;
* змінити дані доставки;
* змінити номер частини в серії.

Ці дії краще виконувати для однієї книги.

---

### 12.13. Behavior after bulk action

Після виконання bulk action:

* список книг оновлюється;
* selected books очищаються;
* summary cards оновлюються, якщо дія впливає на статистику;
* search залишається активним;
* filters залишаються активними;
* sorting залишається активним;
* view mode не змінюється;
* pagination може залишитися на поточній сторінці, якщо на ній ще є книги.

---

### 12.14. Acceptance Criteria

* Користувач може вибрати одну або кілька книг.
* Після вибору книг показується Bulk actions bar.
* Bulk actions bar показує кількість вибраних книг.
* Користувач може очистити selection.
* Користувач може додати вибрані книги до custom list.
* Користувач може додати вибрані книги в reading queue.
* Користувач може масово змінити reading status.
* Користувач може масово змінити ownership status.
* Користувач може масово додати tags.
* Користувач може масово додати книги в улюблені.
* Користувач може масово прибрати книги з улюблених.
* Користувач може масово видалити книги тільки після confirmation modal.
* Після bulk action список книг оновлюється.
* Search, filters, sorting і view mode не скидаються після bulk action.



## 13. Library summary sidebar

Library summary sidebar — це додаткова бокова панель на сторінці **“Моя бібліотека”**, яка показує короткий зріз бібліотеки та швидкі переходи до пов’язаних розділів.

Sidebar не має дублювати page header, statistics page або окремі сторінки застосунку.

---

### 13.1. Purpose

Library summary sidebar потрібен, щоб користувач міг швидко побачити:

* найпопулярніші жанри;
* найчастіші теги;
* останні додані книги;
* швидкі посилання на важливі розділи бібліотеки.

---

### 13.2. Sidebar blocks

Sidebar має містити такі блоки:

| Block                | Description                         |
| -------------------- | ----------------------------------- |
| Top genres           | Найчастіші жанри в бібліотеці       |
| Top tags             | Найчастіші теги користувача         |
| Recently added books | Останні 3 додані книги              |
| Quick links          | Швидкі переходи до окремих сторінок |

---

### 13.3. Top genres

Блок показує найпопулярніші жанри серед книг користувача.

Example:

```text
Top genres
- Fantasy
- Romance
- Mystery
```

Logic:

* показувати до 3 найчастіших жанрів;
* рахувати тільки активні книги поточного користувача;
* видалені книги не враховуються;
* якщо жанрів ще немає, блок можна приховати або показати empty state.

Empty state:

```text
Жанри ще не додані
```

---

### 13.4. Top tags

Блок показує найчастіші теги, які користувач додавав до книг.

Example:

```text
Top tags
- slow burn
- dark academia
- dragons
```

Logic:

* показувати до 3 найчастіших тегів;
* рахувати тільки теги з активних книг поточного користувача;
* видалені книги не враховуються;
* якщо тегів ще немає, блок можна приховати або показати empty state.

Empty state:

```text
Теги ще не додані
```

---

### 13.5. Recently added books

Блок показує 3 останні додані книги.

Example:

```text
Recently added books
- Fourth Wing
- Iron Flame
- Divine Rivals
```

Logic:

* показувати максимум 3 книги;
* сортування: `createdAt DESC`;
* показувати тільки активні книги поточного користувача;
* видалені книги не показуються;
* клік по книзі відкриває сторінку деталей книги.

Empty state:

```text
Книг ще немає
```

---

### 13.6. Quick links

Блок містить швидкі посилання на окремі сторінки застосунку.

Links:

| Link             | Route             |
| ---------------- | ----------------- |
| Серії            | `/series`         |
| Черга читання    | `/reading-queue`  |
| Улюблені         | `/favorites`      |
| Позичені книги   | `/borrowed-books` |
| Книги до покупки | `/books-to-buy`   |

Logic:

* quick links мають працювати як navigation links;
* вони не мають застосовувати фільтри на сторінці бібліотеки;
* активні search, filters, sorting і view mode не мають змінюватися при переході;
* кожен link веде на відповідну окрему сторінку.

---

### 13.7. Responsive behavior

* на desktop sidebar може показуватися праворуч від списку книг;
* на tablet sidebar може переходити під основний контент;
* на mobile sidebar можна показувати після списку книг або приховувати в collapsible block;
* sidebar не має заважати основному перегляду бібліотеки.

---


### 13.8. Acceptance Criteria

* Sidebar показує блок Top genres.
* Sidebar показує блок Top tags.
* Sidebar показує 3 останні додані книги.
* Sidebar показує quick links.
* Top genres рахуються тільки по книгах поточного користувача.
* Top tags рахуються тільки по книгах поточного користувача.
* Recently added books показують останні 3 активні книги.
* Клік по recently added book відкриває book details page.
* Quick links ведуть на окремі сторінки.
* Sidebar не дублює summary cards із page header.
* Sidebar не містить повну статистику бібліотеки.


## 14. States

States описують, що користувач бачить на сторінці **“Моя бібліотека”** у різних ситуаціях: під час завантаження, коли бібліотека порожня, коли пошук або фільтри не дали результатів, або коли сталася помилка.

---

### 14.1. States overview

| State               | When to show                                 |
| ------------------- | -------------------------------------------- |
| Loading             | Дані бібліотеки ще завантажуються            |
| Empty library       | У користувача ще немає жодної активної книги |
| No search results   | Пошук активний, але нічого не знайдено       |
| No filtered results | Фільтри активні, але немає відповідних книг  |
| Error               | Дані не вдалося завантажити або оновити      |

---

### 14.2. Loading state

Loading state показується, коли сторінка очікує дані з API або локального сховища.

When to show:

```text
isLoading = true
```

UI:

* skeleton для summary cards;
* skeleton для toolbar;
* skeleton для book cards або list rows;
* sidebar skeleton, якщо sidebar показується.

Behavior:

* не показувати empty state під час loading;
* не показувати no results state під час loading;
* actions мають бути disabled або недоступні до завершення завантаження.

---

### 14.3. Empty library state

Empty library state показується, якщо в користувача ще немає жодної активної книги.

When to show:

```text
totalBooks = 0
search is empty
filters are empty
quickFilter is empty
```

Message:

```text
Твоя бібліотека поки порожня
```

Description:

```text
Додай першу книгу, щоб почати збирати свою читацьку колекцію.
```

Primary action:

```text
+ Додати книгу
```

Behavior:

* кнопка веде на `/books/create`;
* цей state не показується, якщо книги є, але вони приховані через search або filters;
* видалені книги не враховуються.

---

### 14.4. No search results state

No search results state показується, якщо користувач ввів search query, але за цим запитом нічого не знайдено.

When to show:

```text
totalBooks > 0
search is active
filters are empty
resultsCount = 0
```

Message:

```text
Нічого не знайдено
```

Description:

```text
Спробуй змінити пошуковий запит або очистити пошук.
```

Action:

```text
Очистити пошук
```

Behavior:

* очищає тільки search query;
* не змінює sort;
* не змінює view mode;
* після очищення пошуку список книг оновлюється.

---

### 14.5. No filtered results state

No filtered results state показується, якщо активні quick filters або advanced filters, але за ними немає книг.

When to show:

```text
totalBooks > 0
filters are active
resultsCount = 0
```

Message:

```text
Немає книг за вибраними фільтрами
```

Description:

```text
Спробуй змінити фільтри або очистити їх, щоб побачити більше книг.
```

Actions:

```text
Очистити фільтри
Очистити все
```

Behavior:

* **Очистити фільтри** прибирає quick filter і advanced filters;
* search query можна залишити активним, якщо він був введений;
* **Очистити все** прибирає search, quick filter і advanced filters;
* sort і view mode не скидаються.

---

### 14.6. Error state

Error state показується, якщо бібліотеку не вдалося завантажити або action завершився помилкою.

When to show:

```text
isError = true
```

Message:

```text
Не вдалося завантажити бібліотеку
```

Description:

```text
Спробуй оновити сторінку або повторити запит трохи пізніше.
```

Actions:

```text
Спробувати ще раз
```

Behavior:

* action **Спробувати ще раз** повторює запит;
* якщо помилка сталася після bulk action або book card action, потрібно показати error toast;
* якщо попередні дані вже були завантажені, можна залишити їх на сторінці й показати error notification.

---

### 14.7. State priority

Якщо одночасно можливі кілька states, застосовується такий порядок:

```text
1. Loading
2. Error
3. Empty library
4. No search results
5. No filtered results
6. Default books list
```

Important:

* loading має найвищий пріоритет;
* empty library показується тільки коли в користувача взагалі немає активних книг;
* no search results і no filtered results показуються тільки тоді, коли бібліотека не порожня.

---

### 14.8. Acceptance Criteria

* Під час завантаження користувач бачить loading state.
* Empty library state показується тільки якщо в користувача немає активних книг.
* Empty library state має action **+ Додати книгу**.
* No search results state показується, якщо search активний і результатів немає.
* No search results state має action **Очистити пошук**.
* No filtered results state показується, якщо filters активні і результатів немає.
* No filtered results state має actions **Очистити фільтри** і **Очистити все**.
* Error state показується, якщо дані не вдалося завантажити.
* Error state має action **Спробувати ще раз**.
* Loading, empty, no results і error states не конфліктують між собою.


## 15. Pagination / Load more

Для сторінки **“Моя бібліотека”** використовується підхід **Load more** замість класичної pagination.

Користувач бачить першу порцію книг, а потім може підвантажувати наступні книги кнопкою **“Показати ще”**.

---

### 15.1. Purpose

Load more потрібен, щоб:

* не завантажувати всю бібліотеку одразу;
* зробити сторінку швидшою;
* залишити перегляд книг простим і природним;
* не перевантажувати UI класичною pagination.

---

### 15.2. Default behavior

Initial load:

```text
24 books
```

Next load:

```text
+24 books
```

При відкритті сторінки користувач бачить перші 24 книги.

Якщо книг більше, під списком показується кнопка:

```text
Показати ще
```

---

### 15.3. Counter

Над або під списком потрібно показувати кількість завантажених книг.

Example:

```text
Показано 24 з 128 книг
```

Після натискання **Показати ще**:

```text
Показано 48 з 128 книг
```

---

### 15.4. Button behavior

Кнопка **Показати ще**:

* показується тільки якщо є ще книги для завантаження;
* підвантажує наступну порцію книг;
* додає нові книги в кінець поточного списку;
* не очищає вже завантажені книги;
* не змінює search;
* не змінює filters;
* не змінює sorting;
* не змінює view mode.

---

### 15.5. Loading state

Після натискання кнопки потрібно показати loading state.

Button state:

```text
Завантаження...
```

Behavior:

* кнопка тимчасово disabled;
* повторний клік під час завантаження заблокований;
* після успішного завантаження кнопка повертається в normal state або зникає, якщо більше книг немає.

---

### 15.6. End state

Якщо всі книги вже завантажені, кнопка **Показати ще** не показується.

Optional text:

```text
Усі книги показано
```

---

### 15.7. Search, filters and sorting behavior

При зміні будь-якого параметра список має скидатися до першої порції.

Скидання відбувається після зміни:

* search query;
* quick filter;
* advanced filters;
* sorting.

Example:

```text
Було:
Показано 48 з 128 книг

Користувач вибрав жанр Fantasy

Стало:
Показано 24 з 36 книг
```

View mode не скидає завантажені книги.

---

### 15.8. URL behavior

Load more не потрібно зберігати в URL.

У URL зберігаються:

* search;
* quick filter;
* advanced filters;
* sorting;
* view mode.

Не потрібно зберігати:

```text
page
offset
loadedCount
```

Після reload сторінки знову завантажується перша порція книг.

---

### 15.9. API behavior

Backend має підтримувати limit / offset або cursor pagination.

Recommended request:

```text
GET /books?limit=24&offset=0
GET /books?limit=24&offset=24
GET /books?limit=24&offset=48
```

Recommended response:

```ts
{
  items: Book[];
  total: number;
  limit: number;
  offset: number;
  hasMore: boolean;
}
```

---

### 15.10. Error behavior

Якщо наступну порцію книг не вдалося завантажити:

* вже завантажені книги залишаються на сторінці;
* користувач бачить error message або toast;
* кнопка **Показати ще** залишається доступною для повторної спроби.

Message:

```text
Не вдалося завантажити ще книги
```

Action:

```text
Спробувати ще раз
```

---

### 15.11. Acceptance Criteria

* При відкритті сторінки завантажуються перші 24 книги.
* Якщо книг більше ніж 24, показується кнопка **Показати ще**.
* Кнопка підвантажує наступні 24 книги.
* Нові книги додаються в кінець списку.
* Користувач бачить counter типу **Показано X з Y книг**.
* Під час завантаження кнопка disabled.
* Коли всі книги завантажені, кнопка зникає.
* При зміні search список скидається до першої порції.
* При зміні filters список скидається до першої порції.
* При зміні sorting список скидається до першої порції.
* View mode не скидає завантажені книги.
* Load more state не зберігається в URL.
* Якщо завантаження не вдалося, користувач може повторити спробу.
