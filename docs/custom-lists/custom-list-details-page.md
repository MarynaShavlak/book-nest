# Feature: Custom List Details Page

## 1. Purpose

Сторінка **Custom List Details Page** дозволяє користувачу переглядати один конкретний власний список і керувати книгами всередині нього.

Фіча потрібна, щоб власні списки були не просто назвами добірок, а повноцінними персональними книжковими полицями.

Користувач може:

* бачити всі книги, додані до конкретного списку;
* додавати нові книги до списку;
* прибирати книги зі списку;
* змінювати порядок книг у списку;
* переходити до детальної сторінки книги;
* додавати книгу зі списку в чергу читання;
* редагувати інформацію про список;
* видалити список, якщо він більше не потрібен.

---

## 2. Main idea

**Custom Lists Page** показує всі власні списки користувача.

**Custom List Details Page** показує один конкретний список і книги всередині нього.

```text
Custom Lists Page = усі списки
Custom List Details Page = один список + книги цього списку
```

Important rules:

* одна книга може бути в кількох різних списках;
* одна книга не може дублюватися в одному й тому самому списку;
* прибирання книги зі списку не видаляє книгу з бібліотеки;
* видалення списку не видаляє книги з бібліотеки;
* власний список не змінює reading status, ownership status, format або favorite status книги.

---

## 3. Page entry point

Сторінка відкривається після натискання на конкретний список на сторінці **Власні списки**.

Entry point:

```text
Custom Lists Page → List card → Відкрити список
```

Recommended route:

```text
/lists/:listId
```

Example:

```text
/lists/dark-fantasy
```

---

## 4. Page access rules

Сторінка доступна тільки авторизованому користувачу.

Користувач може відкрити тільки свої власні списки.

На сторінці не мають відображатися:

* чужі списки;
* видалені списки;
* книги інших користувачів;
* видалені книги;
* книги, які не належать до цього списку.

Якщо список не існує або недоступний, користувач має побачити not found / access error state.

---

## 5. What books are displayed

На сторінці показуються тільки книги, які додані до цього конкретного списку.

Книга має показуватися, якщо:

```text
book belongs to current user
book is active
book is added to current custom list
```

Книга не має показуватися, якщо:

* книга видалена;
* книга належить іншому користувачу;
* книга не додана до цього списку;
* список видалений.

## 7. Back action

Label:

```text
← До списків
```

Behavior:

* веде на сторінку `/lists`;
* не видаляє активні дані списку;
* не очищає зміни, якщо вони вже збережені.

---

## 8. Header title and description

Title показує назву списку.

Example:

```text
Темне фентезі
```

Description показує опис списку, якщо користувач його додав.

Example:

```text
Похмурі світи, моральні дилеми та незабутні антигерої.
```

Якщо опису немає, блок опису можна приховати.

---

## 9. Count badge

Count badge показує кількість книг у списку.

Example:

```text
15 книг
```

Count має оновлюватися після:

* додавання книг;
* прибирання книги зі списку;
* undo після прибирання книги;
* видалення книги з бібліотеки, якщо вона була в цьому списку.

---

## 10. Primary action: Add books

Primary action:

```text
+ Додати книги
```

Behavior:

* відкриває modal додавання книг до цього списку;
* користувач може вибрати одну або кілька книг зі своєї бібліотеки;
* книги, які вже є у списку, не дублюються.

---

## 11. More actions

У header має бути menu actions.

Actions:

```text
Редагувати список

```

Action **Видалити список** має бути destructive і візуально відділена від інших дій.

| ----------------- | ------------------------------------------ |
| Кількість книг    | Скільки книг у списку                      |

## 13. Toolbar

Toolbar знаходиться над списком книг.

Для MVP toolbar має містити:

| Element   | Type     | Description                               |
| --------- | -------- | ----------------------------------------- |
| Search    | Input    | Пошук книг всередині списку               |
| Sort      | Dropdown | Сортування книг у списку                  |
| View mode | Toggle   | Grid / List, якщо підтримується глобально |

Recommended layout:

```text
[ Пошук у списку... ] [ Сортувати: Позиція в списку ] [ Grid/List ]
```

Filters не входять у MVP.

Reason:

На першому етапі достатньо search + sorting. Складні фільтри краще додати пізніше, якщо списки стануть великими.

---

## 14. Search inside list

Search працює тільки по книгах поточного списку.

Placeholder:

```text
Пошук у списку...
```

Search має працювати за:

* назвою книги;
* оригінальною назвою;
* автором;
* серією;
* жанрами;
* тегами;
* видавництвом.

Search behavior:

* не чутливий до регістру;
* ігнорує зайві пробіли;
* працює по частковому збігу;
* якщо search input порожній, показуються всі книги списку.

---

## 15. Sorting books inside list

Default sorting:

```text
Позиція в списку
```

Reason:

Custom list — це персональна книжкова полиця. Якщо користувач сам змінює порядок книг, цей порядок має бути основним.

Recommended sorting options for MVP:

| Option                | Logic                                |
| --------------------- | ------------------------------------ |
| Позиція в списку      | За ручним порядком користувача       |
| Нові додані спочатку  | Новіші додані до списку першими      |
| Старі додані спочатку | Старіші додані до списку першими     |
| Назва А–Я             | За назвою книги                      |
| Назва Я–А             | За назвою книги у зворотному порядку |
| Автор А–Я             | За автором                           |
| Найвищий рейтинг      | За рейтингом, якщо є                 |
| Більше сторінок       | За кількістю сторінок, якщо є        |
| Менше сторінок        | За кількістю сторінок, якщо є        |

Sorting не змінює склад списку, а тільки порядок відображення книг.

---

## 16. Book position inside custom list

Кожна книга всередині custom list має мати свою позицію.

Position потрібна, щоб користувач міг вручну організувати порядок книг у списку.

Example:

```text
1. Четверте крило
2. Залізне полум’я
3. Асистент лиходія
```

Important:

* позиція книги існує тільки в межах конкретного списку;
* одна й та сама книга може мати різну позицію в різних списках;
* позиція не впливає на My Library;
* позиція не впливає на Reading Queue;
* позиція не змінює reading status або ownership status.

Example:

```text
Книга “Четверте крило” може бути:

- позиція 1 у списку “Книги з драконами”;
- позиція 5 у списку “Хочу перечитати”;
- позиція 2 у списку “Romantasy”.
```

---

## 17. Reorder books in list

Користувач може змінювати порядок книг у конкретному списку.

Reorder доступний тільки якщо:

```text
sorting = Позиція в списку
search is empty
page is not loading
```

Якщо активний search або інший sorting, reorder має бути disabled.

Reason:

Якщо користувач бачить відфільтрований або відсортований список, зміна позицій може бути незрозумілою.

---

## 18. Move book up / down for MVP

Для MVP рекомендовано зробити простий reorder через кнопки:

```text
Перемістити вище
Перемістити нижче
```

Recommended location:

```text
Book card → More actions
```

або compact buttons біля position:

```text
↑
↓
```

Behavior:

* якщо книга перша у списку, action **Перемістити вище** disabled;
* якщо книга остання у списку, action **Перемістити нижче** disabled;
* після переміщення позиції книг перераховуються;
* новий порядок одразу відображається в UI;
* порядок зберігається для поточного користувача.

Example:

Було:

```text
1. Книга A
2. Книга B
3. Книга C
```

Користувач перемістив **Книга C** вище.

Стало:

```text
1. Книга A
2. Книга C
3. Книга B
```

---

## 19. Drag-and-drop as future improvement

Drag-and-drop не входить у MVP.

Його можна додати пізніше як покращення reorder.

Future behavior:

* користувач перетягує книгу в потрібне місце;
* після drop позиції книг оновлюються;
* новий порядок зберігається;
* на mobile має бути fallback через move up / move down.

Important future rule:

```text
Drag-and-drop доступний тільки при sorting = Позиція в списку і без активного search.
```

## 22. Add to Reading Queue action

Для кожної книги у списку має бути дія:

```text
Додати в чергу
```

Behavior:

* якщо книги ще немає в Reading Queue, action додає її в чергу;
* книга додається в кінець черги за замовчуванням;
* після додавання на картці можна показати badge **У черзі**;
* повторне додавання не створює дубль;
* Reading Queue page має оновитися, якщо вона відкрита.

Success message:

```text
Книгу додано в чергу читання
```

```text
У черзі
```

або action:

```text
Перейти до черги
```

Recommended MVP behavior:

```text
Badge: У черзі

```

Rules:

* книга не додається повторно;
* дубль у Reading Queue не створюється;
* якщо користувач натискає на **Перейти до черги**, його веде на `/reading-queue`.

## 29. Add books submit logic

Після натискання **Додати до списку**:

1. перевірити, що список належить поточному користувачу;
2. перевірити, що вибрані книги належать поточному користувачу;
3. перевірити, що вибрані книги ще не додані до цього списку;
4. додати вибрані книги до списку;
5. призначити новим книгам позиції в кінці списку;
6. не створювати дублікати;
7. оновити список книг на сторінці;
8. оновити count badge;
9. оновити `updatedAt` списку;
10. закрити modal;
11. показати success message.

Success message if one book was added:

```text
Книгу додано до списку
```

Success message if several books were added:

```text
Книги додано до списку
```

Example:

```text
2 книги додано до списку
```

## 30. Duplicate prevention

Одна книга не може бути додана в один і той самий список двічі.

Behavior:

* якщо книга вже є в списку, вона показується як **Уже в списку**;
* її не можна повторно вибрати;
* submit не створює дубль;
* books count не збільшується через дубль.

Important:

```text
Одна книга може бути в кількох різних списках, але не може дублюватися в одному списку.
```

---

## 31. Remove book from list

Користувач може прибрати книгу зі списку.

Action label:

```text
Прибрати зі списку
```

Recommended location:

```text
Book card → More actions → Прибрати зі списку
```

Behavior:

* книга зникає тільки з поточного списку;
* книга залишається в бібліотеці;
* книга може залишатися в інших списках;
* reading status не змінюється;
* ownership status не змінюється;
* favorite status не змінюється;
* position інших книг перераховується без пропусків.

---

Reason:

```text
Це не destructive action, бо книга не видаляється з бібліотеки.
```

Recommended behavior:

```text
Click → remove from list → show toast with Undo
```

Toast:

```text
Книгу прибрано зі списку
```

Toast action:

```text
Скасувати
```

Якщо користувач натискає **Скасувати**:

* книга повертається в цей список;
* бажано повернути її на попередню позицію;
* список книг оновлюється;
* count badge повертається до попереднього значення.

```text

```

Recommended location:

```text
Header → More actions
Header → Edit icon
```

Behavior:

* відкриває modal редагування списку;
* користувач може змінити назву, опис, іконку або колір;

Header → More actions → Видалити список
```

Після натискання відкривається confirmation modal.

Modal title:

Видалити список?
```

Modal text:

Список буде видалено, але книги залишаться у вашій бібліотеці.

Після підтвердження:

* список видаляється;
* користувач повертається на сторінку `/lists`;

* показується success message.

```text
Список видалено
```

## 45. Acceptance Criteria

### General

* Користувач може відкрити детальну сторінку конкретного списку.
* Сторінка доступна тільки авторизованому користувачу.
* Користувач бачить тільки свій список.
* Користувач не може відкрити чужий список.
* Видалений список не відкривається.
* Route сторінки має формат `/lists/:listId`.

### Header

* На сторінці показується назва списку.
* На сторінці показується опис списку, якщо він є.
* На сторінці показується кількість книг у списку.
* На сторінці показується дата створення або оновлення.
* Користувач може повернутися до сторінки всіх списків.
* Користувач може натиснути **Додати книги**.
* Користувач може відкрити actions menu списку.
* Користувач може редагувати список.
* Користувач може видалити список.

### Books list

* На сторінці показуються книги, додані до цього списку.
* Кожна книга показує позицію в списку.
* Кожна книга показує обкладинку або placeholder.
* Кожна книга показує назву.
* Кожна книга показує автора.
* Кожна книга показує reading status.
* Кожна книга показує ownership status.
* Кожна книга може показувати genres / tags.
* Кожна книга може показувати series info.
* Користувач може перейти до Book Details.
* Користувач може прибрати книгу зі списку.

### Search and sorting

* Користувач може шукати книги всередині списку.
* Search працює за назвою книги.
* Search працює за оригінальною назвою.
* Search працює за автором.
* Search працює за серією.
* Search працює за жанрами.
* Search працює за тегами.
* Search працює за видавництвом.
* Якщо search нічого не знайшов, показується no search results state.
* Користувач може очистити search.
* Користувач може сортувати книги у списку.
* Default sorting — **Позиція в списку**.

### Book position and reorder

* Кожна книга в списку має позицію.
* Одна й та сама книга може мати різну позицію в різних списках.
* Користувач може перемістити книгу вище.
* Користувач може перемістити книгу нижче.
* Якщо книга перша, action **Перемістити вище** disabled.
* Якщо книга остання, action **Перемістити нижче** disabled.
* Після зміни порядку позиції книг оновлюються.
* Новий порядок зберігається.
* Reorder доступний тільки при sorting = **Позиція в списку**.
* Reorder disabled, якщо активний search.

### Add books

* Користувач може відкрити modal **Додати книги до списку**.
* Modal має блок **Ваша бібліотека**.
* Modal має блок **Вибрано книг: N**.
* Користувач може шукати книги у своїй бібліотеці.
* Користувач може вибрати одну книгу.
* Користувач може вибрати кілька книг.
* Книги, які вже є у списку, показуються як **Уже в списку**.
* Книги, які вже є у списку, не можна додати повторно.
* Після додавання books count оновлюється.
* Після додавання список книг оновлюється.
* Нові книги додаються в кінець списку.
* Користувач бачить success message.

### Remove books

* Користувач може прибрати книгу зі списку.
* Прибирання книги зі списку не видаляє книгу з бібліотеки.
* Прибирання книги зі списку не змінює reading status.
* Прибирання книги зі списку не змінює ownership status.
* Прибирання книги зі списку не змінює favorite status.
* Після прибирання books count оновлюється.
* Після прибирання позиції книг оновлюються без пропусків.
* Після прибирання показується toast.
* Toast має action **Скасувати**.
* Після Undo книга повертається у список.

### Add to Reading Queue

* Користувач може додати книгу зі списку в Reading Queue.
* Якщо книга вже є в черзі, повторно вона не додається.
* Якщо книга вже є в черзі, на картці показується badge **У черзі**.
* Якщо книга вже є в черзі, можна показати action **Перейти до черги**.
* Після додавання книга з’являється на сторінці **Черга читання**.
* Після додавання користувач бачить success message.

### Related Book Details UI

* Якщо книга є в custom lists, Book Details може показувати блок **Мої списки**.
* Блок **Мої списки** показує назви списків, де є книга.
* Клік по назві списку відкриває відповідний Custom List Details Page.
* Якщо книга не додана до жодного списку, блок можна приховати.

### Empty and error states

* Якщо список порожній, показується empty list state.
* Empty state має action **Додати книги**.
* Empty state має action **Повернутися до списків**.
* Якщо список не вдалося завантажити, показується error state.
* Якщо список не знайдено або недоступний, показується not found / access state.
* Error state має action **Спробувати ще раз**.
