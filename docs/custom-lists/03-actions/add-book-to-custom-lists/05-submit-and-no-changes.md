## Role

Defines submit behavior and no-changes behavior.

## Source coverage

`add-to-custom-lists.md` sections 14-15

## Content

## 14. Submit behavior

Кнопка submit:

```text
Зберегти
```

Alternative:

```text
Додати до списків
```

Recommended label:

```text
Зберегти
```

Reason:

Користувач може не тільки додавати, а й прибирати книгу зі списків у цій modal.

Після натискання **Зберегти** система має:

1. перевірити, що книга доступна поточному користувачу;
2. перевірити, що вибрані списки належать поточному користувачу;
3. додати книгу до нових selected списків;
4. прибрати книгу зі списків, з яких користувач зняв вибір;
5. не створювати дублікати;
6. оновити UI Book Details;
7. оновити пов’язані сторінки списків;
8. показати success message;
9. закрити modal.

Success message:

```text
Списки книги оновлено
```

Якщо книга була додана тільки до одного нового списку, можна показати:

```text
Книгу додано до списку
```

Але для multi-select краще універсальне повідомлення:

```text
Списки книги оновлено
```

## 15. No changes behavior

Якщо користувач відкрив modal і нічого не змінив:

* кнопка **Зберегти** може бути disabled;
* або submit не виконує змін і просто закриває modal.

Recommended behavior:

```text
Disable “Зберегти”, якщо немає змін.
```

Reason:

Так користувачу зрозуміліше, що поточний стан уже збережений.
