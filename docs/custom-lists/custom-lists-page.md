# Feature: Custom Lists Page

## 1. Purpose

Сторінка **“Власні списки”** дозволяє користувачу переглядати, створювати, редагувати та видаляти власні книжкові добірки.

Фіча потрібна, щоб користувач міг організовувати книги не тільки за системними статусами, жанрами або серіями, а й за власною логікою.

Examples:

```text
Осіннє читання
Темне фентезі
Книги для настрою
Книги з драконами
Українські видавництва
Хочу перечитати
```

---

## 2. Main idea

**Власні списки** — це ручні тематичні добірки, які створює сам користувач.

Один список може містити багато книг.

Одна книга може бути в кількох списках одночасно.

Important:

```text
Видалення списку не видаляє книги з бібліотеки.
```

Після видалення списку видаляється тільки сам список і зв’язок книг із цим списком. Книги залишаються в **Моїй бібліотеці**.

---

## 3. Difference between system pages and custom lists

Власні списки не мають дублювати системні сторінки BookNest.

System pages:

```text
Улюблені
Черга читання
Книги до покупки
Книги в дорозі
Позичені книги
Серії
```

Custom lists:

```text
Осіннє читання
Книги для настрою
Темне фентезі
Хочу перечитати
Книги від блогерів
```

Important:

* `Улюблені` працюють через `isFavorite`;
* `Книги до покупки` працюють через ownership status;
* `Черга читання` працює через reading queue;
* custom lists — це окрема ручна організація книг.

---

## 4. Page entry point

Сторінка має бути доступна з основного sidebar.

Sidebar item:

```text
Списки
```

Recommended route:

```text
/lists
```

Пункт **“Списки”** має бути active, коли користувач перебуває на сторінці `/lists`.

---

## 5. Page access rules

Сторінка доступна тільки авторизованому користувачу.

Користувач має бачити тільки свої списки.

На сторінці не мають відображатися:

* списки інших користувачів;
* видалені списки;
* чужі книги;
* чужі custom data.

Якщо користувач не авторизований, його потрібно перенаправити на login page.

---

## 6. What lists are displayed

На сторінці **“Власні списки”** показуються всі активні custom lists поточного користувача.

Список має відображатися незалежно від:

* кількості книг у ньому;
* наявності опису;
* наявності preview обкладинок;
* дати створення;
* дати оновлення.

Порожні списки також мають показуватися.

## 7. Page header

Page header має показувати назву сторінки, короткий опис, кількість списків і основну дію.

### Title

```text
Власні списки
```

### Subtitle

```text
Організуйте книги у власні тематичні добірки
```

### Count badge

Example:

```text
7 списків
```

```text
+ Створити список
```

* після створення новий список з’являється на сторінці.

## 8. Custom Lists toolbar

Toolbar знаходиться під page header і над списком карток.

Для MVP toolbar має містити:

| Element   | Type     | Description                                   |
| --------- | -------- | --------------------------------------------- |
| Search    | Input    | Пошук по власних списках                      |
| Sort      | Dropdown | Сортування списків                            |
| View mode | Toggle   | Grid / List, якщо list view уже підтримується |

Recommended layout:

```text
[ Пошук у списках... ] [ Сортувати: Останнє оновлення ] [ Grid/List ]
```

Filters не входять у MVP.

Reason:

На першому етапі списків буде небагато, тому search + sorting достатньо.

---

## 9. Search lists

Search потрібен, щоб користувач міг швидко знайти потрібний список.

Placeholder:

```text
Пошук у списках...
```

Search має працювати за:

* назвою списку;
* описом списку.

У MVP не потрібно шукати за назвами книг усередині списку.

Reason:

Це ускладнює пошук і може бути винесено в future improvements.

Search behavior:

* не чутливий до регістру;
* ігнорує зайві пробіли;
* працює по частковому збігу;
* якщо search input порожній, показуються всі списки.

---

## 10. Sorting

Default sorting:

```text
Останнє оновлення
```

Logic:

```text
updatedAt DESC
```

Recommended sorting options for MVP:

| Option            | Logic             |
| ----------------- | ----------------- |
| Останнє оновлення | `updatedAt DESC`  |
| Спочатку нові     | `createdAt DESC`  |
| Спочатку старі    | `createdAt ASC`   |
| Назва А–Я         | `title ASC`       |
| Назва Я–А         | `title DESC`      |
| Більше книг       | `booksCount DESC` |
| Менше книг        | `booksCount ASC`  |

Sorting не змінює набір списків, а тільки порядок їх відображення.

---

## 11. View modes

Для MVP основний вигляд:

```text
grid
```

Grid view найкраще підходить для власних списків, бо кожен список виглядає як окрема тематична полиця.

List view можна додати, якщо в застосунку вже є готовий reusable компонент.

Available view modes:

| View mode |      MVP | Description                            |
| --------- | -------: | -------------------------------------- |
| `grid`    |      Так | Списки показуються як картки           |
| `list`    | Optional | Списки показуються компактними рядками |

Default:

```text
grid
```

---

## 12. Lists grid

Основний контент сторінки — це grid із картками списків.

Кожна картка представляє один custom list.

Recommended layout:

```text
[ List card ] [ List card ] [ List card ]
[ List card ] [ List card ] [ List card ]
```

На mobile grid переходить в одну колонку.

Картка списку має показувати ключову інформацію про список.

Required elements:

| Element          | Required | Description                      |

| Books count      |      Так | Кількість книг у списку          |
| Cover preview    |      Так | Превʼю обкладинок книг           |

| Open list button |      Так | Перехід у деталі списку          |
| Edit action      |      Так | Редагування списку               |
| More actions     |      Так | Додаткове меню                   |

Optional elements:

| Element                 |      MVP |
| ----------------------- | -------: |
| Icon                    | Optional |
| Color accent            | Optional |
| Access badge            |       Ні |
| Public / private status |       Ні |

---

## 14. Cover preview

Картка списку має показувати кілька обкладинок книг зі списку.

Recommended behavior:

* показувати до 4 обкладинок;
* якщо книг менше, показати стільки, скільки є;
* якщо список порожній, показати placeholder;
* якщо в книги немає обкладинки, показати book placeholder.

Example:

```text
[cover] [cover] [cover] [cover]
```

Cover preview допомагає швидко зрозуміти, які книги всередині списку.

---

## 15. Empty list card behavior

Якщо список не містить книг:

* картка все одно показується;
* books count = `0 книг`;
* замість обкладинок показується placeholder;
* кнопка **Відкрити список** залишається доступною.

Empty preview text:

```text
У списку ще немає книг
```

---

## 16. Open list action

На кожній картці має бути кнопка:

```text
Відкрити список
```

Behavior:

* відкриває детальну сторінку конкретного списку;
* recommended route:

```text
/lists/:listId
```

На сторінці всіх списків не потрібно показувати всі книги зі списку. Для цього має бути окрема сторінка деталей списку.

---

## 17. Create list action

Користувач може створити новий список через кнопку:

```text
+ Створити список
```

Recommended location:

```text
Page header
```

Також дію можна дублювати в sidebar у блоці **Швидкі дії**.

Modal title:

```text
Створити список
```

## 19. Create list validation

### Назва списку

Rules:

| Rule            | Message                                  |
| --------------- | ---------------------------------------- |
| required        | Введіть назву списку                     |
| min 2 symbols   | Назва має містити щонайменше 2 символи   |
| max 80 symbols  | Назва не може бути довшою за 80 символів |
| no HTML         | Назва містить недопустимі символи        |
| duplicate title | Список із такою назвою вже існує         |

### Опис

Rules:

| Rule            | Message                                  |
| --------------- | ---------------------------------------- |
| max 300 symbols | Опис не може бути довшим за 300 символів |

## 20. Create list behavior

Після натискання **Створити список**:

1. система валідує форму;
2. створюється новий список;
3. modal закривається;
4. новий список з’являється на сторінці;
5. count badge у header оновлюється;
6. користувач бачить success message.

Success message:

```text
Список створено
```

Після створення список може з’явитися першим, якщо active sorting = `Останнє оновлення`.

---

## 21. Edit list action

На кожній картці списку має бути action:

```text
Редагувати список
```

Recommended location:

```text
List card → edit icon
List card → more actions menu
```

Для MVP редагування краще робити через modal, а не inline edit.

Reason:

Inline edit складніший: потрібен auto-focus, save/cancel у картці, обробка validation error і keyboard behavior.

## 22. Modal: Edit List

Modal title:

```text
Редагувати список
```

Editable fields:

* назва списку;
* опис;
* іконка;
* колір.

Actions:

```text
Скасувати
Зберегти
```

Після збереження:

* картка списку оновлюється;
* `updatedAt` оновлюється;
* sorting за останнім оновленням може перемістити список вище;
* користувач бачить success message.

Success message:

```text
Список оновлено
```

---

## 23. Delete list action

На кожній картці списку має бути action:

```text
Видалити список
```

Recommended location:

```text
List card → more actions menu
```

Delete action має бути:

* внизу menu;
* візуально відділена від інших дій;
* позначена як destructive action.

---

## 24. Delete list confirmation

Видалення списку має відкривати confirmation modal.

Modal title:

```text
Видалити список?
```

Modal text:

```text
Список буде видалено, але книги залишаться у вашій бібліотеці.
```

Actions:

```text
Скасувати
Видалити список
```

Important:

```text
Видалити список ≠ видалити книги.
```

---

## 25. Delete list behavior

Після підтвердження:

1. список видаляється;
2. список зникає зі сторінки **Власні списки**;
3. зв’язки книг із цим списком видаляються;
4. самі книги залишаються в бібліотеці;
5. count badge оновлюється;
6. користувач бачить success message.

Success message:

```text
Список видалено
```

Якщо видаляється останній список, показується empty state.

## 27. Sidebar: Short statistics

Блок **Коротка статистика** показує загальний стан списків.

Recommended metrics:

| Metric                 | Description                           |
| ---------------------- | ------------------------------------- |
| Всього списків         | Кількість custom lists користувача    |
| Книг у списках         | Загальна кількість book-list зв’язків |
| Найпопулярніший список | Список із найбільшою кількістю книг   |

```text
Всього списків: 7

Найпопулярніший список: Темне фентезі · 27 книг
```

Important:

`Книг у списках` може рахувати одну книгу кілька разів, якщо вона є в кількох списках.

---

## 28. Sidebar: Quick actions

Блок **Швидкі дії** містить корисні navigation/actions.

Recommended actions for MVP:

```text
Створити новий список
Відкрити бібліотеку
```

Не додавати в MVP sidebar action:

```text
Додати книги
```

Reason:

На сторінці всіх списків незрозуміло, до якого саме списку додавати книги. Додавання книг має бути на сторінці конкретного списку або через Book Details.

## 29. Sidebar: Helpful tip

Блок **Корисна порада** пояснює важливу логіку.

Text:

```text
Одна книга може бути в кількох списках.

Видалення списку не видаляє книги з вашої бібліотеки.
```

Цей блок допомагає уникнути страху, що разом зі списком можуть видалитися книги.

## 30. Empty state

Empty state показується, якщо користувач ще не створив жодного списку.

When to show:

```text
listsCount = 0
search is empty
```

Title:

```text
Списків поки немає
```

Description:

```text
Створіть перший список, щоб зберігати книги за настроєм, темою або власним планом читання.
```

Primary action:

```text
Створити список
```

Secondary action:

```text
Перейти до бібліотеки
```

Behavior:

* **Створити список** відкриває create list modal;
* **Перейти до бібліотеки** веде на `/library`.

---

## 31. No search results state

No search results state показується, якщо списки є, але search нічого не знайшов.

When to show:

```text
listsCount > 0
search is active
resultsCount = 0
```

Title:

```text
Нічого не знайдено
```

Description:

```text
Спробуйте змінити пошуковий запит або очистити пошук.
```

Action:

```text
Очистити пошук
```

Behavior:

* очищає search input;
* показує всі списки;
* sorting не змінюється.

---

## 32. Loading state

Loading state показується, коли сторінка очікує дані.

UI:

* skeleton для page header;
* skeleton для toolbar;
* skeleton для list cards;
* skeleton для sidebar.

Behavior:

* не показувати empty state під час loading;
* actions мають бути disabled до завершення завантаження.

---

## 33. Error state

Error state показується, якщо списки не вдалося завантажити.

Title:

```text
Не вдалося завантажити списки
```

Description:

```text
Спробуйте оновити сторінку або повторити запит трохи пізніше.
```

Action:

```text
Спробувати ще раз
```

Якщо помилка сталася після create/edit/delete action, показати toast:

```text
Не вдалося оновити список
```

---

## 34. State priority

Якщо одночасно можливі кілька states, застосовується такий порядок:

```text
1. Loading
2. Error
3. Empty lists
4. No search results
5. Default lists grid
```

Important:

* loading має найвищий пріоритет;
* empty state показується тільки якщо списків немає взагалі;
* no search results показується тільки якщо списки існують, але не знайдені за search.

---

## 35. UI updates after actions

Після створення, редагування або видалення списку мають оновитися:

* lists grid;
* count badge у header;
* sidebar statistics;
* sorting order;
* empty state або default state;
* Custom List Details page, якщо вона відкрита;
* Book Details, якщо там показується індикатор списків.

## 36. What is not included in MVP

У MVP не входить:

* public lists;
* share list;
* favorite lists;
* filters;
* add books modal;
* full Custom List Details Page logic;
* список книг усередині списку;
* прибирання книги зі списку на цій сторінці;
* drag-and-drop книг у списку;
* ручний порядок списків;
* автоматичні списки;
* дублювання списку;
* статистика конкретного списку;
* спільні списки з іншими користувачами;
* API;
* data model.

Ці сценарії потрібно описувати окремими features.

## 37. Acceptance Criteria

### General

* Користувач може відкрити сторінку **Власні списки**.
* Сторінка доступна тільки авторизованому користувачу.
* Користувач бачить тільки свої списки.
* Видалені списки не відображаються.
* У sidebar є пункт **Списки**.
* Route сторінки — `/lists`.

### Page header

* На сторінці є title **Власні списки**.
* На сторінці є subtitle.
* На сторінці показується кількість списків.
* На сторінці є primary action **+ Створити список**.

### Lists grid

* На сторінці показуються картки списків.
* Кожна картка показує назву списку.
* Кожна картка показує опис, якщо він є.
* Кожна картка показує кількість книг.
* Кожна картка показує preview обкладинок.
* Якщо список порожній, картка показує empty preview.
* Користувач може відкрити конкретний список.
* Користувач може редагувати список.
* Користувач може видалити список.

### Search and sorting

* Користувач може шукати списки.
* Search працює за назвою списку.
* Search працює за описом списку.
* Якщо search нічого не знайшов, показується no search results state.
* Користувач може очистити search.
* Користувач може сортувати списки.
* За замовчуванням списки сортуються за останнім оновленням.

### Create list

* Користувач може створити новий список.
* Назва списку є обов’язковою.
* Назва списку має містити щонайменше 2 символи.
* Назва списку не може бути довшою за 80 символів.
* Опис списку optional.
* Опис не може бути довшим за 300 символів.
* Після створення список з’являється на сторінці.
* Count badge оновлюється після створення.
* Користувач бачить success message.

### Edit list

* Користувач може редагувати назву списку.
* Користувач може редагувати опис списку.
* Користувач може змінити іконку, якщо ця опція доступна.
* Користувач може змінити колір, якщо ця опція доступна.
* Після збереження картка списку оновлюється.
* Користувач бачить success message.

### Delete list

* Користувач може видалити список.
* Перед видаленням показується confirmation modal.
* Confirmation modal пояснює, що книги залишаться у бібліотеці.
* Після видалення список зникає зі сторінки.
* Після видалення книги залишаються в бібліотеці.
* Count badge оновлюється після видалення.
* Якщо видалено останній список, показується empty state.

### Sidebar

* Sidebar показує коротку статистику.
* Sidebar показує action **Створити новий список**.
* Sidebar показує action **Відкрити бібліотеку**.
* Sidebar показує пораду про те, що видалення списку не видаляє книги.

### States

* Якщо списків немає, показується empty state.
* Empty state має action **Створити список**.
* Empty state має action **Перейти до бібліотеки**.
* Під час завантаження показується loading state.
* Якщо списки не вдалося завантажити, показується error state.
* Error state має action **Спробувати ще раз**.
