# Feature: Create / Edit / Delete Custom List

## 1. Purpose

Feature **Create / Edit / Delete Custom List** дозволяє користувачу керувати власними книжковими списками в BookNest.

Фіча покриває три основні дії:

* створити новий власний список;
* редагувати існуючий список;
* видалити список.

Ця фіча працює зі списками як окремими добірками книг, але не відповідає за детальне керування книгами всередині списку.

---

## 2. Main idea

Власний список — це ручна тематична добірка книг, яку створює користувач.

Examples:

```text id="d6vprk"
Осіннє читання
Темне фентезі
Книги для настрою
Хочу перечитати
Книги з драконами
```

Important:

```text id="md606w"
Видалення списку не видаляє книги з бібліотеки.
```

Після видалення списку:

* список зникає;
* зв’язки книг із цим списком видаляються;
* самі книги залишаються в бібліотеці користувача.

## 4. Access rules

Користувач може створювати, редагувати та видаляти тільки свої списки.

Система має перевіряти:

* користувач авторизований;
* список належить поточному користувачу;
* список не видалений;
* користувач не може редагувати або видаляти чужі списки.

Якщо список недоступний, дія не має виконуватися.

## 8. Create list validation

### Назва списку

| Rule            | Message                                  |
| --------------- | ---------------------------------------- |
| Required        | Введіть назву списку                     |
| Min 2 symbols   | Назва має містити щонайменше 2 символи   |
| Max 80 symbols  | Назва не може бути довшою за 80 символів |
| No HTML         | Назва містить недопустимі символи        |
| Duplicate title | Список із такою назвою вже існує         |

### Опис

| Rule            | Message                                  |
| --------------- | ---------------------------------------- |
| Max 300 symbols | Опис не може бути довшим за 300 символів |
| No HTML         | Опис містить недопустимі символи         |

### Іконка / Колір

| Rule              | Message                        |
| ----------------- | ------------------------------ |
| Unsupported icon  | Обрана іконка не підтримується |

## 9. Create list submit behavior

Після натискання **Створити список** система має:

1. перевірити форму;
2. створити новий список;
3. закрити modal;
4. додати новий список на сторінку **Власні списки**;
5. оновити count badge у header;
6. оновити sidebar statistics;
7. показати success message.

Success message:

```text id="pjxc2i"
Список створено
```

Якщо active sorting = **Останнє оновлення**, новий список має з’явитися на початку списку.

---

## 10. Create list from Add Book to List modal

Якщо користувач створює список із modal **Додати до списку**, поведінка має бути такою:

1. користувач натискає **+ Створити новий список**;
2. заповнює назву й optional опис;
3. список створюється;
4. новий список одразу з’являється в переліку доступних списків;
5. новий список автоматично стає selected.

Important:

```text id="em1qed"
Створення списку не означає автоматичне додавання книги до нього, якщо користувач не зберіг основну modal.
```

Recommended MVP behavior:

```text id="y2f5e2"
Створити список → список створюється одразу → стає selected → після “Зберегти” книга додається до нього.
```

## 13. Edit list behavior

Після відкриття modal:

* показати поточну назву списку;
* показати поточний опис, якщо він є;
* показати обрану іконку або default icon;
* показати обраний колір або default color.

Кнопка **Зберегти** має бути disabled, якщо користувач нічого не змінив.

Після натискання **Зберегти**:

1. система валідує форму;
2. оновлює список;
3. закриває modal;
4. оновлює картку списку;
5. оновлює `updatedAt`;
6. оновлює порядок списків, якщо active sorting = **Останнє оновлення**;
7. показує success message.

Success message:

```text id="xpesam"
Список оновлено
```

## 17. Delete list behavior

Після підтвердження видалення:

1. список видаляється;
2. список зникає зі сторінки **Власні списки**;
3. зв’язки книг із цим списком видаляються;
4. самі книги залишаються в бібліотеці;
5. count badge оновлюється;

```text id="sjeav5"

```

## 18. Delete list does not delete books

Це ключове правило фічі.

```text id="qc41gf"
Видалення списку не видаляє книги.
```

Example:

```text id="4sf1yz"
Список “Темне фентезі” містить 12 книг.

Користувач видаляє список.

Результат:
- список “Темне фентезі” зникає;
- 12 книг залишаються в “Моїй бібліотеці”;
- книги більше не пов’язані з цим списком.
```

Це правило потрібно чітко показувати в confirmation modal.

## 21. UI updates after actions

### After create

Після створення списку оновлюються:

* lists grid;
* count badge у header;
* sidebar statistics;
* empty state, якщо це перший список;
* sort order.

---

### After edit

Після редагування списку оновлюються:

* назва на картці;
* опис;
* іконка;
* колір;
* дата останнього оновлення;
* sorting order, якщо активне сортування за оновленням.

---

### After delete

Після видалення списку оновлюються:

* lists grid;
* count badge;
* sidebar statistics;
* empty state, якщо списків більше немає;
* no search results state, якщо після видалення більше немає результатів за активним search.

## 22. Accessibility

Create / Edit / Delete modals мають бути доступними для keyboard і screen reader.

Requirements:

* modal має мати focus trap;
* після закриття focus повертається на кнопку, яка відкрила modal;
* поля мають мати labels;
* validation errors мають бути доступні для screen reader;
* submit має працювати через Enter, якщо форма валідна;
* cancel має працювати через Escape;
* destructive action має бути чітко підписана.

Recommended aria labels:

```text id="bnqz2n"
Створити новий список
Редагувати список
Видалити список
Підтвердити видалення списку
```

---

## 23. What is not included

Ця фіча не відповідає за:

* повну сторінку **Власні списки**;
* сторінку деталей списку;
* додавання книг до списку;
* прибирання книг зі списку;
* порядок книг усередині списку;
* drag-and-drop книг у списку;
* public / shared lists;
* доступ за посиланням;
* favorite lists;
* дублювання списку;
* API;
* data model.

Ці сценарії мають бути описані окремими features.

## 24. Acceptance Criteria

### Create list

* Користувач може відкрити modal **Створити список**.
* Користувач може ввести назву списку.
* Назва списку є обов’язковою.
* Назва списку має містити щонайменше 2 символи.
* Назва списку не може бути довшою за 80 символів.
* Користувач може optional додати опис.
* Опис не може бути довшим за 300 символів.
* Користувач може optional вибрати іконку.
* Користувач може optional вибрати колір.
* Якщо список із такою назвою вже існує, користувач бачить validation error.
* Після створення список з’являється на сторінці **Власні списки**.
* Після створення count badge оновлюється.
* Після створення користувач бачить success message.

### Edit list

* Користувач може відкрити modal **Редагувати список**.
* Modal відкривається з поточними даними списку.
* Користувач може змінити назву списку.
* Користувач може змінити опис списку.
* Користувач може змінити іконку, якщо ця опція доступна.
* Користувач може змінити колір, якщо ця опція доступна.
* Кнопка **Зберегти** disabled, якщо немає змін.
* Якщо нова назва дублює інший список користувача, показується validation error.
* Після збереження картка списку оновлюється.
* Після збереження користувач бачить success message.

### Delete list

* Користувач може натиснути **Видалити список**.
* Перед видаленням відкривається confirmation modal.
* Confirmation modal пояснює, що книги залишаться в бібліотеці.
* Користувач може скасувати видалення.
* Користувач може підтвердити видалення.
* Після підтвердження список зникає зі сторінки **Власні списки**.
* Після видалення книги зі списку залишаються в бібліотеці.
* Після видалення count badge оновлюється.
* Якщо видалено останній список, показується empty state.
* Якщо сталася помилка, список не зникає і користувач бачить error message.

### Permissions

* Користувач може створювати списки тільки для себе.
* Користувач може редагувати тільки свої списки.
* Користувач може видаляти тільки свої списки.
* Користувач не може редагувати або видаляти чужі списки.
