# Поля профілю користувача

## Опис

Профіль користувача — це персональний розділ у BookNest, де користувач може переглядати й редагувати базову інформацію про себе та свої читацькі вподобання.

У профілі має бути тільки інформація, яка стосується самого користувача.
Налаштування застосунку, такі як тема, мова, імпорт / експорт, сповіщення та безпека, будуть у підрозділі **Налаштування**.

---

## Що користувач бачить у профілі

Користувач має бачити таку інформацію:

* аватар або placeholder з ініціалами;
* ім’я користувача;
* прізвище користувача;
* нікнейм;
* email;
* коротке bio / опис про себе;
* улюблену цитату про книги;
* улюблені жанри;
* дату народження, якщо користувач її додав;
* дату створення акаунту;
* коротку читацьку статистику.

---

| ------------------------- | ----------------------- | ----------: | ---------------------------------------------------------- |

## Улюблена цитата про книги

Користувач може додати одну коротку цитату, яка буде показуватися в верхньому блоці профілю біля аватара, імені та email.

### Приклад відображення

```text
“Книги — це мандрівки, які починаються, не виходячи з дому.”
```

### Логіка

* поле необов’язкове;
* якщо цитата не додана, цей блок не показується;
* цитата має відображатися в header профілю;
* цитата не є нотаткою і не прив’язана до конкретної книги;
* це персональна цитата користувача для профілю.

---

## Дата народження

Дата народження є опційним полем.

### Логіка

* користувач може додати дату народження;
* користувач може залишити поле порожнім;
* дата народження не повинна бути обов’язковою;
* якщо дата не додана, у профілі вона не показується;
* дата народження не має використовуватись як публічна інформація без окремої логіки приватності.

### Формат відображення

```text
12.05.1998
```

## Поля тільки для перегляду

Ці поля потрібно показувати користувачу, але не редагувати напряму з форми профілю:

| Поле                   | Опис                                                   |
| ---------------------- | ------------------------------------------------------ |
| Email                  | Email-адреса користувача                               |
| Auth provider          | Спосіб входу: email/password, Google, Apple            |
| Дата створення акаунту | Дата реєстрації користувача                            |
| Читацька статистика    | Рахується автоматично на основі бібліотеки користувача |

Email краще не редагувати напряму у формі профілю.
Якщо потрібна зміна email, це має бути окремий security flow.

## Коротка статистика профілю

У профілі можна показати короткий читацький огляд:

| Статистика        | Опис                                   |
| ----------------- | -------------------------------------- |
| Усього книг       | Загальна кількість книг у бібліотеці   |
| Прочитано книг    | Кількість книг зі статусом `Прочитано` |
| Читаю зараз       | Книги зі статусом `Читаю`              |
| Улюблених книг    | Книги, позначені як улюблені           |
| Кількість нотаток | Загальна кількість нотаток користувача |
| Кількість цитат   | Загальна кількість збережених цитат    |

Якщо користувач ще не додав книги, показати empty state:

```text
Статистика з’явиться після додавання книг.
```

Форма редагування профілю має містити:

* аватар;
* ім’я;
* прізвище;
* нікнейм;
* дата народження;
* bio;
* улюблена цитата про книги;

Після збереження змін:


## Валідація

### Ім’я та прізвище

* обов’язкове поле;
* мінімум 2 символи;
* максимум 50 символів;
* перед збереженням потрібно робити `trim`.

### Нікнейм

* необов’язкове поле;
* максимум 30 символів;
* без пробілів;
* дозволені символи:

    * літери;
    * цифри;
    * `_`;
    * `.`;
    * `-`.

### Дата народження

* необов’язкове поле;
* має бути валідною датою;
* не може бути датою в майбутньому;
* якщо поле порожнє, зберігається `null` або не зберігається взагалі.

### Bio

* необов’язкове поле;
* максимум 300 символів.

### Улюблена цитата про книги

* необов’язкове поле;
* максимум 200 символів;
* якщо поле порожнє, цитата не показується в профілі.

### Аватар

* необов’язкове поле;
* дозволені формати: JPG, PNG, WEBP;
* максимальний розмір: 5 MB.

### Улюблені жанри

* необов’язкове поле;
* максимум 10 жанрів.


## Блок “Соціальні мережі”

У профілі користувача має бути окремий блок **“Соціальні мережі”**, де користувач може додавати посилання або username на свої книжкові / особисті профілі.

Цей блок є опційним. Якщо користувач не додав жодного посилання, блок можна не показувати або показувати empty state.

## Що користувач бачить у блоці

Користувач бачить список доданих соціальних мереж:

* іконка соціальної мережі;
* username або назва посилання;
* кнопка редагування;
* кнопка видалення;

## Поля для social link

| --------- | ---------- | ----------: | --------------------------------------- |
| Платформа | Select     |         Так | Тип соціальної мережі                   |
| Username  | Text input |          Ні | Нік користувача без повного URL         |
| URL       | Text input |          Ні | Повне посилання на профіль              |
| Label     | Text input |          Ні | Кастомна назва посилання, якщо потрібно |

---

## Логіка social links

* користувач може додати кілька соціальних мереж;
* одна платформа може бути додана тільки один раз, якщо це не `Other`;
* для кожного social link має бути або `username`, або `url`;
* якщо користувач вводить username, frontend або backend може сформувати URL автоматично;
* якщо користувач вводить повний URL, він має бути валідним;
* користувач може редагувати social link;
* користувач може видалити social link;
* якщо social links немає, показати empty state.

Empty state:

```text
Соціальні мережі ще не додані.
```

# Валідація редагованих полів

## Аватар

* поле необов’язкове;
* дозволені формати: `JPG`, `PNG`, `WEBP`;
* максимальний розмір файлу: `5 MB`;
* рекомендований розмір: мінімум `512x512`;
* не дозволяти SVG або потенційно небезпечні файли;
* якщо файл невалідний, показати validation error;
* якщо аватар видалено, показувати placeholder з ініціалами.

Приклад помилки:

```text
Підтримуються тільки JPG, PNG або WEBP до 5 MB.
```

---

## Ім’я

* обов’язкове поле;
* мінімум 2 символи;
* максимум 50 символів;
* перед збереженням робити `trim`;
* не може складатися тільки з пробілів;
* не дозволяти HTML-теги.

Приклад помилки:

```text
Введіть ім’я від 2 до 50 символів.
```

---

## Прізвище

* обов’язкове поле;
* мінімум 2 символи;
* максимум 50 символів;
* перед збереженням робити `trim`;
* не може складатися тільки з пробілів;
* не дозволяти HTML-теги.

Приклад помилки:

```text
Введіть прізвище від 2 до 50 символів.
```

---

## Нікнейм

* необов’язкове поле;
* максимум 30 символів;
* мінімум 3 символи, якщо поле заповнене;
* без пробілів;
* дозволені символи:

    * літери;
    * цифри;
    * `_`;
    * `.`;
    * `-`;
* не зберігати `@` на початку, якщо username зберігається без символу `@`;
* якщо нікнейм буде публічним, він має бути унікальним.

Приклад помилки:

```text
Нікнейм може містити літери, цифри, крапку, дефіс або underscore.
```

---

## Дата народження

* необов’язкове поле;
* має бути валідною датою;
* не може бути датою в майбутньому;
* якщо поле порожнє, зберігати `null` або не зберігати поле взагалі;
* дата народження не має показуватись публічно без окремих privacy settings.

Приклад помилки:

```text
Дата народження не може бути в майбутньому.
```

---

## Bio

* необов’язкове поле;
* максимум 300 символів;
* перед збереженням робити `trim`;
* перенос рядків дозволений;
* не дозволяти HTML-теги;
* якщо поле порожнє, блок bio можна не показувати.

Приклад помилки:

```text
Bio може містити максимум 300 символів.
```

---

## Улюблена цитата про книги

* необов’язкове поле;
* максимум 200 символів;
* перед збереженням робити `trim`;
* не дозволяти HTML-теги;
* якщо поле порожнє, цитата не показується в header профілю;
* цитата не прив’язана до конкретної книги;
* це персональна цитата профілю.

Приклад помилки:

```text
Цитата може містити максимум 200 символів.
```

---

## Улюблені жанри

* необов’язкове поле;
* максимум 10 жанрів;
* кожен жанр має бути з існуючого довідника жанрів або з дозволених кастомних значень;
* дублікати не дозволені;
* якщо жанр видалений з довідника, потрібно коректно обробити його в профілі.

Приклад помилки:

```text
Можна вибрати максимум 10 жанрів.
```

---

## Соціальні мережі

### Загальна валідація

* поле необов’язкове;
* максимум 10 social links;
* кожен social link має мати платформу;
* для кожного social link має бути заповнено `username` або `url`;
* дублікати однакових платформ не дозволені, крім `OTHER`;
* дублікати однакових URL не дозволені;
* перед збереженням робити `trim`;
* не дозволяти HTML-теги.

Приклад помилки:

```text
Додайте username або посилання на профіль.
```

---

### Platform

* обов’язкове поле;
* значення має бути тільки зі списку дозволених платформ;
* якщо платформа `OTHER`, бажано заповнити `label`.

Приклад помилки:

```text
Оберіть соціальну мережу.
```

---

### Username

* необов’язкове поле, якщо заповнений `url`;
* максимум 50 символів;
* мінімум 2 символи, якщо поле заповнене;
* username можна вводити з `@` або без `@`, але зберігати краще без `@`;
* не дозволяти пробіли на початку і в кінці;
* не дозволяти HTML-теги.

Приклад помилки:

```text
Username може містити максимум 50 символів.
```

---

### URL

* необов’язкове поле, якщо заповнений `username`;
* має бути валідним URL;
* дозволені тільки `https://` посилання;
* не дозволяти `javascript:`, `data:`, `file:`;
* максимум 300 символів;
* URL має відповідати обраній платформі, якщо це можливо.

Приклад помилки:

```text
Введіть коректне https-посилання.
```

---

### Label

* необов’язкове поле;
* максимум 40 символів;
* корисне для `WEBSITE` або `OTHER`;
* перед збереженням робити `trim`;
* не дозволяти HTML-теги.

Приклад помилки:

```text
Назва посилання може містити максимум 40 символів.
```

## Acceptance Criteria для social links

* Користувач бачить блок **Соціальні мережі** у профілі.
* Користувач може додати social link.
* Користувач може вибрати платформу social link.
* Користувач може додати username або URL.
* Користувач може редагувати social link.
* Користувач може видалити social link.
* Якщо social links немає, показується empty state.
* Якщо введений невалідний URL, показується validation error.
* Якщо користувач додає дублікат social link, показується validation error.
* Якщо social link збережено, він показується у списку.
* Social links зберігаються тільки для поточного користувача.



---

## Acceptance Criteria

* Користувач може відкрити сторінку профілю.
* Користувач бачить аватар або placeholder.
* Користувач бачить ім’я, прізвище та email.
* Користувач може редагувати ім’я та прізвище.
* Користувач може редагувати аватар.
* Користувач може редагувати нікнейм.
* Користувач може редагувати bio.
* Користувач може додати або видалити дату народження.
* Користувач може додати або видалити улюблену цитату про книги.
* Улюблена цитата показується біля аватара в header профілю.
* Якщо цитата не додана, блок цитати не показується.
* Користувач може вибрати улюблені жанри.
* Користувач бачить коротку читацьку статистику.
* Користувач може вийти з акаунту зі сторінки профілю.
* Зміни профілю зберігаються для поточного користувача.
* Після збереження на сторінці показуються оновлені дані.
* Якщо збереження не вдалося, користувач бачить повідомлення про помилку.
* Якщо аватар невалідний, користувач бачить validation error.
* Email видимий, але не редагується напряму з форми профілю.


# Налаштування профілю користувача

## Опис

У профілі користувача має бути підрозділ **“Налаштування”**, де користувач може персоналізувати застосунок під себе: змінити тему, акцентний колір, мову інтерфейсу, формат дат, вигляд бібліотеки, email-сповіщення та базові параметри безпеки.

Ці налаштування зберігаються окремо для кожного користувача.

---

## 1. Тема інтерфейсу

Користувач може вибрати тему застосунку.

### Варіанти

| Значення | Label    | Опис                                           |
| -------- | -------- | ---------------------------------------------- |
| `light`  | Світла   | Застосунок завжди відкривається у світлій темі |
| `dark`   | Темна    | Застосунок завжди відкривається у темній темі  |
| `system` | Системна | Тема підтягується з налаштувань пристрою       |

### Логіка

* якщо вибрано `light`, застосунок завжди використовує світлу тему;
* якщо вибрано `dark`, застосунок завжди використовує темну тему;
* якщо вибрано `system`, застосунок бере тему з системних налаштувань користувача;
* вибране значення має зберігатися після перезавантаження сторінки.

---

## 2. Акцентний колір

Користувач може вибрати основний акцентний колір застосунку.

Акцентний колір використовується для:

* primary buttons;
* активних пунктів меню;
* активних tabs;
* selected states;
* focus states;
* деяких badge / highlight elements.

### Варіанти для MVP

| Значення | Label        |
| -------- | ------------ |
| `brown`  | Коричневий   |
| `orange` | Помаранчевий |
| `yellow` | Жовтий       |
| `green`  | Зелений      |
| `blue`   | Синій        |
| `purple` | Фіолетовий   |

### Логіка

* користувач вибирає один акцентний колір;
* обраний колір застосовується до UI;
* значення зберігається для поточного користувача;
* після оновлення сторінки вибір не скидається.

---

## 3. Мова інтерфейсу

Користувач може вибрати мову інтерфейсу BookNest.

### Варіанти для MVP

| Значення | Label      |
| -------- | ---------- |
| `uk`     | Українська |
| `en`     | English    |

### Пізніше можна додати

* Польська
* Німецька
* Іспанська

### Логіка

* після зміни мови інтерфейс має оновитися;
* вибрана мова зберігається для користувача;
* якщо мову не вибрано, використовується мова за замовчуванням — `uk`.

---

## 4. Формат дати

Користувач може вибрати формат відображення дат у застосунку.

### Варіанти

| Значення     | Приклад    |
| ------------ | ---------- |
| `DD.MM.YYYY` | 25.06.2026 |
| `MM/DD/YYYY` | 06/25/2026 |
| `YYYY-MM-DD` | 2026-06-25 |

### Де використовується

* дата створення акаунту;
* дата початку читання;
* дата завершення читання;
* дата доставки книги;
* дата повернення позиченої книги;
* reading calendar;
* reading goals.

### Логіка

* користувач вибирає один формат;
* всі дати в інтерфейсі мають відображатися у вибраному форматі;
* значення зберігається для поточного користувача.

---

## 5. Перший день тижня

Користувач може вибрати, з якого дня починається тиждень.

### Варіанти

| Значення | Label     |
| -------- | --------- |
| `monday` | Понеділок |
| `sunday` | Неділя    |

### Де використовується

* reading calendar;
* weekly reading summary;
* reading streak;
* статистика по тижнях;
* цілі читання.

### Логіка

* якщо вибрано `monday`, календарний тиждень починається з понеділка;
* якщо вибрано `sunday`, календарний тиждень починається з неділі;
* значення має впливати на всі тижневі підрахунки у застосунку.

---

## 6. Часовий пояс

Користувач може бачити або змінити часовий пояс.

### Приклад

```text
(UTC+02:00) Київ
```

### Де використовується

* reading calendar;
* reading streak;
* email-нагадування;
* дата доставки книги;
* дата повернення позиченої книги;
* статистика по днях;
* weekly / monthly reports.

### Логіка для MVP

Для MVP можна автоматично визначати часовий пояс з браузера.

Користувач бачить поточний часовий пояс у профілі, але зміна може бути додана пізніше.

---

## 7. Вигляд бібліотеки

Користувач може вибрати стандартний вигляд списків книг.

### Варіанти

| Значення | Label  | Опис                               |
| -------- | ------ | ---------------------------------- |
| `grid`   | Картки | Книги показуються у вигляді карток |
| `list`   | Список | Книги показуються у вигляді списку |

### Де використовується

* Моя бібліотека;
* Улюблені книги;
* Книги до покупки;
* Книги в дорозі;
* Позичені книги;
* Деталі списку, якщо там показуються книги.

### Логіка

* якщо вибрано `grid`, списки книг відкриваються у вигляді карток;
* якщо вибрано `list`, списки книг відкриваються у вигляді списку;
* користувач може змінити вигляд на самій сторінці, але дефолтне значення береться з налаштувань профілю.

---

## 8. Підтвердження перед видаленням

Користувач може увімкнути або вимкнути confirmation modal перед видаленням важливих даних.

### Значення

| Значення | Опис                                                |
| -------- | --------------------------------------------------- |
| `true`   | Перед видаленням показується confirmation modal     |
| `false`  | Видалення виконується без додаткового підтвердження |

### Де використовується

* видалення книги;
* видалення нотатки;
* видалення цитати;
* видалення списку;
* видалення social link;
* видалення персонажа;
* видалення посилання на магазин.

### Логіка

* для MVP рекомендовано значення `true` за замовчуванням;
* навіть якщо користувач вимкнув підтвердження, для критичних дій краще все одно показувати confirmation modal;
* критичні дії: видалення акаунту, повне очищення даних, масове видалення.

---

## 9. Зміна паролю

У блоці **Безпека** користувач може перейти до зміни паролю.

### Що показувати

* назва блоку: **Безпека**;
* опис: **Оновіть пароль для захисту вашого акаунту**;
* кнопка: **Змінити пароль**.

### Логіка

Після натискання на кнопку:

* відкривається modal або окрема сторінка зміни паролю;
* користувач вводить поточний пароль;
* користувач вводить новий пароль;
* користувач підтверджує новий пароль;
* після успішної зміни показується success notification;
* після зміни паролю відправляється `password_changed_email`.

### Важливо

Якщо користувач авторизований через Google або Apple, зміна паролю може бути недоступна напряму в BookNest.

У такому випадку потрібно показати повідомлення:

```text
Ваш акаунт використовує зовнішній спосіб входу. Пароль можна змінити через ваш auth provider.
```

---

## 10. Email-сповіщення

Користувач може керувати optional email notifications.

### Що можна налаштовувати

| Поле                    | Тип    | Опис                                |
| ----------------------- | ------ | ----------------------------------- |
| `readingReminders`      | Toggle | Нагадування оновити прогрес читання |
| `readingGoalReminders`  | Toggle | Нагадування про читацькі цілі       |
| `borrowedBookReminders` | Toggle | Нагадування про позичені книги      |
| `deliveryReminders`     | Toggle | Нагадування про книги в дорозі      |
| `weeklyReadingSummary`  | Toggle | Щотижневий читацький звіт           |
| `monthlyReadingReport`  | Toggle | Щомісячний читацький звіт           |

### Логіка

* кожне email-сповіщення має окремий toggle;
* якщо toggle увімкнений, користувач може отримувати відповідні листи;
* якщо toggle вимкнений, такі листи не відправляються;
* стан toggle зберігається для поточного користувача;
* після оновлення сторінки вибрані налаштування не скидаються.

### Системні листи не вимикаються

Користувач не може вимкнути:

* password reset email;
* email verification;
* password changed email;
* важливі security emails.

## Data model

```ts
type ThemeMode = 'light' | 'dark' | 'system';

type AccentColor =
  | 'brown'

  | 'DD.MM.YYYY'
  | 'MM/DD/YYYY'
  | 'YYYY-MM-DD';

```

## Acceptance Criteria

* Користувач бачить підрозділ **Налаштування** у профілі.
* Користувач може вибрати тему інтерфейсу.
* Користувач може вибрати акцентний колір.
* Користувач може вибрати мову інтерфейсу.
* Користувач може вибрати формат дати.
* Користувач може вибрати перший день тижня.
* Користувач бачить часовий пояс.
* Користувач може вибрати вигляд бібліотеки: `grid` або `list`.
* Користувач може увімкнути або вимкнути підтвердження перед видаленням.
* Користувач може перейти до зміни паролю.
* Користувач може керувати email-сповіщеннями.
* Усі зміни зберігаються для поточного користувача.
* Після оновлення сторінки налаштування не скидаються.
* Якщо збереження налаштувань не вдалося, користувач бачить повідомлення про помилку.
* System emails не можна вимкнути через налаштування.
