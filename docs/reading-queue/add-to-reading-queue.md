# Feature: Add to Reading Queue from Book Details

## 1. Purpose

Feature **Add to Reading Queue from Book Details** дозволяє користувачу додати конкретну книгу в **Чергу читання** прямо зі сторінки деталей книги.

Фіча також дозволяє прибрати книгу з черги, якщо вона вже була додана.

Ця логіка потрібна, щоб користувач міг швидко планувати, що читати далі, не переходячи окремо на сторінку **Черга читання**.

---

## 2. Main idea

Черга читання — це впорядкований список книг, які користувач планує читати далі.

Книга може бути:

```text
не в черзі
```

або:

```text
у черзі на певній позиції
```

Основна логіка:

```text
Додати в чергу → книга зʼявляється в Reading Queue
Прибрати з черги → книга зникає тільки з Reading Queue
```

Important:

* додавання в чергу не змінює reading status;
* додавання в чергу не змінює ownership status;
* прибирання з черги не видаляє книгу з бібліотеки;
* одна книга не може бути в черзі двічі;
* кожна книга в черзі має свою позицію;
* позиції в черзі мають бути послідовними без пропусків.

---

## 3. Entry point

Дія доступна на сторінці **Book Details**.

Recommended location:

```text
Book Details → Right sidebar → Quick actions
```

Action label, якщо книги ще немає в черзі:

```text
Додати в чергу читання
```

Якщо книга вже є в черзі, замість цієї дії потрібно показувати статус:

```text
У черзі · позиція N
```

і окрему дію:

```text
Прибрати з черги
```

Example:

```text
У черзі · позиція 4
Прибрати з черги
```

---

## 4. When action is available

Action **Додати в чергу читання** доступна, якщо:

* книга належить поточному користувачу;
* книга не видалена;
* книги ще немає в черзі.

Action не потрібно блокувати через reading status або ownership status.

Користувач може додати в чергу книгу зі статусом:

* Не почато;
* Хочу прочитати;
* Читаю;
* На паузі;
* Прочитано;
* Покинуто;
* Немає;
* Хочу купити;
* В дорозі;
* Маю;
* Позичена у когось;
* Видана комусь.

Reason:

```text
Черга читання — це план користувача, а не автоматична залежність від статусів.
```

Наприклад, користувач може додати прочитану книгу в чергу, якщо хоче перечитати її пізніше.

---

## 5. UI states on Book Details

### 5.1. Book is not in queue

Якщо книга ще не додана в чергу, у Quick actions показати:

```text
Додати в чергу читання
```

Behavior:

* action відкриває modal;
* користувач обирає позицію в черзі;
* після підтвердження книга додається в чергу.

---

### 5.2. Book is already in queue

Якщо книга вже додана в чергу, у Quick actions показати:

```text
У черзі · позиція N
```

і дію:

```text
Прибрати з черги
```

Behavior:

* action **Додати в чергу читання** більше не показується;
* користувач бачить, що книга вже є в черзі;
* користувач може прибрати книгу з черги;
* користувач може перейти на сторінку **Черга читання**, якщо хоче змінити порядок через повний список.

---

Modal відкривається після натискання:

```text
Додати в чергу читання
```

Modal title:

```text
Додати в чергу читання
```

Subtitle:


## 8. Queue position selection

Користувач має вибрати, куди саме додати книгу в черзі.

Available options:

```text
На початок черги
У кінець черги
На конкретну позицію
```

Default option:

```text
У кінець черги
```

Recommended UI:

```text
Куди додати книгу?

( ) На початок черги
(•) У кінець черги
( ) На конкретну позицію
```

Якщо користувач обирає **На конкретну позицію**, потрібно показати додаткове поле:

```text
Позиція в черзі
```

Example:

```text
Позиція: 3
```

Helper text:

```text
Якщо на цій позиції вже є книга, вона та всі наступні книги змістяться нижче.
```

---

## 9. Position logic

### 9.1. Add to the beginning

Якщо користувач обрав:

```text
На початок черги
```

книга стає першою в черзі.

Усі інші книги зміщуються нижче.

Example:

```text
Було:
1. Книга A
2. Книга B
3. Книга C

Додаємо Книгу D на початок

Стало:
1. Книга D
2. Книга A
3. Книга B
4. Книга C
```

---

### 9.2. Add to the end

Якщо користувач обрав:

```text
У кінець черги
```

книга додається після всіх книг у черзі.

Example:

```text
Було:
1. Книга A
2. Книга B
3. Книга C

Додаємо Книгу D у кінець

Стало:
1. Книга A
2. Книга B
3. Книга C
4. Книга D
```

---

### 9.3. Add to specific position

Якщо користувач обрав:

```text
На конкретну позицію
```

він має вказати номер позиції.

Example:

```text
Позиція: 2
```

Якщо на цій позиції вже є книга, нова книга вставляється на вказане місце, а книга, яка була на цій позиції, разом з усіма наступними зміщується нижче.

Example:

```text
Було:
1. Книга A
2. Книга B
3. Книга C

Додаємо Книгу D на позицію 2

Стало:
1. Книга A
2. Книга D
3. Книга B
4. Книга C
```

---

## 10. Specific position validation

Поле **Позиція в черзі** показується тільки тоді, коли користувач обрав option **На конкретну позицію**.

Validation:

| Rule                                             | Message                                                    |
| ------------------------------------------------ | ---------------------------------------------------------- |
| position is required                             | Вкажіть позицію в черзі                                    |
| position must be number                          | Позиція має бути числом                                    |
| position must be integer                         | Позиція має бути цілим числом                              |
| position must be greater than 0                  | Позиція має бути більшою за 0                              |
| position cannot be greater than queue length + 1 | Позиція не може бути більшою за кількість книг у черзі + 1 |

Allowed range:

```text
1 ... queueLength + 1
```

Example:

```text
У черзі зараз 5 книг.
Користувач може вказати позицію від 1 до 6.
```

If user enters:

```text
position = 6
```

це означає додати книгу в кінець черги.

---

## 11. Empty queue behavior

Якщо черга порожня, будь-який варіант позиції додає книгу на позицію 1.

Result:

```text
position = 1
```

Recommended behavior:

* залишити всі options доступними;
* але якщо користувач обрав **На конкретну позицію**, дозволити тільки позицію `1`;
* helper text може пояснити, що це буде перша книга в черзі.

Example:

```text
Черга поки порожня. Книга буде додана на позицію 1.
```

---

## 12. Submit behavior

Після натискання:

```text
Додати в чергу
```

система має:

1. перевірити, чи книга вже є в черзі;
2. якщо книга не в черзі — додати її;
3. призначити позицію згідно з вибором користувача;
4. якщо потрібно — змістити інші книги нижче;
5. оновити Book Details UI;
6. оновити сторінку Reading Queue, якщо вона вже відкрита в іншому місці застосунку;
7. показати success message.

Success message:

```text
Книгу додано в чергу читання
```

Після успішного submit modal закривається.

---

## 13. Duplicate prevention

Одна книга не може бути додана в чергу кілька разів.

Якщо користувач намагається додати книгу, яка вже є в черзі:

* новий запис у черзі не створюється;
* позиція книги не дублюється;
* користувач бачить повідомлення.

Message:

```text
Книга вже є в черзі читання
```

На Book Details у цьому випадку має показуватися:

```text
У черзі · позиція N
```

---

## 14. UI after successful add

Після успішного додавання книги в чергу на Book Details має оновитися блок Quick actions.

Було:

```text
Додати в чергу читання
```

Стало:

```text
У черзі · позиція N
Прибрати з черги
```

Також мають оновитися:

* Book Details sidebar;
* Book Details actions;
* My Library card, якщо ця книга відображається там;
* Favorites page, якщо книга є в улюблених;
* Reading Queue page;
* Dashboard, якщо там показується блок черги читання.

---

## 15. Remove from queue from Book Details

Якщо книга вже є в черзі, користувач може прибрати її прямо зі сторінки Book Details.

Action label:

```text
Прибрати з черги
```

Recommended location:

```text
Book Details → Right sidebar → Quick actions
```

Behavior:

* дія прибирає книгу тільки з черги;
* сама книга залишається в бібліотеці;
* reading status не змінюється;
* ownership status не змінюється;
* формат книги не змінюється;
* нотатки, цитати, персонажі та інші дані книги не змінюються.

---

## 16. Remove behavior

Після натискання **Прибрати з черги** рекомендовано не показувати confirmation modal.

Reason:

```text
Це не destructive action, бо книга не видаляється з бібліотеки.
```

Recommended behavior:

```text
Click → remove from queue → show toast with Undo
```

Toast:

```text
Книгу прибрано з черги
```

Toast action:

```text
Скасувати
```

---

## 17. Undo remove logic

Якщо користувач натискає **Скасувати** в toast:

* книга повертається в чергу;
* бажано повернути її на попередню позицію;
* якщо попередня позиція вже недоступна, книга додається максимально близько до попереднього місця;
* Book Details знову показує статус **У черзі · позиція N**.

Example:

```text
Було:
1. Книга A
2. Книга B
3. Книга C

Користувач прибрав Книгу B

Стало:
1. Книга A
2. Книга C

Користувач натиснув Undo

Стало:
1. Книга A
2. Книга B
3. Книга C
```

---

## 18. Position recalculation after remove

Після прибирання книги з черги позиції інших книг мають оновитися.

Example:

```text
Було:
1. Книга A
2. Книга B
3. Книга C
4. Книга D

Користувач прибрав Книгу B

Стало:
1. Книга A
2. Книга C
3. Книга D
```

Important:

* у черзі не має бути пропусків у позиціях;
* позиції мають залишатися послідовними;
* Book Details має показувати актуальну позицію, якщо книга залишилась у черзі.

---

## 19. UI after successful remove

Після прибирання книги з черги на Book Details має оновитися блок Quick actions.

Було:

```text
У черзі · позиція 4
Прибрати з черги
```

Стало:

```text
Додати в чергу читання
```

Також мають оновитися:

* Reading Queue page;
* My Library card;
* Favorites page;
* Dashboard, якщо там показується черга читання;
* counters, якщо вони є.

---

## 20. Loading behavior

### Add to queue loading

Після натискання **Додати в чергу**:

* submit button стає disabled;
* показується loading state;
* повторний submit блокується;
* modal не закривається до успішного збереження.

Button text:

```text
Додавання...
```

---

### Remove from queue loading

Після натискання **Прибрати з черги**:

* action тимчасово disabled;
* повторний клік блокується;
* можна показати локальний spinner або disabled state.

---

## 21. Error behavior

### Add error

Якщо книгу не вдалося додати в чергу:

* modal залишається відкритою;
* вибрана позиція не очищається;
* Book Details UI не оновлюється;
* користувач бачить error message.

Error message:

```text
Не вдалося додати книгу в чергу
```

---

### Remove error

Якщо книгу не вдалося прибрати з черги:

* Book Details UI повертається до попереднього стану;
* книга залишається позначеною як така, що є в черзі;
* користувач бачить error message.

Error message:

```text
Не вдалося прибрати книгу з черги
```

---

## 22. Accessibility

Action **Додати в чергу читання** і **Прибрати з черги** мають бути доступні для keyboard і screen reader.

Requirements:

* buttons мають бути focusable;
* action має працювати через Enter / Space;
* disabled state має бути зрозумілим;
* modal має мати focus trap;
* після закриття modal focus має повертатися на кнопку, яка її відкрила.

Recommended aria labels:

```text
Додати книгу в чергу читання
Прибрати книгу з черги читання
```

---

## 23. What is not included

Ця фіча не відповідає за:

* повну сторінку Reading Queue;
* drag-and-drop;
* reorder на сторінці черги;
* пошук у черзі;
* фільтри черги;
* сортування черги;
* sidebar сторінки черги;
* кнопку **Почати читати**;
* автоматичне додавання наступної книги із серії;
* bulk додавання книг у чергу;
* рекомендації для черги;
* data model;
* API.

Ці сценарії мають бути описані окремими фічами.

## 24. Acceptance Criteria

* Користувач бачить action **Додати в чергу читання** на Book Details, якщо книги ще немає в черзі.
* Користувач може відкрити modal **Додати в чергу читання**.
* Modal показує назву книги й автора.
* Користувач може вибрати позицію **На початок черги**.
* Користувач може вибрати позицію **У кінець черги**.
* Користувач може вибрати позицію **На конкретну позицію**.
* За замовчуванням вибрана позиція **У кінець черги**.
* Якщо користувач обирає **На конкретну позицію**, показується поле **Позиція в черзі**.
* Поле **Позиція в черзі** є required тільки для option **На конкретну позицію**.
* Позиція має бути цілим числом.
* Позиція має бути більшою за 0.
* Позиція не може бути більшою за кількість книг у черзі + 1.
* Після submit книга додається в чергу.
* Після submit книга отримує позицію в черзі.
* Якщо книга додана на початок, вона стає першою в черзі.
* Якщо книга додана в кінець, вона стає останньою в черзі.
* Якщо книга додана на конкретну позицію, вона вставляється на вказане місце.
* Якщо на конкретній позиції вже була книга, вона та всі наступні книги зміщуються нижче.
* Якщо книга вже є в черзі, дубль не створюється.
* Після додавання Book Details показує **У черзі · позиція N**.
* Після додавання action **Додати в чергу читання** зникає.
* Якщо книга вже є в черзі, користувач бачить action **Прибрати з черги**.
* Користувач може прибрати книгу з черги з Book Details.
* Після прибирання книга зникає тільки з черги.
* Після прибирання книга залишається в бібліотеці.
* Після прибирання reading status не змінюється.
* Після прибирання ownership status не змінюється.
* Після прибирання позиції інших книг у черзі перераховуються.
* Після прибирання користувач бачить toast **Книгу прибрано з черги**.
* Користувач може натиснути **Скасувати** в toast і повернути книгу в чергу.
* Якщо сталася помилка при додаванні, modal залишається відкритою.
* Якщо сталася помилка при прибиранні, UI повертається до попереднього стану.
